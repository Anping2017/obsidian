# 💼 Odoo `sale` 模块详解

## 一、`sale` 模块的作用

- Odoo **销售管理核心模块**。
- 管理从报价到订单交付的完整销售流程。
- 提供销售订单、报价单、价格管理等功能。
- 是销售业务的基础模块。

📌 形象理解：  
👉 销售团队使用 `sale` 模块管理客户订单和报价。

---

## 二、核心功能

### 1. 报价单（Quotations）

- 创建和管理销售报价
- 报价单转换为销售订单
- 报价有效期管理
- 报价版本控制

### 2. 销售订单（Sales Orders）

- 创建和管理销售订单
- 订单确认和取消
- 订单状态跟踪
- 订单修改和历史

### 3. 价格管理

- 产品价格表（Price Lists）
- 客户特定价格
- 数量折扣
- 促销和优惠

### 4. 销售报表和分析

- 销售报表
- 销售团队绩效
- 客户分析
- 产品分析

### 5. 订单确认和交付

- 订单确认流程
- 与库存模块集成（自动创建交货单）
- 发货跟踪

## 三、核心模型

### 1. `sale.order` - 销售订单

销售订单主模型：

```
class SaleOrder(models.Model):
    _name = 'sale.order'
    _inherit = ['mail.thread', 'mail.activity.mixin']
    
    name = fields.Char('Order Reference', required=True)
    partner_id = fields.Many2one('res.partner', 'Customer', required=True)
    date_order = fields.Datetime('Order Date', required=True)
    state = fields.Selection([
        ('draft', 'Quotation'),
        ('sent', 'Quotation Sent'),
        ('sale', 'Sales Order'),
        ('done', 'Locked'),
        ('cancel', 'Cancelled')
    ], string='Status')
    order_line = fields.One2many('sale.order.line', 'order_id', 'Order Lines')
    amount_total = fields.Monetary('Total', compute='_compute_amount')
```

订单状态：
- **草稿**（Draft）：报价阶段
- **已发送**（Sent）：报价已发送给客户
- **销售订单**（Sale）：已确认的订单
- **已完成**（Done）：订单已完成
- **已取消**（Cancelled）：订单已取消

### 2. `sale.order.line` - 订单行

订单明细行：

```
class SaleOrderLine(models.Model):
    _name = 'sale.order.line'
    
    order_id = fields.Many2one('sale.order', 'Order', required=True)
    product_id = fields.Many2one('product.product', 'Product', required=True)
    name = fields.Text('Description', required=True)
    product_uom_qty = fields.Float('Quantity', required=True)
    price_unit = fields.Float('Unit Price', required=True)
    price_subtotal = fields.Monetary('Subtotal', compute='_compute_amount')
    tax_id = fields.Many2many('account.tax', 'Tax')
```

### 3. `sale.order.template` - 订单模板

用于快速创建订单的模板。

## 五、销售流程

### 1. 创建报价单

1. 选择客户
2. 添加产品行
3. 设置价格和数量
4. 应用折扣或促销
5. 生成报价单 PDF

### 2. 发送报价

- 通过邮件发送报价单
- 生成 PDF 附件
- 跟踪报价状态

### 3. 确认订单

- 客户接受报价后确认订单
- 订单状态从"报价"变为"销售订单"
- 触发库存预留（如果安装了 `sale_stock`）

### 4. 交付和发票

- 与库存模块集成，创建交货单
- 与会计模块集成，创建发票
- 跟踪交付状态

## 九、配置和设置详解

### 1. 销售团队配置

#### 销售团队模型

```
class CrmTeam(models.Model):
    _name = 'crm.team'
    _description = 'Sales Team'
    
    name = fields.Char('Sales Team', required=True)
    member_ids = fields.One2many('crm.team.member', 'team_id', 'Team Members')
    company_id = fields.Many2one('res.company', 'Company')
    user_id = fields.Many2one('res.users', 'Team Leader')
    target_sales = fields.Monetary('Sales Target')
    currency_id = fields.Many2one('res.currency', 'Currency')
```

#### 创建销售团队

1. **销售 > 配置 > 销售团队**
2. 创建销售团队：
   - **名称**：团队名称（如"华北销售团队"）
   - **团队负责人**：指定团队负责人
   - **团队成员**：添加团队成员
   - **销售目标**：设置团队销售目标

#### 销售团队功能

- **团队绩效跟踪**：跟踪团队销售绩效
- **订单分配**：将订单分配给团队
- **报告层级**：按团队组织报表

### 2. 产品配置详解

#### 产品销售设置

1. **库存 > 产品 > 产品**
2. 编辑产品
3. **销售**选项卡：
   - **可销售**：勾选后可在销售中使用
   - **销售价格**：产品标准销售价格
   - **价格表**：产品关联的价格表
   - **销售人员**：默认销售人员
   - **销售描述**：产品在销售中的描述

#### 产品变体

- **产品属性**：颜色、尺寸等
- **变体价格**：不同变体的不同价格
- **变体库存**：不同变体的独立库存

#### 产品类型

- **可库存产品**（Storable Product）：
  - 需要管理库存
  - 可以与库存模块集成

- **服务产品**（Service）：
  - 不需要库存
  - 用于服务销售

- **消耗品**（Consumable）：
  - 不需要库存跟踪
  - 购买即消耗

#### 创建价格表

1. **销售 > 配置 > 价格表**
2. 创建新价格表：
   - **名称**：价格表名称（如"VIP客户价格表"）
   - **货币**：价格表使用的货币
   - **价格表项**：添加价格规则

#### 价格规则类型

- **固定价格**：设置固定的销售价格
- **百分比**：基于基础价格的百分比
- **基于成本**：基于产品成本加价
- **数量折扣**：基于数量的价格折扣

#### 价格表应用规则

- **客户级别**：不同客户使用不同价格表
- **产品类别**：不同类别产品不同价格
- **最小数量**：达到最小数量才应用价格
- **有效期**：价格表项的有效期

### 4. 工作流配置详解

#### 订单确认流程

1. **销售 > 配置 > 设置**
2. **销售订单**选项卡：
   - **订单策略**：
     - 按订单交付（MTO）
     - 按库存交付（MTS）
   - **锁定期**：订单确认后锁定期限
   - **发票策略**：
     - 订购时开票
     - 交付时开票
     - 分多次开票

#### 审批规则配置

1. **销售 > 配置 > 设置**
2. **审批**选项卡：
   - **审批阈值**：超过此金额需要审批
   - **审批人**：指定审批人
   - **审批流程**：单级或多级审批

#### 自动化规则

1. **设置 > 技术 > 自动化 > 自动化规则**
2. 创建销售自动化规则

#### 自动化场景

- **自动发送报价**：报价单创建后自动发送给客户
- **自动确认订单**：满足条件自动确认
- **自动创建交货单**：订单确认后自动创建（需 `sale_stock`）
- **自动创建发票**：交付后自动创建发票

### 5. 通知配置

#### 邮件通知设置

1. **销售 > 配置 > 设置**
2. **通知**选项卡
3. 配置通知规则：
   - 新报价单发送通知
   - 订单确认通知
   - 发货通知
   - 发票发送通知

## 十、价格管理详解

### 1. 价格表层级

#### 多价格表支持

- **默认价格表**：公司默认价格表
- **客户价格表**：特定客户的价格表
- **产品价格表**：产品特定价格表
- **促销价格表**：临时促销价格

#### 价格表优先级

```
客户价格表 > 产品价格表 > 默认价格表
```

### 2. 价格计算方法

#### 固定价格

- **设置方式**：直接设置固定价格
- **适用**：特定客户或产品的特殊价格

#### 百分比折扣

- **设置方式**：基于基础价格设置百分比
- **示例**：基础价格 100，设置 10% 折扣 = 90

#### 成本加价

- **设置方式**：基于产品成本加价
- **计算公式**：价格 = 成本 × (1 + 加价率)

#### 数量折扣

- **设置方式**：基于购买数量设置不同价格
- **示例**：
  - 1-10 件：100 元/件
  - 11-50 件：90 元/件
  - 51+ 件：80 元/件

### 3. 价格历史

- **价格变更记录**：记录价格变更历史
- **价格趋势**：分析价格变化趋势
- **价格对比**：对比不同时期的价格

### 1. 订单模板

#### 模板模型

2. **使用模板**：
   - 创建订单时选择模板
   - 自动填充订单内容
   - 修改后创建订单

#### 模板应用场景

- **标准产品组合**：经常一起销售的产品
- **标准服务包**：标准的服务产品组合
- **快速下单**：提高订单创建效率

### 2. 订单合并和拆分

#### 订单合并

- **合并报价**：合并多个报价单为一个订单
- **合并条件**：相同客户、相同交货日期等
- **合并优势**：简化管理，批量处理

#### 订单拆分

- **按交货日期拆分**：不同交货日期的产品分开
- **按仓库拆分**：不同仓库的产品分开
- **部分发货**：支持多次发货

### 3. 订单修改

#### 修改流程

```
已确认订单
 ↓
解锁订单（如配置）
 ↓
修改订单内容
 ↓
记录变更日志
 ↓
审批（如需要）
 ↓
重新确认订单
```

#### 修改限制

- **已发货订单**：通常不能修改
- **已开票订单**：需要先取消发票
- **锁定期间**：锁定期内不能修改

### 4. 销售分析维度

#### 按客户分析

- 客户销售额

- 产品销售趋势

#### 按销售人员分析

- 销售人员订单数
- 销售人员绩效排名

## 十二、典型使用场景详解

### 场景 1：完整销售流程

**需求**：从询价到收款的完整流程

**详细步骤**：

1. **创建报价单**
   ```
   销售 > 报价单 > 新建
   - 选择客户
   - 添加产品行
   - 系统自动应用价格表
   - 调整价格（如需要）
   - 添加折扣或促销
   - 检查总额和税额
   ```

2. **发送报价单**
   - 点击"发送报价单"
   - 系统生成PDF
   - 通过邮件发送
   - 跟踪报价状态

3. **客户沟通**
   - 在报价单的Chatter中沟通
   - 记录客户反馈
   - 调整报价（如需要）

4. **确认订单**
   - 客户接受报价后
   - 点击"确认订单"
   - 订单状态变为"销售订单"
   - 系统自动创建交货单（如安装了 `sale_stock`）
   - 系统自动预留库存（如安装了 `sale_stock`）

5. **发货处理**（需 `sale_stock`）
   - 仓库处理交货单
   - 确认发货
   - 更新订单交付状态

6. **开具发票**（需 `account`）
   - 创建客户发票
   - 发票关联订单
   - 审核并过账发票

7. **收款处理**（需 `account_payment`）
   - 客户付款
   - 登记付款
   - 对账完成

### 场景 2：批量销售

**需求**：处理大批量订单

**步骤**：

1. **批量创建报价**
   - 使用模板快速创建
   - 或导入订单数据

2. **批量确认**
   - 选择多个报价单
   - 批量确认订单

3. **批量发货**
   - 合并发货
   - 批量处理交货单

### 场景 3：价格谈判

**需求**：与客户进行价格谈判

**步骤**：

1. **初始报价**
   - 使用标准价格表
   - 发送初始报价

2. **客户还价**
   - 记录客户还价
   - 在Chatter中讨论

3. **价格调整**
   - 修改订单价格
   - 应用特殊折扣
   - 或使用客户特定价格表

4. **最终确认**
   - 达成价格协议
   - 确认订单

## 十三、销售报表和分析详解

### 1. 销售报表类型

#### 销售订单报表

- **订单列表**：所有销售订单列表
- **订单明细**：订单详细信息
- **订单状态**：按状态筛选订单

#### 销售分析报表

- **销售报表**：按客户、产品、销售人员的销售报表
- **销售漏斗**：从报价到订单的转化分析
- **销售趋势**：销售趋势分析

#### 客户分析报表

- **客户销售额**：各客户的销售额
- **客户订单数**：各客户的订单数量
- **客户排名**：按销售额排名客户

#### 产品分析报表

- **产品销售额**：各产品的销售额
- **产品销售数量**：各产品的销售数量
- **产品销售排名**：畅销产品排名

### 2. 销售仪表板

#### 关键指标（KPI）

- **总销售额**：期间内总销售额
- **订单数量**：期间内订单总数
- **平均订单金额**：总销售额 / 订单数
- **转化率**：订单数 / 报价数
- **新客户数**：期间内新客户数量

#### 图表分析

- **销售趋势图**：销售额随时间变化
- **产品销售饼图**：产品销售占比
- **客户分布图**：客户销售额分布
- **地理分布图**：销售地理分布

### 3. 自定义报表

## 十五、常见问题和解决方案

### 问题 1：无法确认订单

**原因**：
- 订单行中有错误
- 价格计算错误
- 审批流程未完成

**解决方案**：
1. 检查订单行信息
2. 验证价格计算
3. 完成审批流程
4. 检查系统配置

### 问题 2：价格不正确

**原因**：
- 价格表未正确应用
- 价格规则配置错误
- 客户价格表未设置

**解决方案**：
1. 检查客户价格表配置
2. 验证价格规则
3. 检查产品价格设置
4. 手动调整价格（如需要）

### 问题 3：库存不足无法确认

**原因**：
- 可用库存不足（需 `sale_stock`）
- 库存未预留

**解决方案**：
1. 检查产品可用库存
2. 等待采购到货
3. 调整订单数量
4. 配置允许负库存（如需要）

### 问题 4：无法创建发票

**原因**：
- 订单未发货（如配置为交付时开票）
- 发票已创建
- 权限不足

**解决方案**：
1. 完成订单发货
2. 检查是否已有发票
3. 检查用户权限
4. 检查发票策略配置
