# 需求分析三件套详解

## 一、3 个工具的关系

递进使用,不是并列:

```
JTBD → Value Proposition Canvas → Kano 模型
(发现)     (匹配)                (优先级)

找真需求   把需求映射到你的产品   决定哪些先做/必做/惊喜
```

## 二、JTBD(Jobs-to-be-Done)

### 核心洞察
客户不买产品,他们"雇佣"产品完成一件事。

**Christensen 麦当劳奶昔案例**:早晨奶昔的真实竞争对手不是可乐/咖啡,而是香蕉/早餐三明治——因为客户"雇佣"奶昔完成"通勤耐吃 + 单手拿"这个 job。

### 3 层 Job

| 层次 | 含义 | 手机维修例 |
|---|---|---|
| 功能层 | 实际任务 | 修好碎屏 |
| 情感层 | 使用时感受 | 不被宰,感觉公正 |
| 社交层 | 别人怎么看你 | 跟朋友说"我找到良心店" |

**你的产品同时命中 3 层 = 极强产品**。只命中功能层 = 通用替代品。

### 公式

```
当 [情境], 我想 [动机], 这样我可以 [期望结果]
```

### 手机行业例子

- **功能层**:当 [顾客拿碎屏手机进店], 我想 [10 秒给他透明报价], 这样我可以 [快速成交并让顾客信任]
- **情感层**:当 [店主要发抖音但不会拍], 我想 [用 AI 生成"像真人做"的视频], 这样我可以 [有面子又能拿单]
- **社交层**:当 [同行看到我店抖音号], 我想 [他们觉得我懂科技], 这样我可以 [被视为"新一代店主"]

### 露营例子

- **功能层**:当 [来 NZ 想 7 天自驾露营], 我想 [3 分钟拿到详细路书], 这样我可以 [不用花 20 小时自己搜]
- **情感层**:当 [第一次 NZ 露营既想尝试又怕出事], 我想 [有把握、有备用方案], 这样我可以 [不焦虑地享受]
- **社交层**:当 [露营回国], 我想 [有酷照片酷故事], 这样我可以 [朋友圈发出来别人问"怎么去的"]

### 常见错误
1. 只做功能层的 JTBD(变通用替代品)
2. 用抽象词"提高效率"(应用客户真实话)
3. 从产品倒推 job(循环论证)

## 三、Value Proposition Canvas

### 是什么
Alex Osterwalder 设计的可视化工具,让客户需求 vs 你的方案精确对齐(Fit)。

### 结构

```
┌───────────────────┐     ┌───────────────────┐
│   Value Map       │ ⇌  │  Customer Profile │
│  (你的方案)       │ Fit │  (客户画像)       │
│                   │     │                   │
│ • Products        │     │ • Jobs            │
│ • Pain Relievers  │     │ • Pains           │
│ • Gain Creators   │     │ • Gains           │
└───────────────────┘     └───────────────────┘
```

### 右侧:Customer Profile
- Jobs:客户想完成的任务(从 JTBD 拿)
- Pains:完成任务时的困难/风险/不爽
- Gains:完成任务后想得到的好处

### 左侧:Value Map
- Products & Services:你提供什么
- Pain Relievers:你如何缓解每个 Pain
- Gain Creators:你如何提供每个 Gain

### 核心操作
**不是列清单,是画连线**。每个 Pain 都要有对应的 Reliever;每个 Gain 都要有对应的 Creator。

- 有 Pain 无 Reliever = 客户不满意点未解决
- 有 Reliever 无对应 Pain = 可能是无差异需求(无用功能)

### 手机店 AI 工具例子

**Customer Profile(手机店主)**:
- Jobs:每周发 3 条抖音 / 回复咨询 / 上架 Trade Me / 出报价单
- Pains:不会剪视频 / 没时间 / 不知道说什么 / 不敢用英文 / 报价被压
- Gains:多 20% 销售 / 少加班 2h/天 / 感觉"懂营销" / 顾客说"高级"

**Value Map**:
- Products:手机店 IP AIGC 内容工厂
- Pain Relievers:
  - 不会剪 → 3 分钟出 1 条完整抖音
  - 没时间 → 一次输入 5 平台版本
  - 不知道说什么 → 100+ 手机行业话术模板
  - 不敢英文 → AI 双语客服
  - 报价被压 → 智能报价对比工具
- Gain Creators:
  - 多销售 → ROI 数据看板
  - 少加班 → 全流程自动化
  - 懂营销 → 教练模式在线
  - 店高级 → 高质量 IP 模板

### 常见错误
4. 只列 Pain 不找 Reliever(空谈)
5. 加太多"想加的功能"到 Value Map(无对应 Pain/Gain)
6. Customer Profile 全靠猜(应访谈 5+ 真实客户)

## 四、Kano 模型

### 是什么
日本 Kano 教授提出,按"对满意度的影响"给需求分类。

### 5 类需求

| 类型 | 有 | 没有 | 说明 |
|---|---|---|---|
| 基本(Must-be) | 不觉得 | 崩溃 | 理所当然 |
| 期望(Performance) | 满意 | 不满意 | 线性,越多越好 |
| 兴奋(Delight) | 惊喜 | 不失望 | 超预期 |
| 无差异(Indifferent) | 无感 | 无感 | 别投入 |
| 反向(Reverse) | 反感 | 满意 | 你以为客户要,实际讨厌 |

### 关键洞察
- 基本 = 门槛(不做就死)
- 期望 = 竞争差异(比对手做得好)
- 兴奋 = 记住你/推荐你的原因
- 无差异 = 陷阱
- 反向 = 灾难

### 时间维度(极重要)
**兴奋需求会降级**:今天惊喜 → 明天期望 → 后天基本

iPhone 触屏例:
- 2007 兴奋 → 2012 期望 → 2020 基本

→ 你要不断创造新的兴奋点。**兴奋需求有保质期**。

### 手机店 AI 工具例子

**基本**:中文文案可用 / 界面能登能保存 / 支付正常 / 数据不丢 / 内容不违规

**期望**:生成质量高 / 速度快 / 平台多 / 价格便宜 / 客服快

**兴奋**:
- 一键 5 平台生成+自动发布
- 竞品情报实时推送
- 双语+多语言原生
- AI 教练周策略建议
- 老板/员工不同视图

**无差异**(别做):高级动画 / 品牌 slogan 生成器 / 通用 BGM 库

**反向**(避免):强制每天登录 / 弹窗推销 / 复杂设置向导

### 露营路书例子
- 基本:路线准确 / 营地真实 / 可下载 PDF
- 期望:双语 / 含照片 / GPS / 24h 退款
- 兴奋:自动个性化生成 / 离线 App / 群内 1h 应急答疑

### 常见错误
7. "我觉得酷"当兴奋需求(应问客户)
8. 忽略兴奋需求的时间衰减
9. 把无差异当期望(浪费开发资源)

## 五、3 工具串起来的实战流程(2 小时)

### Step 1(30 分钟)JTBD 找真需求
选 target 客户,写 3 层 job(功能/情感/社交)。
**产出**:3 句 JTBD statement

### Step 2(60 分钟)VPC 检查匹配
画左右两侧:
- 右侧 Customer Profile:Jobs / Pains / Gains(每类 5-8 个)
- 左侧 Value Map:Products / Pain Relievers / Gain Creators

关键检查:每 Pain 有 Reliever 吗?每 Gain 有 Creator 吗?
**产出**:对齐的 canvas + 发现的"未回应的 Pain/Gain"

### Step 3(30 分钟)Kano 排优先级
把 Value Map 归类到 5 类。
决策:
- 基本 + 1-2 关键期望 = MVP
- 无差异 = 砍
- 反向 = 立刻停
- 兴奋 = 差异化投入

**产出**:MVP 功能清单 + 差异化亮点清单

## 七、与 Messaging Framework 的连接

需求分析(本文)→ 定位与消息:

- **JTBD** 决定了 Positioning 里的"目标客户"和"关键利益"
- **VPC 的 Pain Relievers** 就是 Key Messages 里的"消息"
- **Kano 的兴奋需求** 就是 Elevator Pitch 里的"护城河"

**顺序**:先做需求分析,再做 Messaging。跳过需求分析直接写文案 = 空中楼阁。
