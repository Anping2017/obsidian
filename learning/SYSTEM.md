# 学习辅助系统(v0.1)

## 1. 是什么

vault 上的脚手架式学习辅助系统。

- **不是教练** — 不施压、不主动启动 session、不渲染挫败感
- **是工具箱** — 提供 6 种 mode 剧本、4 维进度评估、周/月复盘节奏

**目标**:把 1085+ wiki 从"图书馆"激活为"训练场",同时让知识库在使用中持续生长(代谢循环)。

## 2. 何时触发

Claude 检测到下列任一情况,**先读本文件**,按决策树进入系统:

- **关键词**:学习 / 总结 / 复盘 / 诊断 / 深入 / 全面理解 / 把 X 和 Y 连起来 / 用模型分析 / 帮我决策 / 升级 stub / 补 [概念]
- **用户主动开启**:"开 session"、"开始学习"、"想学 X"、"我有个困惑"
- **任何带"?"或"如何理解"的问题** → 默认 Mode F

**例外**:用户明确说"先不开学习系统,就闲聊",跳过本系统。

## 3. 决策树

```
1. 识别意图 → 匹配 A-F 哪个 mode(见下表)
2. 读 PLAYBOOK.md 对应章节,严格按步骤执行
3. (可选)读 DASHBOARD.md,拿该学科/概念的历史进度
4. 执行剧本步骤
5. 写 sessions/YYYY-WW-<mode>-<topic>.md(frontmatter 必含 vault_changes)
6. 末尾做"产物归档判定":本次产生的新素材/概念/综述去 raw/wiki/output 哪里?
   与用户确认后执行
7. 末尾基于 DASHBOARD 给一句温和建议(可拒绝)
```

### Mode 识别速查

| Mode | 触发模式 | 一句话 |
|---|---|---|
| **A 学科诊断** | "诊断 X"、"看看我 X 到几分"、"扫描 X" | 给一个学科生成"已掌握/薄弱/孤立/缺失"四类报告 |
| **B 跨域综合** | "把 X 和 Y 连起来"、"X 与 Y 的关系"、"综合 X Y" | 找隐藏连接,写综述到 output/ |
| **C 主题深读** | "深入 X"、"全面理解 X" | 把一个 topic/concept 读透,升级到 mature |
| **D 思维模型沙盒** | "用模型分析"、"帮我决策"、"应该不应该 X" | 用 3-5 个心智模型分析真实决策 |
| **E stub 升级** | "升级 stub"、"补 X" | 把 stub 重写为 mature 完整条目 |
| **F 自由提问** | 任何带"?"的问题、"我想问"、"如何理解" | 用 vault 知识快速回答 + 延伸 |

**冲突时**:不确定属哪个 mode → **主动问用户**,不要猜。详见 PLAYBOOK 末尾"冲突与歧义处理"章节。

## 4. Session 生命周期

```
[起始]                      [执行]                      [结束]
确认 mode               →   按 PLAYBOOK 步骤         →  写 sessions/<file>(frontmatter 含 vault_changes)
确认输入                    严格不跳步                    询问产物归档(raw/wiki/output)
(学科/概念/决策)                                          更新 DASHBOARD 客观字段
                                                         一句温和下一步建议(可拒绝)
```

**起始**:不确认就不开始;比如用户说"诊断金融"但没说哪个子领域,问清楚再进。

**执行**:严格读 PLAYBOOK 对应章节,按步骤号顺序;遇到模糊点,立即问用户而不是发挥。

**结束**:三件事——写 sessions、归档产物、温和建议。三件齐全才算结束。

## 5. 文件地图

| 文件 | 何时读 | 职责 |
|---|---|---|
| **`SYSTEM.md`**(本文件) | 检测到学习意图时第一个读 | 入口与决策树 |
| `RULES.md` | 用户挑战边界时 / 不确定能不能做时 | 必做/不能做清单 |
| `PLAYBOOK.md` | 确定 mode 后读对应章节 | 6 种剧本步骤 |
| `DASHBOARD.md` | 需历史进度参考 / 月复盘 | 12 学科 × 4 维度评分 + 全局健康指标 |
| `CHANGELOG.md` | 月复盘后写入 / 用户问"系统改过什么" | 版本与修订历史 |
| `sessions/` | 每次 session 末尾写入 | 会话日志(不是知识资产) |
| `reviews/` | 周/月复盘时写入与读取 | 复盘文档 |
| `_design/` | 设计层面的疑问 | 原始 spec 与 implementation plan |

## 6. 找不到答案怎么办

如果用户的请求**不能映射到任何 mode**,且不是闲聊:

- **优先 F mode 兜底**(自由提问最轻量,5-15 分钟)
- 如果 F 也不合适 → 说明请求超出本系统范围,正常处理(不强行套用学习系统)

**关键**:不要把所有交互都套进 mode。用户问"今天天气"就直接答,不要搞"开 F session"。

## 7. 与 vault 三层(raw/wiki/output)的关系

`learning/` 不是平行结构,而是**调度层**。

- **session 中遇到新原始素材**(网页、对话、书摘) → 转 markdown 入 `raw/<对应学科>/`
- **session 中产生新概念**或对已有概念有重大补充 → 在 `wiki/` 建 stub 或升级条目(**用户确认后**写入)
- **session 中产生综述、跨域分析、决策报告** → 入 `output/`,frontmatter `type: permanent` `tags` 加 `output`
- **sessions/ 文件本身只是日志,不是知识资产**;真正的资产在 raw/wiki/output

每次 session 末尾的"产物归档判定"是**强制步骤**,不能省略。

## 8. 系统自身的修改

本文件、`RULES.md`、`PLAYBOOK.md` 都不能擅自修改。

任何修改必须:
1. 在月复盘讨论中达成共识(或用户口头要求即时重构,但仍要走流程)
2. 写入 `CHANGELOG.md`
3. 按版本号策略调整版本

详见 `RULES.md` 与 `CHANGELOG.md`。
