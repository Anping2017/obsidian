# 跳表 Skip List

## 定义

**跳表(Skip List)**是一种基于概率的有序数据结构,在有序[[链表]]之上构建多级索引。每一级索引是下一级的"快进通道",查找时自顶向下、自前向后跳跃,实现期望 O(log n) 的查找、插入、删除。

它是 William Pugh 1989 年提出的"对树的概率替代品",代码量远少于红黑树/AVL,但性能可比。**Redis 的有序集合(zset)**、**LevelDB / RocksDB 的 MemTable** 都用跳表。

## 核心要点

### 结构

最底层是普通的有序链表,包含所有元素。
向上每一层是下层的随机子集 —— 每个节点以概率 p(通常 0.5 或 0.25)被"提升"到上一层。
理想情况下层数为 log_(1/p) n。

### 查找(O(log n) 期望)

```
从最高层开始
当前层向前走,直到下一个节点的 key > 目标
若不到,下降一层
重复直到底层,精确匹配或失败
```

### 插入(O(log n) 期望)

1. 找到插入位置(同查找,记录每层的 update 节点)
2. 随机生成新节点的层数(几何分布:第 k 层概率 p^(k-1))
3. 在每层把新节点链入

### 跳表 vs [[二叉搜索树]] / 平衡树

| 维度 | 跳表 | 红黑树 |
|---|---|---|
| 平均查找/插删 | O(log n) | O(log n) |
| 最坏查找 | O(log n) 高概率 | O(log n) 严格 |
| 空间(指针) | 期望 2n | 严格 2n |
| 实现复杂度 | 简单(无旋转) | 复杂(旋转、染色) |
| 范围查询 | 极简(底层链表向前走) | 需中序遍历 |
| 并发友好 | 节点局部锁更易 | 旋转涉及多节点 |
| 缓存友好 | 一般 | 一般 |

工程上 Redis 选跳表而非红黑树,主要原因:实现简单、范围查询(ZRANGEBYSCORE)直观、支持反向迭代(底层链表)。

### 概率层数生成

```
def random_level(max_level=32, p=0.25):
    level = 1
    while random() < p and level < max_level:
        level += 1
    return level
```

p=0.25 平衡空间与查找速度。

### 期望分析

每一层是下一层节点数的 p 比例。从最高层走到底层平均下降 log_(1/p) n 次,每层平均向前走 1/p 步,总期望步数 O((1/p) log_(1/p) n) = O(log n)。

## 和其他概念的关系

跳表是[[链表]]加索引的精巧扩展,与[[B+树]]、[[二叉搜索树]]构成"动态有序集合"的三大代表。Redis 用跳表 + [[Hash表]]实现 zset:跳表保证有序范围查询、Hash 表保证 O(1) 按 key 查分数。

LSM 树(Log-Structured Merge Tree)的 MemTable 部分也常用跳表(LevelDB、RocksDB),原因是单线程下追加性能极好、且 dump 到磁盘前能保持有序。

LRU/LFU 缓存常见的"哈希表 + 双向链表",和"跳表 + 哈希表"在思路上接近 —— 都是用辅助索引把顺序结构和按键访问结合。
