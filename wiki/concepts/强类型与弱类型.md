# 强类型与弱类型

## 定义

**强类型(Strongly-Typed)** 与 **弱类型(Weakly-Typed)** 描述语言对隐式类型转换的容忍度——强类型在不同类型操作时倾向报错或显式转换,弱类型倾向自动转换以让代码"跑得通"。这是语言设计中容易混淆但与 [[静态类型与动态类型]] 不同的维度。

## 核心要点

- **强类型代表**:Python、Java、C#、Go、Rust、Haskell。`"1" + 2` 报 TypeError。
- **弱类型代表**:C、JavaScript、PHP。`"1" + 2` 在 JS 得到 `"12"`、在 C 通过指针运算可能产生意外行为。
- **判断标准**
  - 跨类型运算是否需要显式转换。
  - 运行时是否做类型一致性检查。
  - 常见操作(+、==、隐式 boolean)是否定义一致。
- **JS 的"奇葩"案例**
  - `[] + {}` 得到 `"[object Object]"`,`{} + []` 得到 `0`(引擎解析为块语句 + 一元加)。
  - `==` 做隐式转换,易出错;`===` 严格相等。
  - 现代 TS、ESLint、`use strict` 把弱类型问题锁死或编译期暴露。
- **强类型 + 静态推导**
  - Rust/Haskell 不需写注解但仍强类型——一切类型在编译期被检查。
- **强类型 + 动态(Python)**
  - Python 强且动态——运行时报 TypeError;`int + str` 不会偷偷拼接。
- **维度组合**
  - 强 + 静态:Java、Rust、Haskell、Go。
  - 强 + 动态:Python、Ruby。
  - 弱 + 静态:C(指针/隐式数值转换);C++ 比 C 强。
  - 弱 + 动态:JavaScript、PHP(改良中)、Perl。
- **设计权衡**
  - 强类型减少运行时惊讶,代价是要写更多转换代码。
  - 弱类型代码看起来短,但暗藏陷阱。

## 关系

- 与 [[静态类型与动态类型]] 正交——共同构成类型系统的二维分类。
- [[TypeScript类型系统]] 把弱动态的 JS 变成强(基本)+ 渐进式静态。
- 影响 [[整洁代码]]、[[代码评审]] 关注点——弱类型项目更需要测试与 Lint。
- 与 [[内存管理]] 间接相关:弱类型语言常允许指针运算,内存安全更难保证。
- 影响 [[单元测试金字塔]] 设计——弱+动态语言通常需要更密的单元测试。
