# 编译vs解释

## 定义

**编译(Compilation)** 是把源代码整体翻译为目标语言(机器码、字节码、其他高级语言)的过程,翻译完成后再执行;**解释(Interpretation)** 是逐条读取源代码或中间表示并立刻执行,无需独立的目标产物。两者并非严格二分,现代语言多采用混合模式。

## 核心要点

- **纯编译**:C、C++、Rust、Go(到机器码);执行前完成全部分析与优化,启动快、运行快;调试需符号表;重新构建慢。
- **纯解释**:早期 BASIC、Bash 脚本;启动快、改即跑、跨平台;但慢且每次都重新分析。
- **字节码 + 虚拟机**:Java、Python、C#、Ruby——编译为平台无关字节码,由 VM 解释或 JIT 编译为本地代码;参考 [[字节码与中间表示]]。
- **JIT(Just-In-Time)**:运行时把热点代码编译为本地码并缓存——HotSpot、V8、PyPy、.NET CLR;参考 [[JIT编译]]。
- **AOT(Ahead-of-Time)**:启动前把字节码或源码编译为原生可执行;GraalVM Native Image、Dart AOT、Swift;启动快、内存小,但部分动态特性受限;参考 [[AOT编译]]。
- **混合实例**
  - JavaScript V8:解析为 AST → Ignition 字节码解释器 → TurboFan 优化 JIT。
  - Python:CPython 编译为字节码后解释;PyPy 用 tracing JIT;Cython 静态编译。
  - Java:javac 编译为字节码 → JVM 解释 + C1/C2 JIT,可选 AOT。

## 编译流水线一览

1. **词法分析**:源码 → token 流。
2. **语法分析**:token → AST。
3. **语义分析**:类型检查、作用域解析。
4. **中间代码生成**:AST → IR(三地址码、SSA、字节码)。
5. **优化**:常量折叠、循环展开、死代码消除、内联。
6. **目标代码生成**:IR → 机器码/字节码。
7. **链接**:解决符号引用,产生可执行文件;参考 [[链接与加载]]。

## 关系

- 与 [[字节码与中间表示]]、[[JIT编译]]、[[AOT编译]] 在同一坐标系上的不同点位。
- 与 [[静态类型与动态类型]] 正交——动态语言可以编译,静态语言可以解释。
- 影响 [[性能调优]] 策略——AOT 看启动,JIT 看长跑稳态。
- 与 [[操作系统]] 加载器的协作:编译产物经 [[链接与加载]] 进入内存。
