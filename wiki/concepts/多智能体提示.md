# 多智能体提示

## 定义

**多智能体提示**(Multi-Agent Prompting)是 [[提示词工程]] 中**让多个具有不同角色、视角或专业背景的 [[大语言模型]] 实例协同完成任务**的技术。

它把单一 LLM 解决问题的串行思考,扩展为**多个虚拟代理之间的对话、辩论、分工**,在复杂任务上常优于单 Agent,同时也增加了协调成本与系统复杂度。

## 核心要点

### 主要协作模式

#### 1. 辩论(Debate)

两个或多个 Agent 持不同立场互相质疑:

```
Agent A: 主张 X 因为 ...
Agent B: 反对 X 因为 ...
Agent A 反驳 ...
Agent B 反驳 ...
Judge Agent: 综合双方观点,得出结论
```

经典论文 *Improving Factuality and Reasoning in Language Models through Multiagent Debate*(2023):
- 多 Agent 辩论显著提升数学推理与事实准确性
- 不同 Agent 错误相互抵消
- 与 Self-Consistency 思想互补

#### 2. 分工(Division of Labor)

按角色分解任务:

```
Researcher: 收集相关信息
Writer: 基于信息撰写初稿
Editor: 审校润色
Critic: 提供改进意见
Final: 整合输出
```

CrewAI、AutoGen 框架的核心模式。

#### 3. 主管-工作者(Manager-Worker)

```
Manager: 拆解任务为子任务,分配给工作者
Worker A: 完成子任务 1
Worker B: 完成子任务 2
Manager: 整合结果,判断是否完成
```

类似项目管理的层级结构。

#### 4. 共识投票(Voting / Consensus)

多个 Agent 独立解决同一问题,投票或加权得出最终答案:

```
Agent 1: 答案 A
Agent 2: 答案 A
Agent 3: 答案 B
→ 多数答案 A
```

类似 Self-Consistency,但每个 Agent 可有不同 prompt / 视角。

#### 5. 角色扮演(Role Play)

模拟特定场景下的多方互动:

```
模拟法庭:
- 法官 Agent
- 原告律师 Agent
- 被告律师 Agent
- 证人 Agent
互相对话演绎过程
```

用于训练数据生成、教育模拟。

#### 6. 链式优化(Chain Refinement)

```
Agent 1: 初版答案
Agent 2: 基于初版的反思
Agent 3: 综合反思的修订版
Agent 4: 最终质量审查
```

[[反思提示]] 的多 Agent 化版本。

### 经典框架与实现

#### AutoGen(微软)

最早系统化多 Agent 框架:
- 自然语言定义 Agent 角色
- AssistantAgent + UserProxyAgent 二元
- 任务驱动的对话流
- 支持代码执行、工具调用

#### CrewAI

角色驱动的"团队"模式:
```python
researcher = Agent(role="Researcher", goal="...")
writer = Agent(role="Writer", goal="...")
crew = Crew(agents=[researcher, writer], tasks=[...])
crew.kickoff()
```

#### LangGraph(LangChain)

把多 Agent 协作建模为状态机/图:
- 节点 = Agent
- 边 = 状态转换
- 支持循环、条件分支

#### MetaGPT

模拟软件公司:
- 产品经理 → 写需求
- 架构师 → 设计
- 开发 → 编码
- 测试 → 验证
按瀑布流工作

### Prompt 设计要点

#### 1. 角色定义清晰

```
你是 Alex,一位资深财务分析师。
专长:财务建模、估值、风险分析。
风格:严谨、数据驱动、保守。
任务:对给定公司做估值分析。
不要做超出财务专业之外的判断。
```

#### 2. 通信协议明确

```
回应格式:
[发言人姓名]:[说话内容]

或结构化:
{
  "agent": "Alex",
  "intent": "提供分析",
  "content": "...",
  "next_speaker": "Bob"  // 谁接下来说
}
```

#### 3. 终止条件

防止无限循环:
- 最大轮次
- 达成共识
- 任务完成关键词
- 关键里程碑达成

#### 4. 共享上下文

- 所有 Agent 看到同一历史(全可见)
- 或仅看到自己角色相关信息(私有视角)
- 影响协作动态

#### 5. 工具与能力分配

不同 Agent 可有不同工具集:
- Researcher 有网页搜索
- Coder 有代码执行
- Reviewer 仅有读权限

### 优势

#### 1. 错误抵消

多个 Agent 独立思考,系统性错误概率降低(类似 ensemble)。

#### 2. 视角多元

避免单一 LLM 的思维定式。

#### 3. 复杂任务分解

把"超出单 Agent 上下文"的任务通过分工解决。

#### 4. 模拟真实流程

适合模拟复杂工作流(软件开发、法庭、医疗会诊)。

### 局限与挑战

#### 1. 协调成本

多 Agent 需多次 LLM 调用 → token 与时间成本倍增。

#### 2. 同质化

所有 Agent 用同一底层模型 → 共享同样偏见与盲点。
应对:用不同模型(GPT-4 + Claude + Gemini)。

#### 3. 责任分散

某个 Agent 错误,整体责任不清。

#### 4. 死锁与循环

Agent 互相等待或反复修改 → 任务停滞。

#### 5. 漂移

长对话中 Agent 可能"忘记"原始任务,跑偏。

#### 6. 谄媚效应

Agent 间可能互相赞同,失去批判性。

### 实务建议

1. **单 Agent 优先**:能用单 Agent 解决就不用多 Agent
2. **明确分工**:重叠角色 = 浪费
3. **数量适度**:2-4 个常足够,> 6 难管理
4. **限制对话深度**:不要让 Agent 无限聊
5. **关键节点人工干预**:重大决策需人确认
6. **监控 token 与延迟**:防成本失控
7. **测试多种角色组合**:不同问题需不同团队

### 评估方法

#### AgentBench

多 Agent 复杂任务基准。

#### 真实场景指标

- 任务完成率
- 响应时间
- token 消耗
- 用户满意度

#### 内部一致性

Agent 间结论是否互相支撑?

### 与单 Agent 的对比

| 维度 | 单 Agent | 多 Agent |
|---|---|---|
| 简单任务 | ✓ 更优 | 浪费 |
| 复杂规划 | 受限 | ✓ 更优 |
| 多视角分析 | 受限 | ✓ 更优 |
| 成本 | 低 | 高 |
| 调试 | 易 | 难 |
| 责任清晰 | 高 | 低 |
| 扩展性 | 低 | 高 |

### 与 [[反思提示]] 的关系

[[反思提示]] 是同一 Agent 自我批评;多 Agent 是不同 Agent 互相批评。前者节省成本,后者多样性强。

### 行业应用

- **学术研究**:辩论式增强推理
- **代码生成**:Coder + Reviewer + Tester
- **客服**:Triage + Specialist + Manager
- **创作**:Brainstormer + Writer + Editor
- **决策辅助**:多专家 Agent 模拟咨询

## 和其他概念的关系

- 是 [[提示词工程]] 高级技巧
- 与 [[反思提示]]、[[思维链]] 形成"协作 + 思考"组合
- 与 [[AI Agent框架]] 紧密关联(AutoGen、CrewAI)
- 用 [[工具调用提示]] 让 Agent 与现实交互
- 应用于 [[AI编码助手]] 高级模式(MetaGPT、ChatDev)
- 在 [[AI模型评估基准]] 中 AgentBench 等专门测试
- 与 [[超级对齐]] 中的"AI 监督 AI"思想相通
- [[OpenAI]] Swarm、[[Anthropic]] 内部 Agent 实验代表前沿
