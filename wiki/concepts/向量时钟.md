# 向量时钟

## 定义

**向量时钟(Vector Clock)** 是 Friedemann Mattern 和 Colin Fidge 在 1988 年独立提出的逻辑时钟扩展。它为分布式系统中每个进程维护一个版本号数组(向量),通过数组的偏序比较捕捉事件的**因果关系(happens-before)**,精确识别"先后"与"并发",是 Dynamo / Riak / Voldemort 等无主复制系统检测冲突的核心。

## 核心要点

- **背景:Lamport 时钟的不足**
  - Lamport 1978 年提出标量逻辑时钟:每个事件一个数,a → b ⇒ C(a) < C(b),但反之不一定
  - 即"小者不一定先",无法区分因果与并发
  - 向量时钟补上这一短板
- **数据结构**
  - 每个进程 Pi 维护向量 V_i = [V_i[1], V_i[2], ..., V_i[N]],N = 进程数
  - V_i[j] 表示 Pi 已知的 Pj 的最新事件计数
- **更新规则**
  - **本地事件**:V_i[i] += 1
  - **发送消息 m**:先 V_i[i] += 1,把 V_i 附在 m 上发送
  - **接收消息 m**:V_i[k] = max(V_i[k], V_m[k]) for all k,然后 V_i[i] += 1
- **比较规则**
  - V_a ≤ V_b 当且仅当 V_a[k] ≤ V_b[k] 对所有 k
  - V_a < V_b ⇔ V_a ≤ V_b 且 V_a ≠ V_b ⇒ a 因果先于 b
  - V_a 与 V_b 不可比 ⇒ a 与 b 并发(concurrent)
- **判断结果**
  - **a 因果先于 b**:b 一定能"看到" a 的影响
  - **a 与 b 并发**:它们独立发生,需冲突解决
- **典型应用**
  - **Dynamo / Riak**:多副本写入时附带向量时钟,读取时检测并发版本
  - **Git 合并**:DAG 实质是一种向量时钟变体
  - **协同编辑(OT/CRDT)**:跟踪操作因果
  - **Causal+ Consistency**:用向量时钟保证因果一致
- **冲突解决策略**
  - **Last-Write-Wins(LWW)**:用墙钟时间最大者胜出,简单但丢数据
  - **应用层语义合并**:如购物车并发写,合并两份的并集
  - **保留所有并发版本**:让用户/上游决定(Riak 的 sibling)
  - **CRDT**:数学保证合并无冲突,如 G-Counter、PN-Counter、OR-Set
- **挑战与替代**
  - **空间膨胀**:N 个进程的向量长度 N,百万节点不现实
  - **解决:版本向量(Version Vector)**:不为每个客户端记录,只为副本节点
  - **Dotted Version Vector(DVV)**:Riak 改进,精确处理客户端并发
  - **Hybrid Logical Clock(HLC)**:CockroachDB / YugabyteDB 用,结合物理时间和逻辑计数
  - **TrueTime**:Spanner 用 GPS+原子钟,不需要向量
- **逻辑时钟谱系**
  - **Lamport 时钟**:标量,只判断因果偏序
  - **向量时钟**:精确捕捉因果与并发
  - **矩阵时钟**:每节点存所有节点对其他节点的视图,空间 O(N²)
  - **HLC**:折中,实用化主流

## 和其他概念的关系

向量时钟是 [[一致性模型]] 中"因果一致性"的实现工具,广泛用于 [[NoSQL数据库]] 的多副本冲突解决。

它替代物理时钟解决分布式系统时钟漂移问题,是 [[BASE理论]] 与最终一致性的关键支撑。

[[Raft共识算法]] / [[Paxos]] 通过 Leader 强制全序,不需要向量时钟;而 [[主从复制]] 的多主拓扑、Cassandra 的无主架构则离不开它。

[[消息队列]] 中,事件溯源系统用向量时钟保证事件因果顺序;Kafka 通过分区内有序简化这一问题。

[[微服务]] 跨服务调用追踪因果(Trace ID + Span ID + 父子关系)本质也是向量时钟思想的工程版本。
