# RAG

## 定义

**RAG(Retrieval-Augmented Generation, 检索增强生成)** 是把外部知识检索与 [[大语言模型]] 生成相结合的范式:回答问题前,先用查询去向量库或搜索引擎检索若干相关文档片段,把这些片段连同原始问题一起塞入 prompt,让模型基于真实材料生成答案。

由 Lewis et al. (2020) 提出,如今已是企业级 LLM 应用最主流的架构。

## 核心要点

**典型流水线**

1. **离线阶段**:文档切块 → 计算 [[Embedding]] → 写入 [[向量数据库]]
2. **在线阶段**:用户查询 → 计算查询 Embedding → 向量数据库召回 Top-K → 重排 → 拼入 prompt → LLM 生成

**关键设计点**

| 阶段 | 关键决策 |
|---|---|
| 切块(Chunking) | 大小(常 200-1000 token)、重叠、按语义/段落切 |
| 嵌入模型 | OpenAI text-embedding-3、BGE、Cohere 等 |
| 检索 | 纯向量、纯关键词(BM25)、混合检索(主流) |
| 重排(Rerank) | 用 cross-encoder 重排前 K 提升精度 |
| Prompt 拼装 | 引用格式、上下文优先级、系统指令 |
| 评估 | 检索召回率、生成忠实度、回答相关性 |

**为何主流**

- 解决 [[幻觉]]:模型基于真实文档生成,可校验
- 解决知识过时:更新知识库即可,无须重训模型
- 解决私有知识:企业内部文档不进训练,但可检索
- 成本低于微调:更新效率高、可解释性强

**进阶变体**

- 多步 RAG / Agent RAG:让模型决定查什么、查几次
- 图 RAG(GraphRAG):结合知识图谱
- 自反思 RAG(Self-RAG):模型自评检索质量
- 长上下文 vs RAG:百万 [[上下文窗口]] 出现后,二者关系重新平衡

**典型踩坑**

- 切块过小丢上下文,过大稀释相关性
- 仅用向量检索难处理精确名词,需混合 BM25
- 检索到无关文档反而误导模型(噪声放大)
- 评估困难,需独立维护检索 + 生成两层指标

## 和其他概念的关系

- 核心组件:[[Embedding]] + [[向量数据库]] + [[大语言模型]]
- 主要价值:大幅降低 [[幻觉]] 风险,提供可溯源答案
- 与 [[预训练与微调]] 对比:更新知识不必动权重,运维更轻
- 与 [[上下文窗口]] 关系:窗口越大,可塞入更多检索片段,但二者并非互相替代
- 与 [[函数调用]] 协同:RAG 解决"查文档",函数调用解决"调 API",[[AI Agent]] 中常并存
- 工程优化:[[Prompt Caching]] 可缓存长固定指导部分降低成本
- 计算机科学基础:精确召回常用 [[Hash表]] 做去重和精确匹配过滤;分布式向量检索中分片路由依赖 [[一致性Hash]];混合检索的关键词通道与传统 [[搜索引擎优化]] 的倒排索引、BM25 共享同一套技术栈
