# Python装饰器

## 定义

**装饰器(Decorator)** 是 Python 的一种语法糖,通过 `@decorator` 写在函数或类定义之上,等价于 `f = decorator(f)` —— 把原函数传给装饰器,用返回值替换原引用。它是[[闭包]]、高阶函数与元编程的组合产物,广泛用于横切关注点(日志、缓存、权限、计时)。

## 核心要点

- **本质**:`@deco` 即 `func = deco(func)`,装饰器是接收函数返回函数的高阶函数。
- **保留元信息**:用 `functools.wraps` 把 `__name__`/`__doc__`/`__wrapped__` 从原函数复制到包装器,避免内省失真。
- **带参装饰器**:三层嵌套——外层接装饰器参数,中层接被装饰函数,内层接调用参数。
- **类装饰器**:实现 `__call__` 的类也可作装饰器,适合需要状态(计数器、缓存表)的场景。
- **装饰类**:装饰器同样可作用于类,常见用途包括注册到全局表、注入新属性、改写方法。
- **常用内置**:`@staticmethod`、`@classmethod`、`@property`、`@functools.lru_cache`、`@dataclass`。
- **顺序**:多装饰器从下往上应用、调用时从上往下进入(类似栈)。
- **副作用与陷阱**:在导入时立即执行装饰器主体——副作用要谨慎;捕获循环变量需用默认参数固化。

## 关系

- 是 [[Python生成器]]、[[Python上下文管理器]]、[[Python元类]] 之外另一类元编程武器,共同支撑 Pythonic 抽象。
- 实现依赖 [[闭包]] 的"函数+定义环境"语义。
- 在 [[设计模式]] 视角下对应 GoF 装饰器模式,但 Python 用一等函数+语法糖大幅简化。
- 与 [[Python GIL]] 无直接关系,但 `lru_cache` 等装饰器常用于优化受 [[GIL]] 影响的 CPU 密集计算。
- 与 [[面向对象编程]] 的方法装饰(property、classmethod)结合改写属性访问语义。
- 在 Web 框架(Flask 路由、Django view、FastAPI 依赖注入)中是核心 API 形态。
