# 复杂度分析 Complexity Analysis

## 定义

复杂度分析是评估[[算法]]在不同输入规模 n 下消耗的**时间**与**空间**资源的方法论。它不关心特定机器、编译器、常数因子,只关注当 n 趋于无穷时,资源消耗如何随 n 增长 —— 即"渐进行为(asymptotic behavior)"。最常用的工具是**大 O 记号**(Big O):上界。配套有大 Ω(下界)和大 Θ(紧界)。

复杂度分析有两个维度:
- **时间复杂度**:基本操作执行次数
- **空间复杂度**:除输入外所需的额外存储

## 核心要点

### 大 O 的含义

T(n) = O(f(n)) 意味着存在常数 c 和 n₀,使所有 n ≥ n₀ 时 T(n) ≤ c·f(n)。直觉理解:f(n) 是 T(n) 的"上界趋势"。

### 常见复杂度等级(由低到高)

| 记号 | 名称 | 典型算法 |
|---|---|---|
| O(1) | 常数 | 数组下标访问、[[Hash表]]查找 |
| O(log n) | 对数 | [[二分查找]]、平衡树操作 |
| O(n) | 线性 | 遍历、线性搜索 |
| O(n log n) | 线性对数 | 快速排序、归并排序、堆排序 |
| O(n²) | 平方 | 冒泡排序、双层嵌套 |
| O(2ⁿ) | 指数 | 朴素递归斐波那契、子集枚举 |
| O(n!) | 阶乘 | 全排列、TSP 暴力解 |

### 三种情况分析

- **最坏情况(Worst Case)**:输入下界保证,工程上最常用
- **最好情况(Best Case)**:输入恰好让算法最快
- **平均情况(Average Case)**:随机输入下的期望,如[[快速排序]]平均 O(n log n)、最坏 O(n²)

### 主定理(Master Theorem)

[[分治算法]]复杂度的常用工具:T(n) = aT(n/b) + f(n) 可根据 a、b、f 的关系直接得出。如归并排序 T(n) = 2T(n/2) + O(n) → O(n log n)。

### 摊还分析(Amortized Analysis)

单次操作可能很慢但平均到一系列操作上是低复杂度。如[[动态数组]]扩容:单次扩容 O(n),但 n 次 push 的平均代价是 O(1)。

### 空间复杂度的常见误区

输入本身占用的空间不算入空间复杂度;只计算辅助空间。递归算法空间复杂度等于递归调用栈深度(如归并排序 O(log n) 栈空间)。

## 和其他概念的关系

复杂度是设计与选择[[数据结构]]、[[算法]]的核心标尺。同一问题用不同[[排序算法]]差距巨大,O(n²) 在 n=10⁶ 时已不可用。[[Hash表]]靠 O(1) 平均查找击败 O(log n) 的[[二叉搜索树]]但牺牲有序性。[[动态规划]]与朴素[[递归]]的差异本质是"重叠子问题"导致的指数到多项式爆炸。系统设计中,[[缓存]]把高频操作从 O(磁盘 IO) 降到 O(内存访问),数量级差异。

复杂度分析也指导[[数据库索引]]选择(B+ 树 O(log n) 查找)、[[负载均衡]]路由(一致性 hash O(log n))、密码哈希(故意慢)。

AI 应用:深度学习的可行性根本上由复杂度决定 —— [[Transformer]] 自注意力的 $O(n^2)$ 是当前长上下文优化(FlashAttention、稀疏注意力、线性注意力)所要攻克的对象;[[神经网络]] 训练中前向、反向传播的算力评估全部走复杂度分析的同一套语言;[[机器学习]] 算法选型时,样本量 $n$ 与维度 $d$ 决定了哪种算法在可接受时间内收敛(SVM 的 $O(n^2)\sim O(n^3)$ 在大数据下被神经网络取代,部分原因即此)。
