# 进程与线程 Process and Thread

## 定义

**进程(Process)**是[[操作系统]]进行**资源分配**的基本单位。一个进程拥有独立的:
- 虚拟地址空间(代码段、数据段、堆、[[栈]])
- 文件描述符表
- 信号处理表
- 用户身份与权限

**线程(Thread)**是 CPU **调度执行**的基本单位,运行在进程内。同一进程的多个线程**共享**进程的地址空间和资源,但各有独立的:
- 程序计数器(PC)
- 栈
- 寄存器上下文
- 线程本地存储(TLS)

口诀:**进程 = 资源 + 1 个或多个线程,线程 = 进程内的执行流**。

## 核心要点

### 进程 vs 线程对比

| 维度 | 进程 | 线程 |
|---|---|---|
| 内存空间 | 独立 | 共享 |
| 创建/销毁代价 | 重(MB 级) | 轻(KB 级) |
| 切换成本 | 大(刷新页表、TLB) | 小(栈/寄存器) |
| 通信方式 | IPC(管道、共享内存、socket、信号) | 共享变量 + 锁 |
| 隔离性 | 强(一个挂掉不影响别的) | 弱(一个崩溃整个进程崩) |
| 安全性 | OS 级隔离 | 同进程信任域 |

### 进程的生命周期

新建 → 就绪 → 运行 → 阻塞 → 终止。状态转换由调度器、IO 完成、信号、退出系统调用驱动。

### 进程创建:fork() / exec() / spawn()

Unix 经典:
- `fork()`:复制当前进程,父子各执行,通过返回值区分
- `exec()`:替换当前进程映像为新程序
- `fork()` + `exec()` 是 shell、`system()` 调用的基础

Windows:`CreateProcess()` 直接创建新进程(无 fork)。Python `subprocess` 跨平台封装。

### 用户线程 vs 内核线程

- **用户线程(N:1)**:用户态调度,内核看到一个进程。优势:切换零系统调用;劣势:一线阻塞全部阻塞,无法利用多核
- **内核线程(1:1)**:内核调度,Java/C++/Linux pthread 默认。优势:多核并行;劣势:创建切换有内核开销
- **混合(M:N)**:Go runtime 把 M 个 goroutine 映射到 N 个 OS 线程,兼顾切换轻量与多核利用

### Go 的 Goroutine

不是线程,是用户态轻量执行单元(几 KB 栈起步)。Go runtime 的调度器(GMP 模型)在少量 OS 线程上调度成千上万 goroutine。这是为何 Go 处理高并发以"廉价"著称。

### 协程(Coroutine)

用户态的、协作式调度的"线程":自己 yield 让出 CPU。Python asyncio、Kotlin coroutine、Lua coroutine、C++20 coroutine。本质是带保存恢复机制的函数。

### IPC 进程间通信

- **管道(Pipe)**:父子进程单向字节流
- **命名管道(FIFO)**:有名字,无亲缘关系也能用
- **消息队列**:System V、POSIX
- **共享内存**:最快,需要外部同步
- **信号量**:同步原语
- **Socket**:本机或跨机
- **信号(Signal)**:异步通知

### 线程同步

见[[并发与并行]]:互斥锁、读写锁、条件变量、信号量、屏障、原子操作。

### 现代趋势:容器与隔离

[[Docker容器]]复用 Linux Namespace + cgroups 实现"轻量级进程隔离":各容器进程共享内核但有独立的 PID、网络、文件系统视图。介于进程和虚拟机之间。

## 和其他概念的关系

进程与线程是[[操作系统]]最核心的抽象之一。[[并发与并行]]的实现底层就是进程/线程模型。线程之上有协程/goroutine,进程之上有[[Docker容器]]、虚拟机。

[[事件循环]]是单线程的极致优化:用一个线程处理海量 IO,绕过线程切换开销。Node.js、Nginx 用此模式;Java NIO、Vertx 类似。

[[消息队列]]在分布式语境下做了进程间通信的工业化:不只跨进程,还跨机器、跨数据中心。Erlang Actor 模型把"进程"轻量化到一个 VM 内,数百万进程共存。
