# 模型评估

## 定义

**模型评估(Model Evaluation)** 是用一系列指标和基准来衡量 [[机器学习]] 模型在未见数据上能力与可靠性的过程。它是模型选择、版本对比、上线决策的依据。在 [[大语言模型]] 时代,评估变得更加困难也更加重要,因为模型能力多维、任务开放、错误形态复杂。

## 核心要点

**经典 ML 指标**

| 任务 | 主要指标 |
|---|---|
| 二分类 | 准确率、Precision/Recall/F1、AUC-ROC、AUC-PR |
| 多分类 | Macro/Micro F1、Top-K 准确率 |
| 回归 | MSE、RMSE、MAE、R² |
| 排序 | NDCG、MAP、MRR |
| 聚类 | 轮廓系数、ARI |

评估前提是有独立的 [[训练集与测试集]] 划分。

**LLM 时代评估难点**

- 输出开放,无标准答案 → 需用 LLM-as-Judge 或人工评测
- 单一基准 saturating fast,模型刷分但实际能力没增长
- 训练数据污染:基准被泄露入预训练
- 安全/真实性/有害性等多维度,需独立评测
- 涌现能力评估非线性(参见 [[涌现能力]] 中的"海市蜃楼"争论)

**主流大模型基准**

| 基准 | 评估什么 |
|---|---|
| MMLU | 57 个学科多选题,综合知识 |
| GSM8K / MATH | 数学推理 |
| HumanEval / MBPP | 代码生成 |
| HellaSwag / ARC | 常识推理 |
| TruthfulQA | 真实性、抗 [[幻觉]] |
| MT-Bench / Chatbot Arena | 对话能力,人类偏好 |
| SWE-bench | 真实软件工程任务 |
| HELM | 多维全面评估框架 |

**生成质量评估**

- BLEU、ROUGE、METEOR:n-gram 匹配,翻译/摘要传统指标
- BERTScore:基于 [[Embedding]] 的语义相似度
- LLM-as-Judge:用强 LLM 给候选打分,主流但有偏差
- 困惑度(Perplexity):语言模型预训练标准指标
- 人工评估:仍是黄金标准,但贵且慢

**评估工程实践**

- 把评估集和 prompt 一起版本化
- 区分功能集(任务能否完成)与回归集(性能不退化)
- A/B 测试 / Online 指标(用户停留、回购、问题解决率)
- 监控线上 [[幻觉]] 率、[[提示注入]] 攻击成功率

## 和其他概念的关系

- 数据基础:必须有 [[训练集与测试集]] 的严格划分
- 与 [[过拟合与正则化]]:评估数据出现在训练流程中即等于作弊
- 服务对象:[[机器学习]] 与 [[大语言模型]] 全链路
- 特殊维度:[[幻觉]] 评估、安全评估是 LLM 独有维度
- 与 [[涌现能力]] 关系:评测设计影响是否能观测到能力跃迁
