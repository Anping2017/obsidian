# 数据库 Database

## 定义

数据库(Database, DB)是**长期存储在计算机中、按特定数据模型组织、可被多用户并发共享、并支持高效检索与维护**的数据集合。数据库由**数据库管理系统(DBMS)** 管理,DBMS 提供:

- 数据定义语言(DDL):描述数据结构
- 数据操纵语言(DML):增删改查
- 事务管理:[[ACID]] 保证
- 并发控制:[[锁机制]]、[[MVCC]]
- 故障恢复:WAL、备份、复制

## 核心要点

### 数据模型分类

| 模型 | 代表 | 特点 |
|---|---|---|
| 关系模型 | [[关系型数据库]](MySQL、PostgreSQL、Oracle) | 表 + 关系,SQL 标准 |
| 键值 | Redis、DynamoDB | 简单、低延迟 |
| 文档 | MongoDB、CouchDB | JSON 嵌套、模式灵活 |
| 列族 | HBase、Cassandra | 大规模写入、稀疏数据 |
| 图 | Neo4j | 节点+边,关系密集 |
| 时序 | InfluxDB、TimescaleDB | 时间戳为核心维度 |
| 向量 | [[向量数据库]] (Pinecone, Milvus) | 相似度检索,AI 时代崛起 |

[[NoSQL数据库]] 泛指非关系型,各有专长。

### 基础架构

- **存储引擎**:数据如何在磁盘组织([[B+树]]、LSM-Tree、列存)
- **查询引擎**:解析 SQL → 优化 → 生成执行计划([[查询优化器]])
- **事务管理器**:协议保证 [[ACID]]
- **并发控制**:[[数据库锁机制]] 与 [[MVCC]]
- **缓冲池**:把热数据驻留内存,减少磁盘 IO

### 三个核心议题

1. **一致性 vs 可用性 vs 性能**:CAP 与 [[BASE理论]] 的权衡
2. **OLTP vs OLAP**:在线事务处理高并发短事务,在线分析处理低并发长查询。[[OLAP与OLTP]]
3. **行存 vs [[列式存储]]**:OLTP 行,OLAP 列

### 索引与优化

- 索引本质是另一份排好序的数据副本,加速查找。详见 [[数据库索引]]
- [[数据库范式]] 控制冗余;反范式换查询性能
- [[查询优化器]] 选择最佳执行计划,基于代价估计与统计信息

### 分布式与扩展

- **主从复制**:写主、读从,提升读吞吐
- **分库分表**:按 hash/range 切片
- **[[分布式事务]]**:2PC、Saga、TCC
- **[[Raft共识算法]]**:多副本一致性

## 和其他概念的关系

数据库是 [[计算机科学知识体系|计算机科学]] 中应用最广泛的系统软件之一,与 [[操作系统]]、[[编译原理]] 并列为三大支柱。

数据库优化深度依赖 [[数据结构]] 与 [[算法]] :索引选型(B+树、Hash、跳表)、查询优化(动态规划做 join 顺序)。

[[数据仓库]] 与 [[ETL与ELT]] 是数据库的衍生体系,支持企业级分析。[[列式存储]]、[[Lambda架构]]、流处理引擎是大数据时代的产物。

应用层通过 ORM(SQLAlchemy、Hibernate)或原生驱动访问数据库;[[微服务]] 时代每服务一库,带来 [[分布式事务]] 与 [[分布式锁]] 挑战。AI 时代,[[向量数据库]] 成为 [[RAG|RAG检索增强生成]] 的关键基础设施。
