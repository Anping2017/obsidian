# 反思提示

## 定义

**反思提示**(Reflection Prompting / Self-Reflection)是 [[提示词工程]] 中让 [[大语言模型]] **对自己产生的输出进行批判性审视和修正**的技术。

它不是单次输出最终答案,而是让模型经过"**生成 → 批评 → 修订**"的多轮循环,显著提升复杂任务的答案质量、事实准确性、可靠性,是 [[Constitutional AI]] 与 Reflexion 等方法的核心思想。

## 核心要点

### 基本范式

```
轮次 1:模型生成初始答案 A1
轮次 2:模型对 A1 自我批评 → 找出错误、遗漏
轮次 3:基于批评生成改进版 A2
轮次 4:可继续迭代,直到收敛
```

### 简单实现示例

```
你刚才回答:[A1]
请站在挑剔的专家角度,仔细审视这个回答:
- 有哪些事实错误?
- 哪些推理跳跃?
- 漏掉哪些重要角度?
- 风格是否合适?

列出至少 3 条批评,然后基于这些批评重写答案。
```

### 主要变体

#### 1. Self-Refine(2023, CMU/Allen AI)

经典论文 *Self-Refine: Iterative Refinement with Self-Feedback*:
- 同一个 LLM 既生成又批评又修订
- 在数学、对话、代码、改写任务上均提升
- 不需要外部反馈

#### 2. Reflexion(2023, Northeastern)

强化学习视角:
- LLM 作为"演员"生成答案
- LLM 作为"评估员"打分
- LLM 作为"自我反思员"分析为什么失败
- 把反思加入下次 prompt
- 在 ALFWorld、HotpotQA 等任务上接近 SOTA

#### 3. Constitutional AI 的反思

[[Anthropic]] 在训练阶段把"反思"作为数据生成方式:
- 模型对有害输出自我批评(critique)
- 基于批评修订(revise)
- 用修订后数据微调

#### 4. CoVe(Chain-of-Verification)

Meta 提出的事实核查反思:
1. 生成初始答案
2. 生成验证问题(每个事实点的核查问句)
3. 独立回答这些验证问题
4. 综合验证结果修正答案

显著降低事实性幻觉。

#### 5. Step-Back Prompting(Google DeepMind)

回答具体问题前,先抽象出更高层概念,再用此引导回答。是反思的"升维"形式。

### 反思的关键设计原则

#### 1. 批评维度明确

模糊的"请检查一下"效果差,明确的"检查事实、检查逻辑、检查覆盖度"效果好。

#### 2. 多视角

让模型扮演不同角色批评:
- 外行用户视角(易理解吗?)
- 专家视角(准确吗?)
- 反对者视角(漏洞在哪?)

#### 3. 适度的迭代次数

通常 2-3 轮收益最高;过多迭代可能过度修正或引入新错误。

#### 4. 明确的终止条件

- "直到无新问题"
- 固定轮数
- 评分超过阈值

### 与 [[思维链]] 的对比

| 维度 | CoT | Reflection |
|---|---|---|
| 时点 | 生成时展示推理 | 生成后审视答案 |
| 目的 | 多步推理 | 修正错误 |
| 计算次数 | 1 次 | 多次 |
| 适用 | 数学、逻辑 | 复杂任务、事实性、安全 |

两者可组合:CoT 生成,Reflection 审视。

### 与 Self-Consistency 的对比

| 维度 | Self-Consistency | Reflection |
|---|---|---|
| 思路 | 多次独立采样投票 | 单次答案迭代修正 |
| 多样性 | 高(不同路径) | 低(同一答案演化) |
| 计算 | 并行 | 串行 |
| 适用 | 数学、有标准答案 | 开放生成 |

### 局限

#### 1. 过度自信问题

模型对自己答案过于自信 → 反思变形式化,不真正修正。

#### 2. 过度修正

反思可能引入新错误,从对的改成错的。

#### 3. 计算成本

多轮 → 多倍 token 成本与延迟,生产环境需权衡。

#### 4. 同质性

同一模型既生成又批评 → 可能重复同样错误。
应对:用不同模型(如 GPT-4 生成,Claude 批评)。

#### 5. 边际收益递减

第 3 轮后通常收益很小。

### 实务模板

#### 通用反思

```
任务:[原始问题]
初稿:[模型回答 A1]

请进行如下反思:
1. 找出 A1 中可能的错误或不足(列表形式)
2. 解释每个问题为何存在
3. 给出改进版 A2,确保:
   - 修正所有指出的问题
   - 保持原文优点
   - 不引入新问题
```

#### 事实性反思

```
答案:[A1]

请列出 A1 中的所有具体事实陈述。
对每个事实,标注:
[确定] / [不确定] / [可能错误]

对所有 [不确定] 和 [可能错误],
要么删除,要么改为更保守的表述。
```

### 在产品中的体现

- **OpenAI o1 / o3**:把反思内化为推理过程("thinking")
- **Claude Extended Thinking**:模型在隐藏区域反思后输出
- **DeepSeek R1**:RL 训练中通过反思 token 涌现推理能力
- **AutoGPT 等 Agent**:每步骤后反思决策

### Reasoning Models 的兴起

2024-2025 年"推理模型"(o1、Claude Thinking、DeepSeek R1)把反思机制从 prompt 移到训练:
- 训练数据包含大量"先思考再回答"的模式
- 模型推理时自然进入"思考态"
- 用户看到的是反思后的精简答案

这使得反思从"用户调用的 prompt 技巧"变成"模型本身的能力"。

## 和其他概念的关系

- 是 [[提示词工程]] 高级技巧
- 与 [[思维链]] 互补,可组合使用
- 与 Self-Consistency 在思路上不同但目标相似
- 是 [[Constitutional AI]] 的核心训练手段
- 与 [[AI Agent框架]] 中的"自检"步骤一脉相承
- 反思能力的内化推动 OpenAI o1、Claude Thinking、[[DeepSeek]] R1 等推理模型
- 与 [[超级对齐]] 中的可扩展监督思想相通(让模型监督自己)
- 用于减少 [[大语言模型]] 的幻觉
