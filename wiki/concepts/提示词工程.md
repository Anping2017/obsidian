# 提示词工程

## 定义

**提示词工程(Prompt Engineering)** 是系统化地设计、优化和管理输入给 [[大语言模型]] 的文本指令,以引导其产生符合预期输出的工程方法论。其根本思想是:由于 LLM 已具备强大的预训练能力,改变 prompt 比改变权重便宜得多,大部分能力调用通过 prompt 即可完成。

由 GPT-3 论文(2020)引爆,经 ChatGPT(2022)普及为大众词汇,如今已是 AI 应用工程的核心技能。

## 核心要点

**主要范式**

- [[零样本提示]]:仅靠指令完成任务
- [[少样本提示]]:在 prompt 中给少量示例引导
- [[思维链]]:引导模型展示推理步骤,提升复杂任务表现
- 角色提示:为模型设定身份("你是资深律师...")
- [[结构化输出]]:约束输出为 JSON、Markdown、特定 schema

**结构要素(常见 RTCF 框架)**

| 要素 | 作用 |
|---|---|
| Role(角色) | 设定模型身份与视角 |
| Task(任务) | 明确要做什么、目标是什么 |
| Context(上下文) | 提供背景信息、约束、参考材料 |
| Format(格式) | 指定输出结构、长度、风格 |

**进阶技术**

- 提示词链(Chain):把复杂任务拆成多步 prompt 串联
- Self-Consistency:多次采样取多数答案
- Tree of Thoughts:让模型探索多个推理分支
- ReAct 模式:推理 + 工具调用交替,见 [[AI Agent]]
- 元提示(Meta-Prompting):用 LLM 自动生成或优化 prompt
- 评估与版本化:把 prompt 当代码管理,有测试集和回归

**核心威胁**

- [[提示注入]]:第三方内容劫持模型行为,是 LLM 应用安全的头号问题
- 模型版本敏感:同一 prompt 在不同模型上效果迥异,需重新调优

**经验法则**

- 清晰胜过聪明:模糊的高级技巧不如简单明确的指令
- 给示例胜过描述要求:[[少样本提示]] 通常比堆叠形容词更有效
- 任务越复杂越要拆解:用 [[思维链]] 或多步链条
- 测试驱动:建立可重复的评测集,prompt 改动用 A/B 验证

## 和其他概念的关系

- 主要载体:作用于 [[大语言模型]] 的输入侧
- 核心方法:[[零样本提示]]、[[少样本提示]]、[[思维链]]、角色提示
- 进阶组合:在 [[AI Agent]] 中与 [[函数调用]]、[[RAG]] 共同构成应用层
- 安全维度:[[提示注入]] 防御是工程实践必修课
- 替代/补充:与 [[预训练与微调]] 互为补充,prompt 适合快速迭代,微调适合大改行为
- 经济维度:[[Prompt Caching]] 让长 prompt 经济可行
