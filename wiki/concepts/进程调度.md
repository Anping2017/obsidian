# 进程调度

## 定义

**进程调度(Process Scheduling)** 是操作系统在多个就绪进程/线程之间分配 CPU 时间的机制。调度器目标是兼顾公平性、响应时间、吞吐量、可预测性,并考虑实时任务、I/O 任务、CPU 密集任务的不同特征。

## 核心要点

- **三类调度时机**
  - **长程调度**:决定哪些任务进入系统(批处理时代用,现代少见)。
  - **中程调度**:挂起/换入,配合 [[虚拟内存与分页]] 与 swap。
  - **短程调度**:CPU 调度,毫秒级决策。
- **经典算法**
  - **FCFS / SJF**:先到先服务、最短作业优先;教科书基础。
  - **轮转(Round-Robin)**:固定时间片轮换,公平但不分轻重。
  - **多级反馈队列(MLFQ)**:多优先级队列,任务行为决定升降级,Solaris/Mac OS 经典。
  - **CFS(Completely Fair Scheduler)**:Linux 2.6.23 起主流算法,用红黑树按虚拟运行时间排序,逼近"理想多任务公平"。
  - **EDF(Earliest Deadline First)** / **Rate Monotonic**:实时系统硬性截止时间。
- **抢占 vs 协作**
  - 现代 OS 都是抢占式——时钟中断或更高优先级唤醒就切换。
  - 协作式仅在用户态线程库或早期系统(Mac OS Classic)出现。
- **优先级与 nice 值**
  - Linux nice 范围 -20(高)到 19(低);实时优先级 1-99 用 SCHED_FIFO/SCHED_RR。
  - 优先级反转:低优先级持锁、高优先级等待——优先级继承(POSIX threads)解决。
- **多核调度**
  - 每 CPU 各自就绪队列,Work-Stealing 平衡。
  - **CPU 亲和性(Affinity)**:把任务绑核可减少缓存失效;`taskset`、cgroup cpuset。
  - **NUMA 感知**:任务尽量跑在数据所在节点。
- **CFS 关键概念**
  - **vruntime**:虚拟运行时间,按 nice 加权;调度器选 vruntime 最小的就绪任务。
  - **调度域 / 组**:层次结构匹配 NUMA + SMT 拓扑。
- **新趋势**:EAS(Energy-Aware Scheduling,移动端节能)、Per-Task Util(更精细的负载追踪)、io_uring 与调度耦合。

## 关系

- 是 [[操作系统]] 与 [[进程与线程]] 之间的调度层。
- [[Python GIL]]、[[Java JVM]] 线程模型上叠加 OS 调度形成两级调度。
- [[Go goroutine与channel]] 在用户态做 GMP 调度,把 OS 调度抽象成更轻量的 goroutine 调度。
- [[内核态与用户态]] 切换是调度发生的物理时机。
- 与 [[虚拟内存与分页]] 联动——调度切换可能引发 TLB 失效与 cache pollution。
