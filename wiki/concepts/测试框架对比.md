# 测试框架对比

## 定义

测试框架是为开发者编写、组织、执行测试代码提供的基础设施,涵盖断言库、Mock 工具、测试运行器、报告生成等组件。不同语言、不同测试金字塔层级有各自的领跑框架,选型核心考虑:**生态、速度、调试体验、并行能力**。

[[单元测试金字塔|测试金字塔]]三层:
- **单元测试(Unit)**:函数级,快、量大
- **集成测试(Integration)**:多模块协作
- **E2E 测试(End-to-End)**:浏览器或 API 级用户场景

## JavaScript/TypeScript

**Jest(Facebook,2014)**

- [[React]] 默认测试框架
- 内置 Mock、断言、覆盖率
- 自动并行
- 易用 vs 速度:单元测试快,但启动开销大,集成测试慢
- TS 集成需 ts-jest 或 babel-jest
- snapshot 测试经典

详见 [[Jest与Vitest]]。

**Vitest(2021,基于 Vite)**

- 与 [[Vite]] 共享构建管线,极快
- API 与 Jest 兼容,可低成本迁移
- ESM 原生支持
- 类型友好(TS)
- 现代前端首选

**Mocha + Chai + Sinon**

- 最老牌(2011),还在维护
- 模块化:Mocha 跑测试、Chai 断言、Sinon Mock
- 灵活但需自配
- 老项目仍多

**Cypress**

- 主打 E2E 测试,2017 年
- 在浏览器内跑测试代码,无 [[Selenium]] 服务依赖
- 时间旅行调试:每步截图
- API 友好,新手易上手
- 局限:仅 Chromium、不能多 tab、不能跨域(后续支持改善)

**Playwright(微软,2020)**

- 跨浏览器(Chromium、Firefox、WebKit)
- 跨语言(JS/TS、Python、Java、.NET)
- 自动等待、网络拦截、移动模拟
- 比 Cypress 更强大,挑战其领导地位
- 微软背书,2024 年前后迅速崛起

详见 [[Playwright与Cypress]]。

## Python

**[[PyTest]](2003)**

- Python 测试王者
- 强大 fixture 系统([[依赖注入与控制反转|依赖注入]]测试上下文)
- 简单断言(纯 assert)
- 海量插件:pytest-django、pytest-asyncio、pytest-cov、pytest-xdist(并行)
- 标准
  
**unittest(标准库)**

- Python 内置,JUnit 风格(class TestCase + setUp/tearDown)
- 老式 OOP 风格,配合 pytest 也能跑
- 仅在不能装第三方库时用

**pytest-bdd / behave**

- [[BDD行为驱动开发|BDD]] 风格(Given/When/Then)
- 业务相关测试

## Java

**JUnit**

- Java 测试事实标准
- JUnit 5(Jupiter)是当代主流,2017 年发布
- 注解驱动:@Test、@BeforeEach、@AfterEach
- 参数化测试、动态测试
- 与 Maven/Gradle 紧集成
- IDE 完美支持

**TestNG**

- 与 JUnit 类似,但更强大(并行、依赖、测试组)
- Spring 项目部分用
- 但生态不如 JUnit

**Mockito**

- Java Mock 框架
- when().thenReturn()、verify() API 直观
- 与 JUnit 配套使用

**AssertJ**

- 流畅断言:assertThat(x).isNotNull().contains(...)
- 比 JUnit 自带断言更可读

## Go

**testing(标准库)**

- Go 内置,极简
- TestXxx() 函数 + t.Errorf
- 表驱动测试惯例

**testify**

- 第三方,提供 assert/require 风格断言
- 与 testing 互补

## Rust

**内置 #[test]**

- 与 cargo 集成
- 简单直观
- assert!、assert_eq!、assert_ne! 宏

**criterion**

- 性能基准测试

## .NET

**xUnit**(主流,新项目首选)
**NUnit**(经典)
**MSTest**(微软,与 Visual Studio 紧集成)

## 端到端测试专门

**Cypress**(JS,E2E 王者历史,被 Playwright 挑战)
**Playwright**(JS/Python/Java/.NET,跨浏览器)
**Selenium**(老牌,语言无关,仍主流)
**Puppeteer**(Google,Chromium only)

## API 测试

**Postman / Newman**(可视化 + CLI)
**REST Assured**(Java)
**Supertest**(Node.js)
**httpx + pytest**(Python)

## 移动端

**iOS:XCTest**(原生)、**XCUITest**(UI)
**Android:JUnit + Espresso**
**跨平台:Appium**(Selenium 移动版)、**Detox**(React Native)

## 性能测试

**JMeter**(Java,GUI/CLI)
**k6**(Go,JS 脚本,云原生友好)
**Gatling**(Scala/Java DSL)
**Locust**(Python,可写脚本)

## 实践原则

**1. [[单元测试金字塔|测试金字塔]]**

- 大量单元测试(快、廉价、易写)
- 适量集成测试(覆盖关键路径)
- 少量 E2E(代价高但贴近用户)

**2. 速度优先**

- 单元测试 < 1 秒/个
- 集成测试 < 1 分钟整套
- E2E < 30 分钟整套

**3. 失败快(Fail Fast)**

- 失败一个立即停 vs 全跑完看哪些失败:看场景

**4. 测试金字塔颠倒**

- 错误模式:全 E2E,单元少
- 结果:慢、易抖动、定位难

**5. 并行执行**

- 大多数框架支持并行(pytest-xdist、Jest --maxWorkers、JUnit 5 parallel)
- 注意共享资源(数据库、文件)隔离

**6. [[CI_CD流水线|CI]] 集成**

- 每 PR 跑测试
- 覆盖率门槛(典型 80%)
- 性能基准

## 选择决策

| 场景 | 推荐 |
|---|---|
| React/Vue 单元 | Vitest |
| Node 后端单元 | Vitest 或 Jest |
| Python | PyTest |
| Java | JUnit 5 + Mockito |
| Go | 标准库 + testify |
| Rust | 内置 |
| 跨浏览器 E2E | Playwright |
| 简单 E2E | Cypress |
| 性能 | k6 / Gatling |
