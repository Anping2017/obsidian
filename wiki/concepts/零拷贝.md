# 零拷贝

## 定义

**零拷贝(Zero-Copy)** 是一组减少或消除"用户空间-内核空间"数据拷贝次数的 I/O 优化技术,目标是让数据在内核内直接从源(磁盘、Socket)流到目的,无需 CPU 参与冗余复制,把吞吐与延迟逼近硬件极限。

## 核心要点

- **传统 read+write 的代价**
  - 4 次上下文切换、4 次内存拷贝(磁盘 → 内核 page cache → 用户缓冲区 → 内核 socket buffer → 网卡)。
  - 大文件传输 CPU 用在 memcpy 而非业务。
- **常见技术**
  - **`mmap` + write**:把文件映射到用户空间共享 page cache,省一次拷贝;仍需用户态写 socket。
  - **`sendfile`**:Linux 2.1 引入,文件直接从 page cache 写到 socket buffer,省两次拷贝、两次切换;2.4 起加 SG-DMA,可只在 socket buffer 留描述符,真正零拷贝。
  - **`splice` / `tee` / `vmsplice`**:管道作为内核内桥梁,fd 之间零拷贝转发。
  - **`io_uring`**:零系统调用 + 零拷贝的现代异步 I/O。
- **应用层零拷贝**
  - **DirectByteBuffer**(Java NIO):直接堆外内存,绕过 JVM 堆。
  - **transferTo / transferFrom**:Java NIO FileChannel 调用 sendfile。
  - **Netty FileRegion**:Netty 对底层零拷贝的封装。
  - **Kafka**:用 sendfile 把 page cache 数据直接推到 Socket,实现高吞吐。
- **DPDK / 内核旁路(Kernel Bypass)**
  - 用户态直接操作网卡,完全绕过内核协议栈,延迟微秒级。
  - 代价:失去内核协议栈灵活性,需要专门的应用与运维。
- **RDMA**:网卡直接读写远程内存,跨主机的"零拷贝",HPC 与高性能存储核心。

## 关系

- 是 [[I/O模型]] 与 [[Epoll与Kqueue]] 之上的进一步优化层。
- 与 [[虚拟内存与分页]] 联动——mmap 与 page cache 都建立在分页机制上。
- [[消息队列]] 系统(Kafka)、文件分发服务(NGINX 静态资源)是零拷贝主要受益者。
- 与 [[操作系统]] 内核版本强绑定——不同 Linux 版本支持的零拷贝接口不同。
- [[DPDK与内核旁路]] 把零拷贝推到极端——从"内核内零拷贝"升级为"绕过内核"。
