# 缓存 Cache

## 定义

**缓存(Cache)**是**临时存储热点数据**的中间层,位于"慢但大"的源头与"快但小"的访问者之间。其核心是**局部性原理**:
- **时间局部性**:刚访问过的数据很快还会用
- **空间局部性**:访问 a[i] 后大概率访问 a[i+1]

缓存是性能优化的最普适武器,从 CPU 缓存到 CDN,贯穿计算机系统每一层。

## 核心要点

### 多层级缓存(典型 Web 系统)

```
浏览器缓存 → CDN → Nginx 反向代理缓存 → 应用本地缓存(Caffeine/Guava) → 分布式缓存(Redis) → 数据库
```

每一层延迟相差 1-2 个数量级,层数越靠前命中越好。

### 经典淘汰策略

容量满时如何驱逐:
- **LRU (Least Recently Used)**:淘汰最久未访问。Hash表 + 双向链表 O(1) 实现
- **LFU (Least Frequently Used)**:淘汰访问次数最少。需要计数与抗"突发热点"的衰减
- **FIFO**:先进先出
- **Random**:随机
- **TinyLFU + W-TinyLFU**(Caffeine):用 Sketch 估计频率 + 时间窗口,接近最优
- **TTL 过期**:不淘汰只过期

实测 LRU 对扫描型工作负载差(扫一遍把热点冲掉);LFU/TinyLFU 抗扫描更好。

### 缓存更新策略

- **Cache-Aside(旁路)**:读未命中时应用从 DB 读后写缓存。最常见模式
- **Read-Through**:缓存层自己负责加载
- **Write-Through**:写缓存时同步写 DB
- **Write-Behind/Back**:先写缓存,异步刷 DB(高吞吐,有丢失风险)

### 三大缓存难题

1. **缓存击穿**:某热点 key 失效瞬间大量请求穿透到 DB → 用互斥锁、永不过期、双层缓存
2. **缓存穿透**:大量请求查不存在的 key → DB 也查不到 → 用布隆过滤器、缓存空值
3. **缓存雪崩**:大量 key 同时过期 → DB 被打挂 → 用过期时间加随机抖动、多级缓存、熔断

### 浏览器与 HTTP 缓存

见[[HTTP协议]]:Cache-Control、ETag、Last-Modified。强缓存与协商缓存。CDN 缓存利用相同语义。

### CPU 缓存(L1/L2/L3)

- L1:32-64 KB 每核,几纳秒
- L2:256 KB - 1 MB 每核
- L3:几 MB 多核共享
- 主存:几十 GB,几十 ns

**缓存行(Cache Line)**通常 64 字节。性能编程的核心:
- 数据布局连续(数组优于链表)
- 避免 False Sharing(多核写同一缓存行的不同字段)
- 利用预取(Prefetch)

### 分布式缓存:Redis / Memcached

- **Redis**:单线程 + [[事件循环]],数据结构丰富(字符串、list、hash、set、zset、stream),持久化(RDB/AOF),集群(Sentinel/Cluster)
- **Memcached**:多线程,只支持简单 KV,无持久化

Redis 还常用于:分布式锁(SET NX)、分布式限流、消息队列(Pub/Sub、Stream)、排行榜(zset)、计数器、Session 存储。

### 一致性与失效

最难的问题是"DB 改了,缓存怎么办"。常用做法:
- 先更新 DB,后失效缓存(简单常用)
- Binlog 监听(Canal、Maxwell)异步同步缓存,业务无感

### CDN(Content Delivery Network)

把静态资源(图片、JS/CSS、视频)缓存到全球边缘节点,用户就近访问。是公网级别的缓存系统。配合 HTTP 缓存头与一致性 hash 路由。

## 和其他概念的关系

缓存依赖[[Hash表]](快速查找)和[[链表]](LRU 顺序维护)。[[操作系统]]的页缓存(Page Cache)、[[数据库]]的缓冲池(Buffer Pool)、[[B+树]]的内部页缓存都是同一思想的不同实现。

[[微服务]]的可扩展性大量依赖分布式缓存做读放大。CAP/BASE 理论说明:为了高可用与扩展性,常允许缓存"轻微不一致"以换性能。

[[函数式编程]]的"记忆化(memoization)"是函数级缓存。机器学习推理服务的特征缓存、模型缓存都是同一模式。
