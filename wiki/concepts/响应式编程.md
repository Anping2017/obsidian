# 响应式编程 Reactive Programming

## 定义

**响应式编程(Reactive Programming)** 是一种声明式编程范式,把"**随时间变化的数据流**"作为核心抽象——任何事件(点击、网络响应、定时器、数据更新)都是 Stream,通过 map / filter / merge / debounce 等操作符像 SQL 一样组合处理。

源自 1970 年代电子表格(Excel:cell 改了依赖它的 cell 自动重算),2010 年代由微软的 Reactive Extensions(Rx)系统化为编程库,后扩散到 JavaScript(RxJS)、Java(Reactor / RxJava)、Swift(Combine)、.NET(Rx.NET)等几乎所有主流语言。

## 核心抽象:Observable

```javascript
const click$ = fromEvent(button, 'click')
const search$ = fromEvent(input, 'input').pipe(
  map(e => e.target.value),
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(query => fetchSuggestions(query))
)
search$.subscribe(suggestions => render(suggestions))
```

短短几行,实现了:
- 监听输入框
- 取每次输入值
- 防抖 300ms
- 去重(连续相同值不发)
- 切换最新请求(取消上次)
- 渲染建议

命令式实现需 30+ 行,易错。

## 关键概念

**1. Observable**

可订阅的数据源,产生 0+ 个值,可结束(complete)或出错(error)。

**2. Observer / Subscription**

```typescript
observable$.subscribe({
  next: value => console.log(value),
  error: err => console.error(err),
  complete: () => console.log('done')
})
```

**3. Operators(操作符)**

链式组合,关键家族:

- **创建**:of、from、interval、fromEvent、ajax
- **变换**:map、scan、buffer、window、partition
- **过滤**:filter、distinct、debounce、throttle、take、skip
- **组合**:merge、concat、combineLatest、zip、forkJoin
- **错误处理**:catchError、retry、retryWhen
- **多播**:share、shareReplay、publish
- **高阶**:switchMap、mergeMap、concatMap、exhaustMap

**4. Hot vs Cold**

- **Cold Observable**:每个订阅者独立(从头开始)。如 from(promise) 每次都重发请求。
- **Hot Observable**:多订阅者共享(实时事件)。如 fromEvent(click)。

理解差异是 RxJS 中级阶梯。

**5. Subject**

既是 Observable 也是 Observer——可以 next() 推送值,又可被订阅。常用作事件总线。

## 经典操作符讲解

**switchMap vs mergeMap vs concatMap**

处理"对每个值开新流"时:

- **switchMap**:取最新值,丢弃前面未完成。**典型:搜索建议**(只关心最新输入)
- **mergeMap**:并发所有,顺序不定。典型:无依赖请求并发
- **concatMap**:排队顺序执行,前一完成再下一个。典型:严格顺序的 IO
- **exhaustMap**:正在处理时丢弃新值。典型:防止重复点击提交

**combineLatest vs zip vs withLatestFrom**

合并多个流:

- **combineLatest**:每个流任一更新,组合最新值发出
- **zip**:按位配对(等所有流都到第 N 个)
- **withLatestFrom**:主流发出时,带上其他流的最新值

## 响应式 vs Promise

**Promise**

```javascript
fetch('/api').then(r => r.json()).then(data => render(data))
```

- 一次性
- 单值
- 不可取消
- 简单异步

**Observable**

```javascript
fromFetch('/api').pipe(
  switchMap(r => from(r.json()))
).subscribe(data => render(data))
```

- 可发多个值
- 可取消(unsubscribe)
- 操作符丰富
- 时间维度操作

**何时用什么**

- 单次异步:Promise / async-await(简单)
- 流(WebSocket、SSE):Observable
- 复杂用户交互(搜索、自动保存):Observable
- 简单调用链:Promise

## RxJS 在前端

**应用层**

- 表单值流(react-hook-form 部分)
- 搜索建议、自动保存
- 复杂交互(拖拽、长按、多指)
- WebSocket、SSE 数据流

**Angular**

把 RxJS 作为内置依赖——HttpClient、Forms、Router 全用 Observable。Angular 应用 = 大量 RxJS。

**React**

不强制,但 RxJS 可以与 React 配合(useObservable)。React 的 hooks(useState、useEffect、useReducer)解决了大部分场景,RxJS 用于复杂事件流。

**Vue**

类似 React,vueuse 提供 useObservable。

## Reactor / RxJava(后端)

**Project Reactor(Spring 5+)**

```java
Flux.fromIterable(users)
    .filter(u -> u.getAge() > 18)
    .flatMap(u -> apiClient.fetchPreferences(u.getId()))
    .map(Recommendation::from)
    .reduce(new Stats(), Stats::accumulate)
    .subscribe(System.out::println);
```

[[Spring Boot]] 的 WebFlux 框架基于 Reactor,提供异步非阻塞 Web 处理。在高并发(C10K+)场景下,Reactor 比 Spring MVC 同步线程池更高效。

**RxJava**

老牌响应式 Java 库,2.0 起符合 Reactive Streams 规范。Android 早期(2014-2018)RxJava 是异步主流,后被 Kotlin Coroutines 蚕食。

## Reactive Streams 规范

2015 年标准化的 JVM 响应式接口:
- Publisher / Subscriber / Subscription / Processor
- 背压(Backpressure):订阅者控制接收速率
- Reactor、RxJava、Akka Streams 都实现该接口

背压是与传统 Push 模型的关键区别——慢消费者可向上游"喘气":"我现在只能处理 10 个,先别推那么快"。

## SwiftUI Combine

Apple 在 2019 年推出 Combine 框架,与 [[SwiftUI与UIKit|SwiftUI]] 并行:

```swift
URLSession.shared.dataTaskPublisher(for: url)
    .map { $0.data }
    .decode(type: User.self, decoder: JSONDecoder())
    .receive(on: DispatchQueue.main)
    .sink(receiveCompletion: { ... }, receiveValue: { user in ... })
```

Combine 在 [[SwiftUI与UIKit|SwiftUI]] 内部驱动,与 @Published 属性配合实现状态自动 UI 更新。

## 响应式微服务架构

不仅是编程,也是架构哲学(《Reactive Manifesto》2014):
- **Responsive**:及时响应
- **Resilient**:故障隔离
- **Elastic**:弹性伸缩
- **Message-Driven**:消息驱动

[[微服务]] + [[消息队列]] + [[事件溯源]] + Reactor 等工具构成"响应式系统"。

## 学习曲线挑战

- **思维转变**:从"步骤"到"流",难
- **操作符多**:RxJS 100+ 操作符,知道何时用哪个需经验
- **调试**:链中 5 步出错,定位难(RxJS DevTools 部分缓解)
- **过度使用**:简单异步用 RxJS = 杀鸡用牛刀
- **内存泄漏**:不 unsubscribe 导致流积累

## 反模式

**1. Subject 泛滥**

什么场景都用 Subject 作总线 → 难追踪谁推谁订。优先 Observable 链。

**2. 嵌套 subscribe**

```javascript
a$.subscribe(a => b$.subscribe(b => ...))  // 反模式
a$.pipe(switchMap(a => b$)).subscribe(...)  // 正确
```

**3. 不取消订阅**

组件卸载时不 unsubscribe,内存泄漏。
- 用 takeUntil(destroy$) 模式
- 或 React useEffect cleanup
- 或 Angular AsyncPipe(自动管理)

**4. 把 Promise 包成 Observable 又 await**

```javascript
const value = await firstValueFrom(observable$)  // 偶尔 OK
```

但若处处 await,失去响应式价值。

## 局限

- 学习曲线陡
- 团队培训成本
- 简单问题被复杂化
- 与 async/await 范式冲突
- 调试链难
- 不是所有问题都适合"流"模型

## 现代趋势

**JavaScript/TypeScript**

- async/await 处理 80% 异步
- React Hooks(useState、useReducer、useEffect)解决组件级状态
- TanStack Query / SWR 处理数据获取(内部某种程度像响应式)
- RxJS 用于复杂场景(实时数据、复杂用户交互)

**Java**

- Kotlin Coroutines + Flow 蚕食 RxJava 份额
- Reactor 在 WebFlux / Spring Cloud Stream 仍主流

**Swift**

- Async/await(Swift 5.5+)替代部分 Combine 用法
- Combine 仍是 SwiftUI 内核

整体趋势:**Coroutines / async-await 处理简单异步,响应式留给真正的"流"场景**。

## 和其他概念的关系

响应式编程是 [[编程范式]] 重要分支,与函数式编程深度契合(纯函数、不可变、组合)。它的"数据流"思想是 [[Apache Spark]] / [[Apache Kafka|Kafka]] Streams 等大数据流处理的概念基础。

它与 [[微服务]] / [[服务网格]] 结合产生"响应式微服务"哲学——异步消息驱动 + 弹性 + 可观测。Reactor、Akka Streams 等是该架构的实现工具。

它的操作符组合思想与 [[设计模式]] 中的责任链、装饰器、观察者深度同构,是"GoF 模式"在数据流领域的现代化呈现。
