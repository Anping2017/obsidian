# 批处理

## 定义

**批处理(Batch Processing)** 是对**有界、静态**的数据集进行大规模并行计算的范式。相对 [[流处理]](无界、实时),批处理延迟高(分钟到小时)但吞吐巨大,适合定时报表、ETL、离线训练等场景。MapReduce 是开山之作,Spark 是现代代表,Flink 在批流统一上做了延伸。

## 核心要点

- **批处理 vs 流处理**

| 维度 | 批处理 | 流处理 |
|---|---|---|
| 数据 | 有界、静态 | 无界、动态 |
| 延迟 | 分钟-小时 | 秒-毫秒 |
| 吞吐 | 极高 | 中-高 |
| 状态 | 重新计算 | 持续更新 |
| 用途 | T+1 报表、训练 | 实时监控、风控 |
| 代表 | Hadoop、Spark | Flink、Kafka Streams |

- **MapReduce(Google 2004)**
  - **Map**:数据切片,每片并行执行映射函数,输出 (key, value)
  - **Shuffle**:相同 key 的数据汇总到同一节点
  - **Reduce**:每 key 的 values 聚合得最终结果
  - **优势**:简单模型,易并行,容错(任务挂了重跑)
  - **劣势**:中间结果落盘慢,只支持单轮 MR,复杂任务要多轮串接
  - **实现**:Hadoop MapReduce、Disco、CouchDB
- **Apache Spark**
  - 2009 年伯克利诞生,2010 年开源
  - **核心抽象 RDD(Resilient Distributed Dataset)**:不可变分区的数据集合,血缘(lineage)记录依赖关系,失败时重算
  - **DAG 调度**:把多步操作组合为有向无环图,优化执行顺序
  - **内存计算**:中间结果存内存,比 MR 快 10-100 倍
  - **统一 API**:批 + 流(Structured Streaming)+ ML(MLlib)+ 图(GraphX)+ SQL
  - **生态**:Hadoop / S3 / Hive / Iceberg / Delta Lake 全兼容
  - 是当前批处理事实标准
- **Apache Flink**
  - 流为第一公民,批是流的特例(有界流)
  - 真正实现"批流统一",同 API、同引擎
  - 见 [[流处理]]
- **批处理流水线常见架构**
  - **数据源**:S3 / HDFS / Hive / 数据库 CDC
  - **调度**:Airflow / Prefect / Dagster / Azkaban,定时触发
  - **计算引擎**:Spark / Flink / Trino / Hive
  - **输出**:[[数据仓库]] / 数据湖 / 业务数据库
- **MPP(Massively Parallel Processing)**
  - 与 MR / Spark 不同的批处理范式
  - 多个节点的 SQL 引擎共享元数据,任务由优化器全局规划
  - 内存中流水线执行,中间结果不落盘
  - **代表**:Presto / Trino、Greenplum、ClickHouse、Doris、StarRocks
  - 速度比 Spark SQL 快(交互式),但容错弱(节点挂了整任务挂)
  - 见 [[数据仓库]]
- **批处理的实践要点**
  - **幂等性**:任务可重跑、不重复处理(基于水印 / 分区)
  - **小文件问题**:HDFS / S3 上大量小文件影响性能,需合并
  - **数据倾斜**:某个 key 数据量极大导致单 reducer 慢,需 salting 或加 combiner
  - **故障恢复**:单任务失败重试,DAG 中断从检查点恢复
- **典型应用**
  - **ETL/ELT**:把业务库 CDC 数据加载到数仓
  - **离线报表**:T+1 业务指标计算
  - **机器学习训练**:大规模特征工程 + 模型训练
  - **数据回填**:历史数据补算
- **批处理的演进**
  - 初代 MapReduce(2004) → Spark(2009) → Flink 批流统一(2015) → 批流融合 + Lakehouse(2020+)
  - 现代趋势:**Delta Lake / Iceberg / Hudi** 在数据湖上加 ACID,使批处理 + 实时增量更新一体化

## 和其他概念的关系

批处理与 [[流处理]] 是大数据计算的两大范式,[[Lambda架构]] 用批 + 流并行融合,Kappa 架构主张全流处理替代批。

批处理是 [[数据仓库]] 与 [[ETL与ELT]] 的核心引擎。Spark / Hive 是把数据从 OLTP 搬到 OLAP 的主力。

底层依赖分布式存储(HDFS / S3 / 列式格式见 [[列式存储]])与分布式调度(YARN / K8s)。Spark/Flink 都能跑在 [[Kubernetes]] 上。

[[查询优化器]] 在 Spark Catalyst、Trino Optimizer 中是批处理性能的关键。

[[微服务]] 中"异步任务"用批处理实现:消息队列堆积一段后批量处理,见 [[消息队列]]。
