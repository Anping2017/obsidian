# 编程范式 Programming Paradigm

## 定义

**编程范式(Programming Paradigm)**是组织和构思程序的基本方式 —— 决定"程序是什么"以及"如何思考问题"。它体现在语言的语法、库、思维习惯上。

主要分两大阵营:
- **命令式(Imperative)**:告诉机器"怎么做"(一步步指令)
- **声明式(Declarative)**:告诉机器"做什么"(目标),细节由实现负责

## 核心要点

### 主要范式速览

| 范式 | 核心 | 代表语言 |
|---|---|---|
| 面向过程 | 函数 + 数据 | C、Pascal、早期 JS |
| [[面向对象编程]] | 对象 + 消息 | Java、C++、Python、Ruby |
| [[函数式编程]] | 纯函数 + 不可变 | Haskell、Lisp、Erlang、Scala |
| 逻辑式 | 事实 + 规则 + 推理 | Prolog、Datalog |
| 声明式查询 | 描述结果 | SQL、GraphQL |
| 响应式 | 数据流 + 自动传播 | RxJS、Elm、Svelte |
| 元编程 | 代码生成代码 | Lisp 宏、Ruby、Rust 宏 |
| 并发范式 | Actor / CSP / STM | Erlang、Go、Clojure |

### 命令式 vs 声明式

```sql
-- 声明式 SQL:说"我要这个结果"
SELECT name FROM users WHERE age > 18;
```

```python
# 命令式 Python:一步步告诉怎么做
result = []
for u in users:
    if u.age > 18:
        result.append(u.name)
```

声明式抽象层次更高、更易并行/优化,但需要好的运行时(SQL 查询优化器、React 虚拟 DOM)支撑。

### 面向过程

最古老,以函数为基本单元,数据共享或通过参数传递。简单直接,适合小程序、系统编程。Linux 内核、libc、嵌入式仍是主战场。

### [[面向对象编程]]

把数据和行为捆绑为对象。封装、继承、多态、抽象。Java、C++、C# 主导工业代码三十年。
近年批评:继承层次脆弱、过度抽象、并发困难。趋势:组合优于继承、不变数据、与 FP 融合。

### [[函数式编程]]

数学函数为中心,无副作用、不可变。优势:可推理、可并行、可缓存。Haskell 是纯 FP;Erlang 用 FP + Actor 模型支撑高并发(WhatsApp 用 Erlang 单服 200 万连接)。

### 逻辑式

只描述事实和规则,运行时通过统一+回溯求解。Prolog 经典:`father(X, tom)` 推理 X。
现代变种 Datalog 在数据库、静态分析(Soufflé)中复活。

### 响应式 / 数据流

把"值随时间变化"作为一等公民。值 = Stream / Observable。修改源自动传播到下游。
- 前端:RxJS、Vue 的响应性、Svelte 编译时的依赖追踪
- 后端:Reactor、RxJava、Project Reactor(Spring WebFlux)

### 元编程

代码即数据,代码生成代码。
- Lisp 宏:同形性,代码就是 list
- Ruby:method_missing、define_method
- C++ 模板元编程:编译期计算
- Rust 宏:声明式 + 过程宏
- Python 装饰器、元类

### 多范式融合

近 20 年趋势:语言不再"纯"。
- Python、JS:OOP + FP + 命令式
- Scala、Kotlin:OOP + FP 显式融合
- Rust:命令式 + FP + 系统编程,无继承
- C++ 现代版(C++20+):lambda、ranges、concepts 大量 FP 化

工程师选择范式的真实依据:
- 团队熟悉度
- 生态库
- 性能需求
- 维护周期长短
- 问题域契合度

### 不同范式的擅长领域

| 范式 | 擅长 |
|---|---|
| 面向过程 | OS、嵌入式、性能极致 |
| OOP | 大型企业应用、UI 框架 |
| FP | 并发、数据流水、可证明的金融/医疗逻辑 |
| 逻辑式 | 知识推理、规则引擎 |
| 声明式 SQL | 数据查询 |
| 响应式 | UI、流数据 |
| Actor | 高并发、分布式 |

## 和其他概念的关系

[[面向对象编程]]、[[函数式编程]]、[[闭包]]、[[递归]]都是编程范式的具体技术或表现。[[设计模式]]生于 OOP,在 FP 中部分模式"消失"或退化。[[设计原则SOLID]]是 OOP 的伦理。

[[并发与并行]]模型(线程、协程、Actor、CSP)其实是不同并发范式。[[数据库]]查询语言是声明式最成功的工业落地。GraphQL 把声明式带到 API 层。

掌握多范式让程序员根据问题选最合适工具,避免"金锤子"陷阱。Linux 内核精于过程式,React/Redux 倚重 FP 思想,Erlang 把 Actor 推到极致 —— 没有"最好的范式",只有"最合适的范式"。
