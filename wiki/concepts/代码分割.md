# 代码分割

## 定义

**代码分割(Code Splitting)** 是把单一 JavaScript bundle 切分成多个**按需加载的 chunk** 的优化技术。目标:首屏只加载关键代码,其他代码在用户真正需要时(路由切换、交互触发)再请求。是 [[Core Web Vitals]] LCP/FID 优化的核心手段。

## 核心要点

### 1. 三种分割维度

#### 入口分割(Entry)

```js
// webpack.config.js
entry: {
  main: './src/main.js',
  admin: './src/admin.js'
}
```

适合多页应用(MPA)。

#### 动态导入(Dynamic Import)

```js
button.onclick = async () => {
  const { runHeavy } = await import('./heavy.js');
  runHeavy();
};
```

ES2020 标准,被 [[Webpack]]/[[Vite]]/[[Rollup]] 自动识别为分割点。

#### Vendor 分割

```js
// webpack
optimization: {
  splitChunks: {
    cacheGroups: {
      vendor: { test: /node_modules/, name: 'vendor', chunks: 'all' }
    }
  }
}
```

把 React、lodash 等第三方库单独打包,业务代码更新时浏览器仍用旧 vendor 缓存。

### 2. 框架级路由分割

#### React + React Router

```jsx
import { lazy, Suspense } from 'react';
const Admin = lazy(() => import('./pages/Admin'));

<Suspense fallback={<Loading/>}>
  <Admin />
</Suspense>
```

#### Vue Router

```js
const routes = [
  { path: '/admin', component: () => import('./Admin.vue') }
];
```

### 3. 与 Tree Shaking 协同

[[Tree Shaking]] 删除死代码,代码分割按需加载活代码,二者结合让首屏 bundle 最小化。

### 4. 预加载(Preload)与预取(Prefetch)

```html
<link rel="preload" href="critical.js" as="script">  <!-- 当前页关键 -->
<link rel="prefetch" href="next-page.js" as="script"> <!-- 未来可能用 -->
```

Webpack 注释魔法:

```js
import(/* webpackPrefetch: true */ './next');
import(/* webpackPreload: true */ './critical');
```

### 5. 粒度权衡

| 粒度 | 优 | 劣 |
|---|---|---|
| 太粗(整个 vendor 一块) | 缓存好 | 首屏大 |
| 适中(按路由 + 大库分块) | 平衡 | 配置复杂 |
| 太细(每模块一 chunk) | 首屏小 | HTTP 请求过多(HTTP/1) |

[[HTTP2协议]] 多路复用让小请求成本降低,粒度可更细。

### 6. 服务器端代码分割

[[SSR]]/RSC 时代,React Server Components 让某些组件**只在服务器跑**,客户端零字节。这是终极代码分割。

### 7. 渐进增强(Progressive Hydration)

页面 SSR 后,水合(hydration)按优先级分块进行,避免一次性激活所有组件造成 [[Core Web Vitals]] FID/INP 飙升。React 18 的 Selective Hydration、Astro Islands 都实现了这一思路。

### 8. 度量

- Performance API:`performance.getEntriesByType('resource')`
- Lighthouse:Coverage 面板看未用 JS%
- Webpack Bundle Analyzer
