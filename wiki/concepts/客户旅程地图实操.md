# 客户旅程地图实操

## 定义

客户旅程地图实操(Customer Journey Map Implementation)是把抽象的"客户旅程"视觉化、表格化、数据化的工程实践。区别于 [[用户旅程地图]] 的概念定义,本概念聚焦于"如何真正落地一份能驱动决策的旅程地图"——核心是六行结构(阶段、触点、行为、思考、情绪、机会)、数据驱动的实证、跨部门协同的工作坊方法、地图后的行动闭环。本概念是 [[用户旅程地图]] / [[客户旅程分析]] 的实操延伸。

## 经典六行结构

| 行 | 内容 | 数据来源 |
|---|---|---|
| **阶段** | Awareness / Consideration / Decision / Onboarding / Use / Advocacy | 行业模型 + 业务实际 |
| **触点** | 该阶段用户接触的渠道/媒介(广告/官网/客服/产品/邮件) | 渠道分析 |
| **行为** | 用户在该触点做什么(搜索、阅读、试用、购买) | 用户行为数据 + 访谈 |
| **思考** | 该行为时的认知与判断("这个值不值"、"安全吗") | 用户访谈、客服记录 |
| **情绪** | 该阶段的情绪曲线(高兴/犹豫/焦虑/失望) | 访谈、NPS、评论 |
| **机会** | 品牌可以为客户解决什么问题 | 工作坊产出 |

## 五步实操流程

### Step 1:范围与目标确定

- **目标客户**:定位 1-2 个核心 [[用户画像]]
- **业务问题**:旅程地图要解答什么(转化漏斗哪里漏?复购率为何低?客服压力为何大?)
- **范围**:全旅程 vs 关键阶段(如只聚焦"考虑→决策")
- **产出形式**:墙面海报 vs 数字白板 vs 内部 Wiki

### Step 2:数据采集

#### 行为数据(可观测)

- GA/友盟:阶段流量、转化率、停留
- CRM:客户进件、跟进、签约时间
- 客服:工单类目、Top 问题、转人工率
- 销售:沟通节点、决策周期

#### 思考与情绪数据(需挖掘)

- **用户访谈**:8-15 位代表性用户,半结构化,聚焦"那个时刻你在想什么"
- **客服与销售一线收集**:每天记录 5 个用户原话
- **NPS + 评论**:负面评论的时间点对应旅程阶段
- **录像/Heatmap**:Hotjar、Microsoft Clarity 看真实使用过程

### Step 3:跨部门工作坊

- **参与方**:营销、产品、销售、客服、运营、数据,各部门 1-2 人
- **形式**:半天到一天,白板/Miro
- **流程**:
  1. 主持人介绍范围与目标
  2. 各方分享自己掌握的旅程片段
  3. 共同绘制 6 行表
  4. 标注"关键触点"与"痛点"
  5. 头脑风暴"机会点"
  6. 优先级排序
- **产出**:一张共识旅程地图 + 5-10 个待跟进机会点

### Step 4:验证与精化

- 把地图发给被访谈用户审核,问"这是你的真实经历吗"
- 让一线员工(销售/客服)修正不准确的地方
- 添加数据:每个阶段的实际转化率、停留时长、流失率

### Step 5:行动闭环

- 把地图机会点变成可执行项目(OKR/Sprint)
- 每季度复盘地图,数据更新,机会闭合
- 大变化(产品迭代、新渠道)后重做相关阶段

## 经典阶段模型

### B2C 电商(线性短)

Awareness → Consideration → Purchase → Delivery → Use → Repeat

### B2B SaaS(长复杂)

Problem Aware → Solution Aware → Vendor Comparison → Trial → Procurement → Onboarding → Adoption → Expansion → Renewal → Advocacy

### 服务业(高接触)

Search → Inquiry → Consultation → Decision → Service Delivery → Follow-Up → Loyalty

### 手机零售(线下+线上混合)

线下:广告认知 → 进店 → 看机 → 比较 → 询价 → 决策 → 离店 → 售后 → 换机
线上:搜索 → 内容种草 → 评测对比 → 下单 → 物流 → 体验 → 评论 → 复购

## 实操陷阱

### 1. 完美主义陷阱

- 试图覆盖所有边缘 case,旅程图过于复杂
- 解药:聚焦 80% 主流路径,剩余作为"分支"

### 2. 部门墙陷阱

- 各部门只画"自己负责的部分",拼起来后有断层
- 解药:跨部门工作坊,强迫全员看完整旅程

### 3. 数据缺失陷阱

- 思考与情绪行只能"猜",不基于真实访谈
- 解药:工作坊前必须做用户访谈,带原话进会议

### 4. 地图变摆设

- 画完贴墙上,无人跟进
- 解药:产出"机会清单"与具体责任人,每月跟进

### 5. 静态化

- 一画就是几年不更新
- 解药:季度复盘,产品/市场大变后立即更新

## 与其他工具的协同

### 与 [[转化漏斗]]

- 漏斗是单维度纵向,旅程图是多维度立体
- 旅程地图可看出漏斗每一层"为什么漏"

### 与 [[用户画像]]

- 不同画像有不同旅程
- 实操时优先做 1-2 个核心画像的旅程,再迭代其他

### 与 [[NPS净推荐值|NPS]]、[[CRM客户关系管理]]、[[CDP客户数据平台]]

- 数据基础设施
- 客户分群对应不同旅程

### 与 [[全渠道营销]]

- 旅程地图是全渠道设计的"地图"
- 全渠道是旅程地图的实施

## 与其他概念的关系

- 与 [[用户旅程地图]]:本概念是其工程化操作
- 与 [[客户旅程分析]]:数据分析侧

- 与 [[全渠道营销]]:实施载体
- 与 [[NPS净推荐值|NPS]]:情绪数据的量化
