# 反向代理

## 定义

**反向代理(Reverse Proxy)** 是部署在服务端的代理服务器,代表后端服务接收外部请求并转发,客户端只看到代理而不知道真实后端。与"正向代理(Forward Proxy)"代表客户端访问外部服务相反,反向代理是 Web 架构入口的标准组件,提供负载均衡、SSL 卸载、缓存、安全防护等能力。

## 核心要点

- **正向 vs 反向**

| 维度 | 正向代理 | 反向代理 |
|---|---|---|
| 代理对象 | 客户端 | 服务端 |
| 隐藏方 | 客户端身份 | 服务端结构 |
| 部署 | 客户端网络出口 | 服务端入口 |
| 典型 | VPN / 翻墙 / 公司出网 | Nginx / API Gateway |
| 客户端感知 | 知道用了代理 | 不知道有代理 |

- **核心能力**
  - **负载均衡**:把流量分到多后端,见 [[负载均衡]]
  - **SSL 卸载(Termination)**:处理 HTTPS 解密,后端走 HTTP,见 [[TLS]]
  - **缓存**:静态资源 / API 响应缓存
  - **限流**:见 [[限流]]
  - **请求 / 响应改写**:增删 Header、URL 重写、压缩
  - **安全过滤**:WAF、IP 黑名单、恶意请求拦截
  - **协议转换**:HTTP/1.1 ↔ HTTP/2 ↔ gRPC
  - **健康检查**:剔除不健康后端
  - **多路复用**:Keepalive / HTTP/2 Multiplex 提高吞吐
- **典型实现**
  - **Nginx**
    - 1.X 版本起广泛使用,C 实现,事件驱动,极高吞吐
    - 配置文件声明式
    - 模块丰富(Lua / NJS 扩展)
    - 适合静态 Web 服务、反向代理、L7 LB
  - **HAProxy**
    - 专注 TCP/HTTP 代理,L4/L7
    - 性能极致,多用于金融、超大流量场景
  - **Envoy**
    - 现代云原生代理,xDS 动态配置,可观测性内建
    - 是 [[服务网格]] 数据面默认
    - 也作 API Gateway / Ingress
  - **Traefik**
    - 自动服务发现(K8s Ingress / Docker Compose)
    - 配置即代码,动态路由
  - **Caddy**
    - 自动 HTTPS(内置 Let's Encrypt)
    - 配置极简
    - 轻量场景 / 个人项目
- **典型部署**
  - **入口反向代理**:Nginx 接收所有外部请求,转发到后端 Web 服务
  - **API 网关型**:见 [[API网关]],Nginx + 插件
  - **K8s Ingress**:Nginx Ingress / Traefik / HAProxy Ingress 暴露集群服务
  - **多级反向代理**:CDN → 入口 LB → API 网关 → 应用 LB → 后端
- **配置要点(Nginx 视角)**
  - **upstream**:定义后端服务器组
    ```
    upstream backend {
      server 10.0.0.1:8080;
      server 10.0.0.2:8080 weight=2;
    }
    ```
  - **proxy_pass**:转发到 upstream
  - **proxy_set_header**:传递真实 IP / Host(Host / X-Forwarded-For / X-Real-IP)
  - **超时**:proxy_connect_timeout / proxy_read_timeout
  - **缓冲**:proxy_buffering 控制是否缓存响应
  - **HTTP/2 + TLS**:listen 443 ssl http2;
- **常见坑**
  - **真实 IP 丢失**:后端读到代理 IP,需 X-Forwarded-For + 应用层取首个非代理 IP
  - **HTTPS 跳转死循环**:负载均衡卸载 SSL,后端协议错判,需 X-Forwarded-Proto
  - **WebSocket 配置遗漏**:需 proxy_set_header Upgrade / Connection
  - **大文件上传卡死**:client_max_body_size 默认 1M,需调大
- **反向代理 vs API 网关 vs 服务网格**
  - **反向代理**:基础转发 + 简单 LB
  - **[[API网关]]**:反向代理 + 认证 / 限流 / 协议转换 / 监控
  - **[[服务网格]]**:网关 + 服务间治理 + mTLS + 可观测性
  - 三者递进,职能扩展
- **现代演进**
  - **eBPF 反向代理(Cilium)**:绕过用户态,内核直接转发,性能更优
  - **WASM 插件**:Envoy / Nginx 用 WASM 写自定义逻辑

## 和其他概念的关系

反向代理是 [[API网关]] 与 [[服务网格]] 的简化形态;Nginx 既可作纯反向代理,也可借插件成为简易 API 网关。

[[CDN]] 本质是分布式反向代理 + 缓存。[[负载均衡]] L7 模式的实现常基于反向代理。

[[TLS]] 卸载是反向代理的常见用途,把加密计算从后端 Web 服务剥离。

[[Web安全]] 中,反向代理是 WAF / 防 DDoS / IP 限流的天然部署点,源站隐藏在代理之后更安全。

[[微服务]] 与 [[Kubernetes]] 中,Ingress Controller(基于 Nginx / Traefik / Envoy)是反向代理的云原生形态。
