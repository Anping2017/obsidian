# 泛型编程 Generic Programming

## 定义

泛型编程(Generic Programming)是一种**让算法与数据结构脱离具体类型而工作**的编程范式。通过把类型作为参数传入(类型参数化),实现「一份代码,多种类型」。它在保留**静态类型安全**的同时获得**多态的灵活性**,被称为「参数多态」(parametric polymorphism)。

经典代表:`List<T>` 链表既能装 `Integer` 也能装 `String`,且编译期就能检测类型错误。

## 核心要点

### 三种实现策略

| 策略 | 代表语言 | 特征 |
|---|---|---|
| 类型擦除(Type Erasure) | Java、TypeScript | 编译后泛型信息消失,运行时统一为 `Object`/`any` |
| 单态化(Monomorphization) | C++ 模板、Rust、Go(1.18+) | 编译期为每个用到的类型生成专门代码 |
| 装箱 + 字典传递 | Haskell 类型类、Swift 协议 | 用类型类/witness 表传递操作 |

各策略权衡:

- 类型擦除:二进制小、可与旧代码兼容,但丧失运行时类型信息(导致 Java 不能 `new T()`)
- 单态化:运行时无开销,性能极致,但二进制膨胀、编译慢
- 字典传递:模块化优雅,但有间接调用开销

### 类型约束(Bounded Generics)

不同语言提供机制限制类型参数:

- Java:`<T extends Comparable<T>>`
- C++:概念(Concepts,C++20)、SFINAE
- Rust:trait bound `T: Display + Clone`
- TypeScript:`T extends string | number`,条件类型,映射类型
- Go:类型集合(union types)、interface 约束

### 协变 / 逆变 / 不变

涉及泛型容器之间的类型关系:

- **协变(Covariant)**:`List<Cat>` 是否 `List<Animal>`(读取场景安全)
- **逆变(Contravariant)**:`Consumer<Animal>` 是否 `Consumer<Cat>`(写入场景安全)
- **不变(Invariant)**:Java 默认,需显式 `? extends` / `? super` 表达

### 高级特性

- **变参泛型(Variadic Generics)**:支持任意数量类型参数,如 C++ `std::tuple`、TS Tuple Types
- **关联类型(Associated Types)**:Rust trait、Swift protocol 内嵌类型
- **高阶类型(Higher-Kinded Types, HKT)**:类型对类型的函数,Scala/Haskell 支持,Rust 部分支持
- **GADTs**:广义代数数据类型,Haskell/OCaml 提供更精细的类型表达

### 泛型 vs 接口(动态分派)

二者解决不同问题:

- **泛型**:编译期已知所有类型,优先零开销
- **接口/特质对象(`dyn Trait`)**:运行时多态,按需选择实现

实践中常组合使用:接口约束泛型参数,既灵活又类型安全。

## 和其他概念的关系

泛型编程是现代静态类型 [[编程语言比较|编程语言]] 的核心抽象机制,与 [[类型系统]]、[[类型推导]]、[[Trait]]/接口、[[函数式编程]] 紧密相连。

C++ STL 是泛型编程的里程碑产物;Rust 在内存安全前提下实现了零成本泛型;[[TypeScript泛型与条件类型]] 把类型层面的元编程推向极致;[[Go 1.18 泛型]] 让 Go 重新有了写通用容器的能力。

泛型编程使得 [[数据结构]](`Map<K, V>`、`List<T>`)、[[算法]](`sort<T: Ord>`)、[[设计模式]](泛型工厂、Observer<T>)的抽象能力大幅提升,减少代码重复。

[[函数式编程]] 中的 monad、functor 都依赖泛型/HKT 表达;[[元编程]](C++ 模板元编程、TypeScript 类型体操、Rust 宏)与泛型有交叉。[[反射]] 则是泛型在「运行期类型擦除」语言中的补丁。
