# 分布式系统 Distributed System

## 定义

分布式系统(Distributed System)是**由多个独立节点(机器、进程)通过网络协作、对外呈现为单一逻辑系统**的计算系统。Leslie Lamport 的著名定义:「在某台你从未听说过的机器故障时,你的电脑停止工作的系统」。

构成要素:

- 多个节点,各自有独立计算与存储
- 节点间通过网络通信(异步、可能丢包/延迟)
- 协作完成某个统一目标(存数据、提供服务、计算任务)
- 对外提供统一的接口与语义

## 核心要点

### 八大常见错误假设(Fallacies of Distributed Computing)

L Peter Deutsch 提出,所有都是错的:

1. 网络是可靠的
2. 延迟是零
3. 带宽是无限的
4. 网络是安全的
5. 拓扑不会变
6. 只有一个管理员
7. 传输代价是零
8. 网络是同质的

理解这八点是分布式系统设计的起点。

### 核心理论

| 理论 | 内容 |
|---|---|
| CAP 定理 | 分区时只能选 C(一致性)或 A(可用性) |
| BASE 理论 | 基本可用、软状态、最终一致 |
| FLP 不可能 | 异步网络中不存在保证总能终止的共识算法 |
| 拜占庭将军 | 存在恶意节点的共识问题 |
| 两将军问题 | 不可靠信道无法保证完美一致 |

### 一致性模型(由强到弱)

- **线性一致性(Linearizability)**:操作看似瞬间完成,全局有序
- **顺序一致性**:全局有序,但顺序不必反映真实时间
- **因果一致性**:有因果关系的操作有序
- **最终一致性**:停止写入后,系统最终收敛
- **读己之写**:用户能读到自己刚写的数据

### 共识算法

详见 [[Raft共识算法]]、[[Paxos]]:

- 解决「多副本对一系列操作达成共识」问题
- 容忍少数节点故障(2f+1 节点容 f 故障)
- 基础是 Quorum(多数派)读写

### 工程模式

| 问题 | 模式 |
|---|---|
| 服务调用 | RPC、消息队列 |
| 服务发现 | 注册中心、DNS |
| 负载均衡 | LB、客户端 LB、一致性 Hash |
| 数据分片 | Range/Hash/一致性 Hash |
| 数据复制 | 主从、多主、链式 |
| 事务 | [[分布式事务]]、Saga、TCC |
| 锁 | [[分布式锁]] |
| 限流 | 令牌桶、漏桶 |
| 故障检测 | 心跳、Gossip、Phi accrual |
| 配置管理 | etcd、ZooKeeper、Consul |

### 可观测性三支柱

- **日志(Logs)**:结构化日志 + 集中收集(ELK)
- **指标(Metrics)**:Prometheus + Grafana
- **追踪(Traces)**:OpenTelemetry、Jaeger、Zipkin

## 和其他概念的关系

分布式系统是 [[计算机科学知识体系|计算机科学]] 的一大分支,衍生子领域包括 [[微服务]]、[[云计算]]、[[大数据]]、[[区块链]]、[[边缘计算]]。

[[关系型数据库]] 通过分库分表与 [[Raft共识算法]] 走向分布式;[[NoSQL数据库]](Cassandra、MongoDB)天生分布式。[[消息队列]](Kafka、RabbitMQ)是分布式系统解耦的标准件。

[[CAP定理]]、[[BASE理论]] 指导工程取舍;[[一致性Hash]]、[[Quorum]]、[[Vector Clock]] 是经典数据结构与算法。

[[Kubernetes]] 把分布式系统的最佳实践产品化,成为云原生时代的事实标准。[[服务网格|Service Mesh]] 进一步把网络治理与业务逻辑分离。
