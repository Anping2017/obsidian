# 倒排索引

## 定义

**倒排索引(Inverted Index)** 是一种把"词(term)→ 包含该词的文档列表"反向组织的索引结构,与传统"文档 → 词列表"的正向索引相反。它通过把文档先分词,然后建立词典 + 倒排链 + 文档评分,实现毫秒级全文检索。是搜索引擎(Google / Bing / Elasticsearch / Solr / Lucene)、日志分析、电商搜索的核心技术。

## 核心要点

- **基本结构**
  - **词典(Term Dictionary)**:所有词的有序集合,常用 [[B+树]] / FST(有限状态转换器)/ 跳表 存储
  - **倒排链(Posting List)**:每个词对应的"出现该词的文档 ID 列表 + 频率 + 位置"
  - **文档存储(Document Store)**:文档原文或字段值
- **构建流程**
  - 1. **采集**:抓取 / 接收原始文档
  - 2. **分析(Analyze)**
    - **分词(Tokenize)**:中文 IK / Jieba,英文按空格 + 词形还原
    - **小写化、去停用词、词干提取(stemming)、同义词扩展**
  - 3. **索引(Index)**:词 → 添加到倒排链
  - 4. **持久化**:Lucene 用类似 [[LSM树]] 的段(Segment)结构,不可变 + 后台合并
- **查询流程**
  - 1. 查询语句分词(同索引侧 analyzer)
  - 2. 词典查找每个词的倒排链
  - 3. 多词组合(AND / OR / NOT)做集合运算
  - 4. 计算相关性评分(TF-IDF / BM25 / 向量相似)
  - 5. 排序返回 Top K
- **评分模型**
  - **TF-IDF**:词频 × 逆文档频率
  - **BM25**:Lucene/ES 默认,改进 TF-IDF,饱和函数防长文档过分得分
  - **向量评分(KNN / ANN)**:Embedding 向量做语义检索,见 [[向量数据库]]
- **存储优化**
  - **压缩**:倒排链中文档 ID 用 delta + 变长编码(VarInt / Frame of Reference)
  - **跳跃表**:大倒排链分级跳跃加速 AND 求交
  - **位图(Roaring Bitmap)**:Solr / ES 用 Roaring Bitmap 表示文档 ID 集合,集合运算快
  - **缓存**:热点词的倒排链 / Filter Cache 常驻内存
- **典型实现**
  - **Apache Lucene**:Java 库,Solr / Elasticsearch 都基于 Lucene
  - **Elasticsearch**:Lucene 之上的分布式服务 + REST API + JSON DSL
  - **OpenSearch**:Elasticsearch fork,Apache 协议
  - **Apache Solr**:更早的 Lucene 服务化项目
  - **PostgreSQL GIN / Tsvector**:RDBMS 原生倒排
  - **MySQL FULLTEXT**:MyISAM / InnoDB(5.6+)支持简单倒排
  - **MeiliSearch / Typesense**:轻量级开箱即用
- **分布式倒排索引**
  - 文档按某种规则分片(用户 ID / 时间)到多节点
  - 查询时各节点本地查 → 协调节点合并排序
  - 倒排索引天然适合"分散查询 + 合并 Top K"
- **倒排 vs 正排**
  - **正排**:文档 ID → 文档内容,用于详情查询
  - **倒排**:词 → 文档 ID 列表,用于关键词查询
  - 搜索系统两者都建,正排用于结果展示,倒排用于查询匹配
- **常见应用**
  - **网站搜索框**:商品 / 帖子 / 文档全文搜索
  - **日志检索**:Elasticsearch 是日志分析(ELK)的核心
  - **代码搜索**:GitHub Code Search、Sourcegraph
  - **学术 / 法律检索**:文献数据库
- **现代趋势:倒排 + 向量混合**
  - 关键词搜索(倒排)+ 语义搜索(向量)结合
  - **Hybrid Search**:同时召回两种结果,RRF / 加权融合
  - Elasticsearch 8.x、Vespa、Weaviate 都支持

## 和其他概念的关系

倒排索引是 [[数据库索引]] 中专为全文检索设计的特殊形态,与 [[B+树]](等值 / 范围)、[[LSM树]](写优化)、[[Hash表]](等值)各司其职。

底层存储常用 [[LSM树]] 思想:索引段不可变 + 后台合并。

与 [[向量数据库]] 是"关键词 vs 语义"的两条搜索路线,现代系统多融合使用(混合搜索)。

[[查询优化器]] 在 ES / Solr 中也存在,优化布尔查询的执行顺序、剪枝、缓存策略。

在 [[微服务]] 架构中,搜索常独立成服务(搜索中心),由 ES 集群承担,通过 CDC + [[消息队列]] 实时同步业务库变更。

[[可观测性三支柱]] 中日志支柱普遍用 ELK / Loki,Loki 反传统不全文索引(只索引 label),走的是不同设计哲学。
