# 包管理器对比

## 定义

包管理器(Package Manager)是编程语言生态的"分发与依赖管理基础设施"。它解决三个核心问题:
1. 从中央仓库下载依赖
2. 解决依赖冲突(版本约束、传递依赖)
3. 跨开发者/CI 环境复现依赖(锁文件)

不同语言的包管理器在这三方面有各自的取舍,反映了语言社区的工程文化。

## JavaScript/TypeScript:npm / yarn / pnpm

**npm(Node Package Manager)**

- [[Node.js]] 内置,2010 年随 Node 一起出现
- 仓库:npmjs.com,世界最大代码仓库(全球 200 万 + 包)
- 锁文件:package-lock.json
- 安装:每个项目独立 node_modules,磁盘消耗大
- 速度:7+ 已用并行,但不及 yarn/pnpm

**yarn**

- Facebook 2016 推出,初衷加速 npm
- 锁文件:yarn.lock
- 引入工作区(Workspaces)做 monorepo
- yarn 1 经典稳定,yarn 2/3/4(Berry)切换 PnP(Plug'n'Play)模式,无 node_modules,但兼容性问题多
- 当前发展放缓,部分团队回 npm 或转 pnpm

**pnpm**

- 2017 年起推出,2020 年后火
- 核心创新:**硬链接 + Content-addressable Store**
- 全局存一份依赖,各项目通过硬链接共享,磁盘节省 50-80%
- 严格依赖隔离,避免"npm 模块借用"问题
- 完整支持 monorepo
- 速度最快,主流前端团队迁移目标

## Python:pip / poetry / uv

**pip**

- Python 内置,默认 PyPI
- 简单 pip install
- 缺锁文件原生支持(用 requirements.txt)
- 依赖解析较简单,易冲突
- 虚拟环境配套用 venv / virtualenv

**Poetry(2018+)**

- pyproject.toml 配置 + poetry.lock
- 完整依赖解析(SAT solver)
- 内建虚拟环境
- 发布到 PyPI 集成
- 较慢,处理复杂依赖时几分钟

**uv(2024,Astral)**

- Rust 写的 pip / pip-tools / venv 替代
- 速度比 pip 快 10-100 倍
- pyproject.toml 兼容
- 项目格式标准化推动者
- 2024-2025 快速取代 pip 的趋势

## Java/[[Kotlin]]:Maven / Gradle

**Maven**

- 2002 年 Apache 项目
- pom.xml 声明式配置
- 中央仓库:Maven Central(JVM 生态最大)
- 严格生命周期(compile/test/package/install/deploy)
- XML 配置冗长但稳定
- 标准化程度极高,IDE 集成完美

**Gradle**

- 2007 年起
- Groovy DSL(可写 Kotlin DSL,Android 默认)
- 比 Maven 灵活,可写复杂逻辑
- 增量构建快
- 配置可读性低于 Maven 简单情况
- Android 默认构建工具

**对比**

| 维度 | Maven | Gradle |
|---|---|---|
| 配置语言 | XML | Groovy/Kotlin DSL |
| 学习曲线 | 中 | 中至高 |
| 灵活性 | 中 | 高 |
| 速度(增量) | 中 | 快 |
| Android | 不主流 | 默认 |

## Rust:Cargo

- 与 [[Rust所有权|Rust]] 一起诞生,内置
- Cargo.toml 配置 + Cargo.lock 锁文件
- crates.io 仓库
- 设计借鉴 npm 但更严谨
- 测试、文档、构建、发布一体
- 工程文化典范,常被其他语言学习

**亮点**

- Workspace 原生支持 monorepo
- features 条件编译
- profile 多模式构建
- 跨平台编译(target)
- 文档生成(rustdoc)集成

## Go:go mod

- Go 1.11(2018)前一直是 GOPATH 时代
- go modules 终于带来现代依赖管理
- go.mod / go.sum
- 简单、快、与 git 紧密(用 git tag 表版本)
- 仓库去中心化(直接 git URL)

## C/C++:vcpkg / Conan / CMake

历史上 C/C++ 没有统一包管理:
- vcpkg(微软)
- Conan(社区)
- CMake FetchContent
- 系统包(apt/yum/brew)

每个项目可能用不同方案,这是 C++ 工程"古老"的标志。

## PHP:Composer

- 2012 年起,PHP 现代生态基础
- composer.json + composer.lock
- Packagist 仓库
- [[Laravel]]、Symfony 等框架推动其普及

## Ruby:Bundler

- Ruby 历史先驱,2010 年 Bundler 推出
- Gemfile / Gemfile.lock
- RubyGems 仓库
- [[Ruby on Rails|Rails]] 强制依赖,稳定可靠

## .NET:NuGet

- Microsoft 2010 年起
- 与 Visual Studio、dotnet CLI 集成
- nuget.org 仓库
- packages.config (旧)/ PackageReference (新)

## 通用设计模式

**1. 锁文件(Lockfile)**

确保跨环境/CI 安装相同版本,Cargo.lock、package-lock.json、poetry.lock、Gemfile.lock 共同模式。

**2. 语义化版本(SemVer)**

MAJOR.MINOR.PATCH 约定,大多数包管理器原生支持 ^1.2.0 等约束。

**3. 中央仓库 vs 去中心化**

- 中心化:npm、PyPI、Maven Central、crates.io
- 去中心化:Go modules(任意 git URL)

**4. 镜像与代理**

国内开发者常用镜像:
- npm:阿里巴巴 npmmirror.com
- pip:清华、阿里、豆瓣
- Maven:阿里
- crates.io:rsproxy

**5. 私有仓库**

- npm:Verdaccio、Nexus、Artifactory
- pip:PyPI Server、Nexus
- Maven:Nexus、Artifactory
- 内部分发的标准做法

## 跨语言对比

| 维度 | npm/pnpm | pip/poetry | Maven/Gradle | Cargo | go mod |
|---|---|---|---|---|---|
| 内置 | 是 | 是 | 否 | 是 | 是 |
| 锁文件 | 是 | poetry 是 | 部分 | 是 | go.sum |
| 依赖解析 | 中 | 强(poetry) | 强 | 强 | 中 |
| 速度 | pnpm 快 | uv 极快 | 慢 | 中 | 极快 |
| 设计典范 | 中 | 改善中 | 老但稳 | 现代经典 | 简洁 |

## 选择决策

新项目通常无选择:语言已决定包管理器。但工程实践层面:
- JavaScript:首选 pnpm
- Python:首选 uv 或 poetry,新人 pip 也能起步
- Java:Android Gradle,后端可选 Maven 稳或 Gradle 快
- Rust:Cargo 唯一选择
- 多语言项目用 Bazel、Buck 等元构建工具
