# 贪心算法 Greedy Algorithm

## 定义

**贪心算法(Greedy)**是一类求解最优化问题的[[算法]]策略:在每一步只做**当前看起来最优**的决策,不回退、不预演,期望最终得到全局最优解。它的特点是简单、快(常常 O(n log n) 或 O(n))、空间小。

贪心能成立的两个前提:
- **贪心选择性质**:每步局部最优可推出全局最优(需严格证明)
- **最优子结构**:全局最优解包含子问题最优解(与[[动态规划]]共享)

不满足贪心选择性质就会得到次优解。

## 核心要点

### 经典适用问题

| 问题 | 贪心策略 |
|---|---|
| 活动选择 | 按结束时间最早 |
| Huffman 编码 | 每次合并频率最小两个节点 |
| 最小生成树(Kruskal) | 按权排序选最短边(并查集判环) |
| Dijkstra 单源最短路 | 每次扩展距离最小未确定点 |
| 区间覆盖 | 按起点排序,每次选能覆盖最远的 |
| 找零钱(标准币制) | 每次用最大可用面额 |
| 任务调度(单机最小化最大延误) | EDF 最早截止优先 |
| 加油站问题 | 起点选总油量充足的 |

### 反例:贪心失败的情况

- **0-1 背包**:按"价值/重量"降序贪心不一定最优 → 必须 [[动态规划]]
- **找零钱(非标准币制)**:面值 [1,3,4],找 6 块,贪心 4+1+1=3 张,DP 3+3=2 张
- **TSP 旅行商**:最近邻贪心不保证最优

### 证明贪心正确的两种范式

1. **交换论证(Exchange Argument)**:设最优解 OPT 与贪心解 G 不同,证明可把 OPT 中"贪心未选的元素"换成"贪心选的"而不变差,反复交换直到 OPT = G
2. **数学归纳法**:假设前 k 步贪心是最优解的前缀,证明第 k+1 步仍是

工程上很多人"凭直觉"用贪心而不证明,容易在边界 case 出错。

### 贪心 vs DP

| 维度 | 贪心 | [[动态规划]] |
|---|---|---|
| 决策空间 | 每步唯一选择 | 探索多种 |
| 复杂度 | 通常 O(n log n) | 通常 O(n²) 或更高 |
| 适用条件 | 严格,需证明 | 较宽松 |
| 思考难度 | 易,但易错 | 系统化 |
| 状态保存 | 通常不保存 | 关键 |

可把贪心看作"DP 的极端简化版"(每个状态只保留一个候选)。

### 拟阵理论(Matroid)

数学上,**拟阵**结构上贪心一定最优。Kruskal 之所以正确,因为图的"无环子图"构成拟阵。这给"是否能用贪心"提供了理论判据,但拟阵抽象不直观,工程多靠经验和反例验证。

## 和其他概念的关系

贪心、[[动态规划]]、[[回溯算法]]、[[分治算法]]构成[[算法]]思想的四大门类。贪心是 DP 的退化(每步只保留一个状态)。当 DP 状态转移恰好"局部最优 = 全局最优"时,可以从 DP 简化到贪心。

[[图]]算法中 Kruskal、Prim、Dijkstra 都是贪心代表。Huffman 编码用贪心建[[树]]。[[操作系统]]页面置换的 LRU、磁盘调度的 SCAN 算法、负载均衡的"加权轮询"本质都是贪心。

实际工程中,贪心常作为"启发式(Heuristic)":即使无法证明全局最优,也能给出"足够好"的近似解,如近似算法、深度学习训练中的随机梯度下降的"步步局部最优"。
