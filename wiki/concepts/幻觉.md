# 幻觉

## 定义

**幻觉(Hallucination)** 指 [[大语言模型]] 生成貌似流畅合理、但事实错误、与上下文矛盾或完全捏造的内容。其根源在于 LLM 是按训练分布**概率生成**下一 token,而非检索事实数据库;只要不实信息在生成空间中"看起来像真的",模型就可能输出。

幻觉是 LLM 在医疗、法律、金融等高风险场景落地最大的可靠性障碍。

## 核心要点

**主要类型**

- 事实幻觉:杜撰人物、日期、引用、API 等(如编造不存在的论文)
- 上下文幻觉:与用户提供的源材料不一致
- 逻辑幻觉:推理过程内部自相矛盾
- 安全相关:声称自己有/没有某种能力时不实

**根因**

- 训练数据本身有错误,被模型学习
- 长尾事实在训练数据中稀疏,模型只能"猜"
- next-token 优化目标无事实约束
- 用户问到训练截止之后的事(模型知识过时)
- 过度自信:[[RLHF]] 对齐有时让模型"听起来更自信"反而强化幻觉

**主流缓解方法**

| 方法 | 思路 |
|---|---|
| [[RAG]] | 把权威外部知识检索到 prompt 中,让模型基于事实生成 |
| 工具调用([[函数调用]]、[[MCP协议]]) | 把事实查询外包给专用 API、数据库 |
| 显式引用与验证 | 强制模型给出来源,可核查 |
| 自我反思([[思维链]]、self-consistency) | 让模型多次生成或自检 |
| 解码时约束 | 限制只能从某词表生成,如 JSON Schema 约束 |
| 微调对齐 | 用 [[RLHF]] 训练拒绝不知答案的行为 |
| 评测与监控 | 把幻觉率纳入产品质量指标 |

**评测难点**

- 没有标准定义,与"创造性"和"合理推断"的边界模糊
- 长文档生成中难以自动检测每个事实
- 涉及多语言、多领域时人工标注成本高

## 和其他概念的关系

- 主要发生在:[[大语言模型]] 推理阶段
- 主要解药:[[RAG]] 与工具调用([[函数调用]]、[[MCP协议]])
- 提示层缓解:[[思维链]] 让推理透明化便于发现错误
- 与 [[RLHF]] 关系:对齐可减少明显错误也可能引入"自信幻觉"
- 评测维度:[[模型评估]] 中的真实性(truthfulness)、TruthfulQA 基准
