# Hash 表 Hash Table

## 定义

**哈希表(Hash Table / Hash Map)**是一种以"键-值对"形式存储数据的[[数据结构]],通过**哈希函数 h(key)**把键映射到**桶数组**下标,从而在期望 O(1) 的时间内完成查找、插入、删除。它是字典、集合、Map 等抽象类型最常见的实现。

三个核心组件:
- **哈希函数**:输入键,输出桶下标
- **桶数组**:存储元素的连续内存
- **冲突解决策略**:不同键 hash 到同一桶时如何处理

## 核心要点

### 哈希函数设计

理想哈希函数应满足:
- **确定性**:同一键总产生相同 hash
- **均匀分布**:输出在桶范围内均匀,降低冲突
- **高效**:计算代价 O(1)
- **雪崩效应**:输入轻微变化导致输出剧变(密码学要求,普通哈希表非必需)

常见做法:除法散列(`h = key % m`,m 取质数)、乘法散列、MurmurHash、CityHash、xxHash、FNV。

### 冲突解决

1. **链地址法(Separate Chaining)**:每个桶是一个[[链表]]/红黑树。Java HashMap 在链长 ≥ 8 时转红黑树以避免最坏 O(n)
2. **开放寻址(Open Addressing)**:冲突时按规则探测下一空位
   - **线性探测**:h(k) + i,易聚集
   - **二次探测**:h(k) + i²,缓解聚集
   - **双重散列**:h₁(k) + i × h₂(k),性能最好但需两次 hash

### 装载因子与扩容

**装载因子 α = 元素数 / 桶数**。α 越大,冲突越多。
- Java HashMap 默认阈值 0.75:超过则桶数翻倍并重新散列
- 扩容(rehash)是 O(n) 操作,对长尾延迟敏感场景需"渐进式 rehash"(Redis 做法)

### 复杂度

| 操作 | 平均 | 最坏 |
|---|---|---|
| 查找 | O(1) | O(n) |
| 插入 | O(1) | O(n) |
| 删除 | O(1) | O(n) |

最坏发生在所有键 hash 到同一桶。哈希攻击(Hash DoS)即恶意构造冲突使服务退化。Java 8 的红黑树 fallback 把最坏降到 O(log n)。

### 一致性哈希(Consistent Hashing)

普通哈希在节点增减时几乎所有键都要重新映射。**一致性哈希**把节点和键都映射到 0-2³² 的环上,键归属于沿环顺时针遇到的第一个节点。节点变更时只影响相邻节点的键,迁移代价从 O(n) 降到 O(n/N)。
- 配合**虚拟节点**解决数据倾斜
- 应用:[[CDN]] 路由、分布式缓存(Memcached、Redis Cluster)、[[一致性Hash]]负载均衡

### 布隆过滤器(Bloom Filter)

用 k 个独立哈希函数 + 位数组判断元素是否"可能存在"。
- 空间极省、查询 O(k)
- **可能假阳性,绝对无假阴性**(因此适用于"判断不存在")
- 应用:URL 去重、缓存穿透防护、Cassandra/HBase 跳过 SSTable

## 和其他概念的关系

哈希表是几乎所有"字典型"接口的默认实现:Python `dict`、Java `HashMap`、Go `map`、JS `Object`/`Map`、Redis hash。它和[[二叉搜索树]]/[[红黑树]]互补:Hash 表 O(1) 但无序;BST O(log n) 但保留有序遍历。

[[数据库]]中:Hash 索引适合等值查询(MySQL Memory 引擎默认、PostgreSQL Hash Index);[[B+树]]索引适合范围查询。NoSQL 的 KV 存储基本是分布式哈希表 + 持久化。

[[缓存]]系统(Memcached、Redis)的核心数据结构是哈希表。[[微服务]]中,API Gateway 路由表常用 hash 加速查找。区块链的 Merkle Tree 用密码学哈希聚合状态。

AI 应用:[[向量数据库]] 中 LSH(局部敏感哈希)用哈希函数对相似向量产生相似桶号,把高维近邻搜索从 $O(nd)$ 降到接近常数级别;[[RAG]] 系统在去重、精确字段过滤、文档块缓存等环节大量使用哈希表加速;LLM 推理的 KV-Cache 也是带 token 键的哈希结构,显著降低自回归解码的重复计算成本。
