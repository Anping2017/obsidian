# 依赖倒置原则 Dependency Inversion Principle

## 定义

依赖倒置原则(Dependency Inversion Principle, DIP)由 Robert C. Martin(Bob 大叔)提出,是 [[设计原则SOLID|SOLID原则]] 中的 **D**。其表述:

1. **高层模块不应依赖低层模块,二者都应依赖抽象**
2. **抽象不应依赖细节,细节应依赖抽象**

「倒置」一词指**依赖方向**的颠倒——传统过程式编程中,高层调用低层、依赖具体实现;DIP 要求反过来,让具体实现去依赖抽象接口,而抽象由高层定义。

## 核心要点

### 直观对比

**违反 DIP**:

```python
class MySQLDatabase:  # 低层
    def save(self, data): ...

class OrderService:  # 高层
    def __init__(self):
        self.db = MySQLDatabase()  # 直接依赖具体类
    def place_order(self, order):
        self.db.save(order)
```

业务层与 MySQL 紧耦合,换数据库要改业务代码,无法 Mock 测试。

**遵循 DIP**:

```python
from abc import ABC, abstractmethod

class Repository(ABC):  # 抽象,由业务层定义
    @abstractmethod
    def save(self, data): ...

class MySQLRepository(Repository):  # 低层实现抽象
    def save(self, data): ...

class OrderService:  # 高层
    def __init__(self, repo: Repository):
        self.repo = repo
    def place_order(self, order):
        self.repo.save(order)
```

业务层只认识 `Repository` 抽象,数据库可换为 PostgreSQL、内存 Mock,无需修改业务代码。

### 常见误解澄清

- **DIP ≠ 简单接口化**:把每个类都加接口不是 DIP,关键是**抽象由高层(使用方)定义、细节去实现它**,而非低层先有类再抽出接口
- **DIP 关注的是依赖方向**:控制权随调用从上到下,但**源码依赖**从下到上
- **DIP 不等于依赖注入(DI)**:DIP 是设计原则,DI 是实现 DIP 的常见技术手段

### 与依赖注入(DI)、IoC 的关系

| 概念 | 含义 |
|---|---|
| DIP | 设计原则:依赖抽象 |
| 依赖注入(DI) | 技术手段:由外部传入依赖,而非内部 new |
| 控制反转(IoC) | 设计模式:框架/容器接管对象创建与生命周期 |
| IoC 容器 | 技术实现:Spring、Guice、NestJS Module 等 |

### 实战收益

1. **可测试性**:用 Mock/Stub 替代真实依赖
2. **可替换性**:换数据库、消息队列、第三方服务无需改业务
3. **演进性**:抽象稳定,实现可独立演化
4. **模块化**:跨团队/跨项目可重用业务逻辑
5. **Clean Architecture / 六边形架构 / 端口与适配器** 都以 DIP 为核心

## 和其他概念的关系

DIP 是 [[设计原则SOLID|SOLID原则]] 中黏合作用最强的一条,常与 [[里氏替换原则]]、[[接口隔离原则]] 联动使用。它是 [[设计模式]] 中策略模式、模板方法、桥接模式、依赖注入模式的理论基础。

DIP 直接驱动了 [[六边形架构]](Hexagonal/Ports & Adapters)、[[整洁代码|整洁架构]](Clean Architecture)、[[洋葱架构]](Onion):核心业务在中心,通过抽象接口与外部世界(数据库、UI、第三方)隔离。

[[微服务]] 间通过接口通信,实质是分布式版的 DIP——每个服务对外暴露稳定 API,内部实现可独立替换。

[[单元测试]] 与 [[Mock 技术]] 几乎完全建立在 DIP 之上;[[TDD测试驱动开发|TDD 测试驱动开发]] 鼓励先定义抽象再实现,自然产生 DIP 友好的代码。

[[整洁代码]]、[[重构方法]] 是 DIP 落地的实践抓手。Spring、ASP.NET Core、NestJS 等现代框架内置 DI 容器,把 DIP 从设计选择变为默认范式。
