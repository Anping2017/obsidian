# 并发与并行 Concurrency vs Parallelism

## 定义

**并发(Concurrency)**:逻辑上"同时"处理多个任务,但任意瞬间不一定真同时执行。重在**任务结构**——把程序设计为多个独立活动。Rob Pike 的精辟定义:"Concurrency is about dealing with lots of things at once."

**并行(Parallelism)**:物理上**真正同时**执行多个任务,需要多核 CPU、多机或 GPU。重在**执行**——把工作分摊到多核。"Parallelism is about doing lots of things at once."

并发不必并行(单核也能并发,通过时间片切换);并行实施时几乎一定也是并发的。

## 核心要点

### 并发模型

| 模型 | 代表 | 调度 | 通信 |
|---|---|---|---|
| 多线程 | Java/C++/Python(GIL) | 内核抢占 | 共享内存 + 锁 |
| 多进程 | OS、Python multiprocessing | 内核抢占 | IPC、消息 |
| [[事件循环]] | Node.js、Nginx、Python asyncio | 用户协作 | 回调、Promise |
| 协程 | Go(goroutine)、Kotlin coroutine、Python async | 用户协作或半内核 | channel、async/await |
| Actor | Erlang、Akka | 自带调度 | 不可变消息 |
| CSP | Go、Clojure core.async | M:N 调度 | 通道 |

### 并发的两大难题

1. **竞态条件(Race Condition)**:多线程读写共享数据顺序不确定 → 数据损坏
2. **死锁(Deadlock)**:多个任务互等对方持有的资源永不释放
3. **活锁(Livelock)**:任务运行但无进展(各自礼让)
4. **饥饿(Starvation)**:某任务长期得不到资源
5. **优先级反转**(实时系统经典 bug)

### 同步原语

- **互斥锁(Mutex)**:保护临界区
- **读写锁**:多读单写
- **信号量(Semaphore)**:计数器,限并发数
- **条件变量**:wait/signal/broadcast
- **CAS / 原子操作**:无锁基础
- **屏障(Barrier)**:让多线程同步到某点

### 并行的硬件层面

- **多核 CPU**:每核独立 ALU,通过缓存一致性协议(MESI)同步
- **SIMD**:Single Instruction Multiple Data,如 SSE/AVX,一条指令处理 4/8/16 数据
- **GPU**:数千核心,适合矩阵/向量并行(深度学习训练)
- **集群**:多机器并行,通过网络通信(MPI、Spark)

### Python GIL 与多线程

CPython 有**全局解释器锁(GIL)**,任意时刻只一个线程执行 Python 字节码。
- IO 密集型:多线程仍有效,因为 IO 时释放 GIL
- CPU 密集型:多线程并不加速 → 用 multiprocessing(多进程,各自有 GIL)、用 C 扩展(numpy 的 BLAS 在 C 层并行)

### Amdahl 定律

并行加速比上限 = 1 / (s + p/N),s 是串行比例、p 是并行比例、N 是核数。即使 95% 可并行,无限核也只 20 倍加速。"系统中最不可并行的那部分,最终决定上界。"

### 并发安全的数据结构

- 无锁队列(LinkedBlockingQueue、Disruptor)
- 并发哈希表(Java ConcurrentHashMap 分段锁)
- COW 集合(CopyOnWriteArrayList)
- STM(软件事务内存,Clojure)
- 不可变数据结构 + 函数式风格 → 天然并发安全

## 和其他概念的关系

并发模型与[[编程范式]]深度耦合:[[函数式编程]]鼓励不可变 → 天然并发友好;[[面向对象编程]]共享可变状态 → 需大量锁。

[[操作系统]]内核里:进程 / 线程是抢占式并发;中断处理是异步并发;调度器实现 N 个任务在 M 个核上的映射。[[事件循环]]是单核协作式并发的最简模型。

[[分布式系统]]是并发的极端形式,加上网络延迟、部分失败、共识(Paxos/Raft)等额外难题。[[数据库]]事务的[[ACID]]隔离级别本质是并发控制(MVCC、2PL)的产物。

[[消息队列]]、Reactor 模式、Stream Processing 都是把并发问题"工业化"封装为可复用框架。
