# HTTP/2 协议

## 定义

**HTTP/2** 是 [[HTTP协议]] 的第二代主要版本,2015 年由 IETF 在 RFC 7540 中标准化。它在保持 HTTP/1.1 语义不变(方法、状态码、首部)的前提下,**重写了传输层格式**,从纯文本协议升级为基于帧(frame)和流(stream)的二进制协议。设计目标是降低延迟、提高吞吐、提升 [[Web安全]] 默认级别。

## 核心要点

### 1. 二进制分帧层

HTTP/2 在 TCP 之上、HTTP 语义之下引入"二进制分帧层":消息被切分为头帧(HEADERS)、数据帧(DATA)等,每帧带流 ID。这让多请求可以**交错**在同一连接中传输,而 HTTP/1.x 是文本逐行解析、严格串行。

### 2. 多路复用(Multiplexing)

单个 TCP 连接上可同时承载多个请求-响应"流",彻底解决 HTTP/1.x 的**队头阻塞**(HOL Blocking)。浏览器不再需要为同源开 6 个连接,域名分片(domain sharding)、CSS 雪碧图、资源合并等历史优化反而成为反模式。

### 3. 首部压缩(HPACK)

使用 HPACK 算法对请求/响应头做静态字典 + 动态字典 + Huffman 编码压缩。Cookie、User-Agent 等高度重复字段在多次请求中只发增量,显著降低首部体积。

### 4. 服务器推送(Server Push)

服务器可在收到 HTML 请求时,主动推送 CSS/JS 资源,无需等待浏览器解析后再请求。但因缓存命中难、收益有限,Chrome 已于 2022 年移除推送支持,实际生产中已淡出。

### 5. 流优先级与依赖

客户端可声明流之间的优先级和依赖关系,服务器据此调度发送顺序,关键资源(首屏 CSS)优先于非关键(图片)。

## 与 HTTP/1.1 对比

| 维度 | HTTP/1.1 | HTTP/2 |
|---|---|---|
| 格式 | 纯文本 | 二进制帧 |
| 并发 | 多 TCP 连接 + Keep-Alive | 单连接多路复用 |
| 首部 | 明文重复发送 | HPACK 压缩 |
| 推送 | 不支持 | Server Push(已淡化) |
| 加密 | 可选 | 实践上必须 TLS |

## TCP 队头阻塞遗留问题

虽然 HTTP/2 解决了应用层 HOL,但仍跑在 TCP 之上;一旦底层有丢包,所有流都被 TCP 顺序保证阻塞。这一痛点直接催生了基于 UDP 的 [[HTTP3协议]] 与 QUIC。

## 关系

- 上承:[[HTTP协议]] 1.1 长连接、管道化等优化
- 下启:[[HTTP3协议]] / QUIC 把多路复用下沉到传输层
- 影响:让 [[RESTful API]] 多请求场景下延迟显著下降
- 配合:[[Web安全]] 中的 TLS 1.2+ 默认强加密
- 颠覆:HTTP/1 时代的雪碧图、域名分片成为反模式
