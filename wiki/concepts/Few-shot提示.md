# Few-shot提示

## 定义

**Few-shot 提示**(Few-shot Prompting)是在 prompt 中给大语言模型提供**少量(通常 1–10 个)输入—输出示例**,让模型通过 [[上下文学习]] 在不更新权重的情况下学会任务模式与输出格式的一种 [[提示词工程]] 技术。

它是 OpenAI 2020 年 GPT-3 论文《Language Models are Few-Shot Learners》引爆的核心范式,与 [[零样本提示]](Zero-shot)、One-shot 共同构成 LLM 上下文学习的三档形态。

## 核心要点

### 与零样本/单样本的对比

| 形态 | 示例数 | 特征 |
|---|---|---|
| **[[零样本提示]]** | 0 | 只描述任务,直接用 |
| **One-shot** | 1 | 给一个示例,锁定格式 |
| **Few-shot** | 2–10 | 多示例覆盖更多模式 |
| **多示例(Many-shot)** | 数十—数千 | 长上下文模型新形态 |

### Few-shot 的三大优势

1. **格式锁定**:确保输出严格遵循示例的结构(JSON、XML、自定义格式)
2. **风格控制**:示例语气、视角、详略程度对模型有强引导
3. **任务定义**:把模糊任务通过示例具体化,减少歧义

### 经典示例模板

```
判断下面句子的情感(正面/中性/负面)。

句子: 这家餐厅的菜很好吃。
情感: 正面

句子: 服务一般,但价格合理。
情感: 中性

句子: 等了两个小时还没上菜。
情感: 负面

句子: <用户输入>
情感:
```

### 示例选择策略

| 策略 | 描述 |
|---|---|
| **多样性** | 覆盖不同任务子类、边界情况 |
| **代表性** | 反映真实分布,而非极端样本 |
| **难度阶梯** | 从简到难安排 |
| **检索式 Few-shot** | 用语义相似度从示例库动态选择 |
| **随机性** | 多次采样不同示例集合验证稳健 |
| **顺序敏感** | 示例顺序会影响表现,常把最易识别的放最近 |

### 与思维链(CoT)的协同

[[思维链]] 与 Few-shot 结合最强:**Few-shot CoT** 把每个示例都展示推理过程,大幅提升数学、逻辑、多步问题准确率。Wei 等 2022 论文标志这一组合的奠基。

变体:
- [[Auto-CoT]]:自动生成推理链作为示例
- [[Plan-and-Solve提示]]:先计划再执行
- [[自一致性]]:多次采样投票

### Few-shot 的局限

- **上下文长度成本**:每个示例都消耗 token
- **示例选择敏感**:不同示例集表现差异大
- **过拟合示例风格**:模型可能模仿表面模式而非真意图
- **复杂任务收益递减**:超过 10 个示例边际效益小
- **与 RAG 模糊**:动态检索的 Few-shot 与 RAG 是同一谱系

### Few-shot vs 微调

| 维度 | Few-shot | 微调(SFT/[[LoRA]]) |
|---|---|---|
| 启动 | 立即可用 | 需训练 |
| 灵活 | 改 prompt 即可 | 需重训 |
| 数据量 | 几个示例 | 数百到数千 |
| 推理成本 | 长 prompt 较贵 | 短 prompt 较便宜 |
| 控制粒度 | 中 | 高 |
| 适用 | 快速原型、变化任务 | 稳定、长期、有数据 |

实践中,**Few-shot → 微调** 是常见演进路径。

## 应用场景

- **格式化输出**:JSON 结构化、表格、Markdown
- **分类任务**:情感、意图、类目
- **风格迁移**:模仿特定作者/品牌语气
- **小样本学习**:在没有大量标注数据时快速上手
- **领域适配**:法律、医疗、金融的术语和模板
- **数据增强**:给小语料"补充"任务定义
- **代码生成**:DSL 与内部 API 的范式展示

## 局限与陷阱

| 陷阱 | 描述 |
|---|---|
| **示例污染** | 错误示例会被模型当成"应学的"模式 |
| **样本偏差** | 示例分布偏离真实任务 |
| **超长 prompt** | 多示例显著增加成本与延迟 |
| **顺序效应** | 示例顺序对结果显著影响 |
| **格式锁定过死** | 模型只会模仿示例格式 |
| **复杂逻辑用示例代替指令** | 应明示规则,不是只摆例子 |

## 与其他概念的关系

- 与 [[零样本提示]] 是同谱系,常对照使用
- 与 [[少样本提示]] 是同义词
- 与 [[上下文学习]] 是父子关系
- 与 [[思维链]]、[[Auto-CoT]]、[[Plan-and-Solve提示]]、[[自一致性]] 协同
- 与 [[结构化输出]]、[[角色提示]]、[[System Prompt]] 协同
- [[元提示]] 用于自动生成 Few-shot 示例
- [[多智能体提示]] 中可用于角色分工示例
- 与 [[RAG]] 接近——动态检索 Few-shot 实质就是检索增强
- 是 [[提示词工程]]、[[提示词工程方法论]]、[[提示词工程五要素]] 的核心模式
- 与微调路径 [[监督微调]]、[[LoRA]]、[[DPO直接偏好优化]] 形成"提示 vs 微调"两条路
