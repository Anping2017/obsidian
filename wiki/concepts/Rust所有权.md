# Rust所有权

## 定义

**所有权(Ownership)** 是 Rust 语言的核心机制——每个值有唯一所有者,所有者离开作用域时值被丢弃(`Drop`)。配合**借用(Borrowing)** 与 **生命周期(Lifetime)** 静态分析,Rust 在编译期保证内存安全(无 use-after-free、double free、null deref)与线程安全(数据竞争编译失败),且零运行时成本(无 GC)。

## 核心要点

- **三条所有权规则**
  1. 每个值有唯一所有者。
  2. 同一时刻只有一个所有者。
  3. 所有者离开作用域,值被 drop。
- **移动语义**:赋值/传参默认按移动(move)转移所有权,源变量失效。基本类型实现 `Copy` trait 后变为按位复制。
- **借用规则**(Borrow Checker)
  - 同一作用域要么有任意多 `&T`(共享借用),要么有唯一 `&mut T`(可变借用),不可同时存在 —— 排除数据竞争的根源。
  - 借用不能比所有者活得更长,否则悬垂引用。
- **生命周期标注**:`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`,告诉编译器返回引用与哪些输入挂钩;多数情况由生命周期省略规则自动推导。
- **智能指针**:`Box<T>`(堆分配)、`Rc<T>`(单线程引用计数)、`Arc<T>`(原子引用计数)、`RefCell<T>`(运行时借用检查) —— 在所有权模型上叠加共享、内部可变性。
- **`unsafe`**:必要时显式声明,绕过借用检查,常见于 FFI、OS 接口、自引用结构;责任转移给程序员证明安全性。

## 关系

- 是 [[内存管理]] 第三条路——既不像 C 手动管理(易出错),也不像 [[Java垃圾回收]] 用 GC(运行时成本),而是编译期所有权静态分析。
- 与 [[并发与并行]] 强相关——`Send`/`Sync` trait 通过类型系统保证跨线程安全。
- [[Rust Trait系统]] 提供面向接口的多态,与所有权深度协同。
- 概念上类似 [[Python上下文管理器]] 的 RAII 思想,但由编译器强制而非运行时约定。
- 影响 [[字节码与中间表示]]——Rust 通过 LLVM 直接编译为本地机器码,无虚拟机层。
- 系统编程领域(Linux 内核、操作系统、嵌入式)选择 Rust 替代 C 的核心理由。
