# 事务隔离级别

## 定义

**事务隔离级别(Isolation Level)** 是 [[ACID事务]] 中"I"的具体实现,定义并发事务之间相互可见性的程度。SQL-92 标准定义四种级别,从低到高分别防护脏读、不可重复读、幻读三类并发异常,代价是并发性能逐级下降。

## 核心要点

- **三类并发异常**
  - **脏读(Dirty Read)**:读到另一未提交事务的修改;若那事务回滚,读到的就是不存在过的数据
  - **不可重复读(Non-repeatable Read)**:同一事务内两次读同一行,值不一样,因为另一事务在中间提交了 UPDATE
  - **幻读(Phantom Read)**:同一事务内两次范围查询,结果集行数变了,因为另一事务在中间提交了 INSERT/DELETE
- **四个标准级别**

| 级别 | 脏读 | 不可重复读 | 幻读 | 性能 |
|---|---|---|---|---|
| 读未提交 Read Uncommitted | 可能 | 可能 | 可能 | 最高 |
| 读已提交 Read Committed | 不可能 | 可能 | 可能 | 高 |
| 可重复读 Repeatable Read | 不可能 | 不可能 | 可能(SQL 标准) | 中 |
| 串行化 Serializable | 不可能 | 不可能 | 不可能 | 最低 |

- **典型数据库默认级别**
  - Oracle / PostgreSQL / SQL Server:**Read Committed**
  - MySQL InnoDB:**Repeatable Read**(且通过 Next-Key Lock 防住幻读,实际接近 Serializable)
- **实现机制**
  - **锁机制**:Serializable 通常用范围锁/谓词锁;较弱级别用行锁 + 间隙锁
  - **MVCC(多版本并发控制)**:每行保留多个版本,读用旧快照、写用最新版本,大幅提升并发;PostgreSQL/InnoDB/Oracle 都用 MVCC
- **InnoDB 特殊机制**
  - **快照读**:普通 SELECT 读 MVCC 快照,无需加锁
  - **当前读**:SELECT...FOR UPDATE / UPDATE / DELETE 读最新版本并加锁
  - **Next-Key Lock = 行锁 + 间隙锁**:锁住索引记录及其前后的间隙,防止其他事务在范围内插入新行,实现 RR 级别下的幻读防护
- **业务层选型建议**
  - 普通 OLTP:RC 足矣,并发好
  - 强一致需求(财务):RR 或 Serializable
  - 报表/分析:可用 RC 甚至 RU,允许些许不一致换性能
- **快照隔离 vs 串行化**
  - **快照隔离(Snapshot Isolation, SI)**:每个事务看到事务开始时的快照,提交时检查写写冲突;PostgreSQL 的"可重复读"实际是 SI
  - **可串行化快照隔离(Serializable Snapshot Isolation, SSI)**:在 SI 基础上检测读写依赖环,达到 Serializable 语义但保留 MVCC 性能;PostgreSQL 9.1+ 的 Serializable

## 和其他概念的关系

隔离级别是 [[ACID事务]] 中"隔离性"的实现谱系。它依赖 [[数据库锁机制]] 与 MVCC 协作。

[[关系型数据库]] 都遵循 SQL 标准定义这四级,但实现细节差异巨大;[[NoSQL数据库]] 多数只提供更弱的最终一致性或单行事务。

在 [[分布式事务]] 场景下,隔离级别的语义会进一步弱化(如 Spanner 的外部一致性、CockroachDB 的 Serializable),涉及 [[CAP定理]] 与 [[一致性模型]] 的取舍。

[[慢查询优化]] 中,过高的隔离级别可能导致锁等待和死锁,需要按业务降级。
