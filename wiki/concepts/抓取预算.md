# 抓取预算

## 定义

**抓取预算(Crawl Budget)** 是 Google 在一定时段(通常一天/一周)对某网站发起的总抓取请求数。Google Webmaster Trends Analyst Gary Illyes 2017 年正式定义,由两个分量决定:

- **Crawl Rate Limit(抓取频率限制)**:服务器响应速度与稳定性决定
- **Crawl Demand(抓取需求)**:URL 数量、更新频率、用户兴趣决定

抓取预算 = min(Crawl Rate Limit, Crawl Demand)

它是 [[企业级SEO]] 的核心议题——只有 **百万级 URL** 的大型电商、新闻站、UGC 站才真正受抓取预算限制,中小站(< 10k URL)几乎不需要担心。

## 核心要点

### 1. 谁需要关心抓取预算

| 站点规模 | 是否需要关心 |
|---|---|
| < 1,000 URL | ❌ 完全不需要 |
| 1k-10k URL | ❌ 一般无需 |
| 10k-100k URL | ⚠️ 大型电商需关心 |
| 100k-1M URL | ✅ 需要管理 |
| > 1M URL | ✅ 核心议题 |

### 2. Crawl Rate Limit 的影响因素

- **服务器响应时间**:< 500ms 优秀,> 2s 严重影响
- **5xx/连接错误率**:Google 自动降速避免压垮站点
- **Search Console 设置**:可手动降低(不能提高)抓取速率
- **Googlebot 智能调度**:根据历史响应自动调整

### 3. Crawl Demand 的影响因素

- **URL 总量**
- **URL 流行度**(链接、流量信号)
- **新鲜度需求**(新闻 vs 静态页)
- **现有索引覆盖度**

### 4. 浪费抓取预算的常见情况

| 浪费源 | 解决方案 |
|---|---|
| **分面导航参数爆炸**(/products?color=red&size=42&...) | URL 参数处理、canonical、robots.txt |
| **会话 ID URL**(/page;jsessionid=...) | 用 cookie 取代 URL session |
| **内部搜索结果页** | robots.txt Disallow |
| **打印版/分享版 URL** | canonical |
| **重复内容** | canonical |
| **404 / 5xx 持续返回** | 修复或 410 |
| **重定向链** | 直接 301 到终点 |
| **被 robots.txt 阻挡的 URL 仍被链接** | 移除站内链接 |
| **大量低价值 UGC 评论页** | noindex + nofollow |

### 5. 优化抓取预算的方法

#### a) Robots.txt 屏蔽

```
Disallow: /search
Disallow: /*?sort=
Disallow: /tmp/
```

#### b) Canonical 集中信号

[[Canonical规范化标签]] 让 Google 把多个相似 URL 合并为一,虽不直接节省抓取但减少索引混乱。

#### c) XML Sitemap 引导

[[XML Sitemap]] 让爬虫优先抓取你认为重要的 URL,而非随机发现。

#### d) 内部链接优化

让重要页面在 [[内链优化]] 中获得更多链接,提升 Crawl Demand。

#### e) 服务器性能

提升 TTFB、减少 5xx 错误,提高 Crawl Rate Limit。

#### f) 删除/合并低质内容

减少总 URL 数,让爬虫预算集中。

#### g) 处理参数

Google Search Console 已不再提供 URL Parameters 工具(2022 弃用),改用 Disallow 或 canonical。

### 6. Search Console 抓取统计报告

- **每天抓取请求数**
- **平均响应大小**
- **平均响应时间**
- **按响应类型/状态码细分**
- **按文件类型(HTML/CSS/JS)细分**
- **按 Googlebot 类型细分**

是诊断抓取预算的核心工具。

## 误区辨析

### 误区 1:"抓取预算 = 索引预算"
不等价。Google 抓取了不一定索引。低质内容仍可能被抓取浪费预算但最终不索引。

### 误区 2:"小站也要关心抓取预算"
< 10k URL 的站基本没有抓取预算问题,Google 几天内就抓完。

### 误区 3:"加 sitemap 就能让 Google 多抓"
Sitemap 引导优先级,不显著增加预算总量。预算上限由服务器与 Demand 决定。

### 误区 4:"屏蔽就能省预算"
Disallow 仅阻止抓取,但 URL 已被发现的话仍然占用 Crawl Demand。最好删除站内链接。

## 当代演进

- **2024 Google 改进抓取**:JS 渲染队列大幅缩短,但仍是预算消耗大头
- **AI 抓取冲击**:GPTBot、Claude-Web 等额外消耗服务器资源,与 SEO 抓取竞争
- **大型电商关键时刻**:产品库百万级时,正确管理抓取预算决定新品何时进入索引
- **HTTP/3 与服务器侧改进**:更高效的协议提高有效 Crawl Rate Limit
