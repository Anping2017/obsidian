# 文件系统

## 定义

**文件系统(File System)** 是 [[操作系统]] 在裸块设备之上构建的命名层次结构与持久化语义,提供文件、目录、权限、元数据的抽象,并负责把这些抽象映射回磁盘块。它是性能、可靠性、一致性多目标博弈的产物。

## 核心要点

- **核心数据结构(Unix 派)**
  - **超级块(Superblock)**:文件系统全局元数据。
  - **inode**:文件的元数据(权限、所有者、大小、块指针),不含文件名。
  - **目录项(Dirent)**:文件名 → inode 编号映射;目录是 dirent 的集合。
  - **数据块(Data Block)**:文件实际内容。
  - **位图 / Extent**:跟踪空闲块。
- **常见 Linux 文件系统**
  - **ext4**:日志型,稳定主流。
  - **XFS**:大文件大空间表现好,Red Hat 默认。
  - **Btrfs / ZFS**:写时复制(CoW),快照、checksum、压缩、RAID。
  - **F2FS**:为闪存优化,Android 大量使用。
  - **tmpfs**:内存文件系统,/tmp 速度极快。
  - **procfs / sysfs**:伪文件系统,内核状态以文件形式暴露。
- **一致性机制**
  - **日志(Journal)**:数据/元数据先写日志再落地,崩溃后重放。
  - **写时复制(Copy-on-Write)**:修改写到新位置,原子翻转指针;天然快照。
  - **fsync**:强制将缓存刷入持久化层;数据库依赖此原语保证 [[ACID事务]] 持久性。
- **性能**
  - **Page Cache**:Linux 把文件缓冲在内存,读重复访问极快;[[零拷贝]] 也建立在此之上。
  - **预读 / 延迟写**:顺序模式优化。
  - **目录索引**:大目录用 hash tree(htree)或 B+树(XFS)避免线性扫描。
- **VFS(Virtual File System)**:Linux 用统一接口抽象不同文件系统,read/write/open 系统调用透明转发。
- **现代趋势**
  - **Persistent Memory(NVDIMM、CXL)**:字节寻址持久内存,DAX 模式绕过 page cache。
  - **FUSE**:用户态文件系统,sshfs/encfs 等实现于其上。
  - **对象存储**:S3、Ceph 把文件系统语义换成 KV,牺牲 POSIX 换扩展性。

## 关系

- 是 [[操作系统]] 提供给应用的核心抽象之一,与 [[I_O模型]] 配合形成持久化基础。
- 数据库 [[ACID事务]] 持久性最终落到文件系统 fsync。
- [[Docker容器]] 镜像基于联合文件系统(OverlayFS) — 多层只读 + 一层可写实现高效共享。
- [[Git版本控制]] 在概念上像微型 CoW 文件系统——内容寻址、树对象、不可变追加。
- [[B+树]] 是文件系统索引(目录、Btrfs/XFS)的常见结构。
