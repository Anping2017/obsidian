# BASE 理论

## 定义

**BASE 理论** 由 Dan Pritchett 在 2008 年提出,是分布式系统对 [[ACID事务]] 的弱化与替代。BASE 是 **B**asically Available(基本可用)、**S**oft state(软状态)、**E**ventually consistent(最终一致)的缩写,故意取与 ACID 化学相反的名字。是 [[NoSQL数据库]]、[[微服务]] 架构、互联网级系统的核心权衡哲学。

## 核心要点

- **三要素**
  - **Basically Available(基本可用)**
    - 出现故障时允许损失部分可用性,核心功能仍能运行
    - 例:大促时关闭部分非核心功能、降级为简版页面
    - 不是"100% 可用",而是"故障时优雅降级"
  - **Soft state(软状态)**
    - 允许系统中存在中间状态,该状态不影响整体可用性
    - 例:订单"处理中"、消息"投递中"、缓存"待刷新"
    - 与 ACID 的"一致性约束实时强制"形成对照
  - **Eventually consistent(最终一致)**
    - 系统经过一段时间后达到一致,期间允许暂时不一致
    - 不要求"任何时刻所有节点看到一样",要求"足够长时间后会一样"
- **BASE vs ACID**

| 维度 | ACID | BASE |
|---|---|---|
| 一致性 | 强一致(实时) | 最终一致 |
| 可用性 | 牺牲可用性求一致 | 优先保可用 |
| 性能 | 中等(锁开销) | 高(无锁、异步) |
| 扩展性 | 单机或小集群 | 大规模分布式 |
| 适用场景 | 金融、订单核心 | 社交、推荐、商品列表 |
| 代表系统 | RDBMS、Spanner | Cassandra、DynamoDB、最终一致 KV |

- **最终一致的实现技术**
  - **异步复制**:主写完即返回,从异步同步,见 [[主从复制]]
  - **消息队列**:写入分发到 [[消息队列]],各服务异步消费
  - **CRDT(无冲突复制数据类型)**:数学上可证明合并不冲突的数据结构
  - **Anti-entropy**:Cassandra 的反熵修复,定期对账修复差异
  - **Read repair**:读到不一致时触发修复
  - **Hinted handoff**:节点临时不可达,数据先存别处,事后转发
- **一致性弱化光谱**
  - 强一致 → 顺序一致 → 因果一致 → 读自己写 → 单调读 → 最终一致
  - 见 [[一致性模型]],BASE 通常指最终一致
- **业务设计要点**
  - **幂等性**:重复执行结果一致,见 [[幂等性]]
  - **补偿机制**:Saga、TCC 中"做错了能撤回",见 [[分布式事务]]
  - **事件溯源(Event Sourcing)**:存储变更事件而非状态,可重放
  - **CQRS**:读写分离架构,写强一致、读最终一致
- **典型场景**
  - **电商商品页**:浏览数 / 评论数最终一致即可,允许几秒延迟
  - **社交时间线**:粉丝几百万,推送有延迟可接受
  - **库存扣减**:核心走 ACID 保证,周边数据(销量统计)走 BASE
  - **微服务跨服务事务**:Saga 模式,失败补偿
- **BASE 的边界**
  - 金融账务、票据、医疗记录等强一致场景仍需 ACID
  - "最终一致"中的"最终"必须有上限(秒级 vs 分钟级,设计前明确)
  - 用户感知:同一会话内的"读自己写"不能违反

## 和其他概念的关系

BASE 是对 [[ACID事务]] 的反面权衡,与 [[CAP定理]] 紧密相关:BASE 是 AP 系统的设计哲学,通过最终一致换取可用性。

[[NoSQL数据库]] 的 Cassandra、DynamoDB、Riak 都是 BASE 的代表实现。其底层多用 [[Quorum]] 协议、[[一致性Hash]] 做分片。

[[微服务]] 跨服务调用普遍接受 BASE 思路,数据一致性靠 [[消息队列]] + [[幂等性]] + 补偿机制保障,而非分布式锁 / 2PC。

[[一致性模型]] 提供了 BASE 与 ACID 之间更精细的中间态(因果一致、读自己写、单调读),工程上常组合使用。

[[分布式事务]] 中的 Saga 模式是 BASE 思想的事务模型代表。
