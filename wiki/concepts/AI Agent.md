# AI Agent

## 定义

**AI Agent(智能体)** 在大模型时代特指以 [[大语言模型]] 为推理核心、能感知环境、规划任务、调用工具、迭代行动以达成目标的自主软件系统。它把 LLM 从被动一次性问答升级为主动、多步、有记忆、能行动的执行者。

## 核心要点

**典型架构(ReAct 模式)**

```
Goal → 思考(Reason)→ 选择动作(Act:调用工具)→ 观察结果 → 思考 → ... → 最终回答
```

**核心组件**

| 组件 | 作用 |
|---|---|
| LLM 推理核心 | [[大语言模型]] 做规划与决策 |
| 工具集 | 由 [[函数调用]]、[[MCP协议]] 暴露的外部能力(搜索、代码执行、API 等) |
| 记忆 | 短期(上下文)、长期(向量库、外部存储) |
| 规划器 | 把高层目标拆成子任务,如 ReAct、Tree of Thoughts、Plan-Execute |
| 评估与反思 | 失败时自检、重试、调整策略 |

**主流形态**

- 对话型 Agent:ChatGPT 高级模式、Claude 等内置工具
- 编码 Agent:Cursor、Claude Code、Devin
- 自动化任务 Agent:浏览器自动化、桌面自动化
- 多 Agent 系统:多个角色化 Agent 协作(如 AutoGen、CrewAI)

**关键工程挑战**

- 错误累积:多步任务中早期错误会被放大,需要好的反思与回退
- 成本与延迟:多次 LLM 调用 + 多次工具调用,容易爆 [[Token]] 和时间预算
- 工具描述质量:模型理解工具能力的能力直接受文档描述质量影响 → [[MCP协议]] 标准化此层
- 安全与权限:Agent 自主行动放大 [[提示注入]] 攻击面,需沙箱、人在回路审批
- 评估难:开放任务无法标准化,业界尝试 SWE-bench、WebArena 等基准

**与传统 [[强化学习]] Agent 的差异**

- 经典 RL Agent 通过试错学习策略
- LLM Agent 直接利用预训练通识 + ICL,几乎无须任务专属训练
- 二者结合趋势:[[RLHF]] 后再用 RL 训练 Agent 使用工具的策略

## 和其他概念的关系

- 主流框架实现见 [[AI Agent框架]](LangChain、AutoGPT 等)

- 核心引擎:[[大语言模型]] 提供推理与决策
- 工具接口:[[函数调用]]、[[MCP协议]]
- 知识层:[[RAG]] 提供动态知识检索
- 历史背景:[[强化学习]] 中"Agent"的概念被 LLM 时代重新诠释
- 安全维度:[[提示注入]] 在 Agent 场景下风险被显著放大
- 上下文管理:对 [[上下文窗口]]、[[Prompt Caching]] 高度敏感
- 软件架构对应:Agent 与各工具的解耦本质上是 [[微服务]] 思想的 AI 版;ReAct 循环更接近 [[函数式编程]] 的纯输入到输出推导;多步规划、反思、回退等模式与传统 [[设计模式]](策略、状态机、责任链)高度同构
