# MVP 最小可行产品

## 定义

**MVP**(Minimum Viable Product,**最小可行产品**)是 Eric Ries 在 2011 年出版的《精益创业》(*The Lean Startup*)中系统化的概念,指**用最少的工作量做出能让团队完成一轮"构建—测量—学习"(Build-Measure-Learn)循环的产品形态**。

MVP 的关键不在"产品多简单",而在**"是否能用最低成本验证最关键的商业假设"**。它是 [[精益创业]] 方法论的核心实践工具。

> "The minimum viable product is that version of a new product which allows a team to collect the maximum amount of validated learning about customers with the least effort." —— Eric Ries

## 核心要点

### MVP 的三个核心要素

1. **Minimum(最小)**:仅包含验证假设必须的功能,砍掉一切非必要
2. **Viable(可行)**:仍能为用户提供真实价值,可以测量真实反馈
3. **Product(产品)**:不一定是软件,可以是着陆页、视频、原型、人工服务

### 与传统产品开发的对比

| 维度 | 传统瀑布开发 | MVP 模式 |
|---|---|---|
| 假设 | 知道用户要什么 | 不确定,需验证 |
| 启动条件 | 完整规划 / 完整产品 | 最小可学习单元 |
| 度量 | 进度 / 功能完成度 | 学习速度 / 验证假设数 |
| 失败成本 | 一次性、巨大 | 持续、小额 |
| 时间 | 9–18 个月发布 | 数周到数月 |

### MVP 的主要形态

| 形态 | 说明 | 典型场景 |
|---|---|---|
| **着陆页** | 描述未来产品,看转化率 | 测试需求是否存在 |
| **视频** | 演示尚未存在的功能 | Dropbox 早期 demo |
| **绿野仙踪 MVP** | 用户以为是软件,后端是人工 | 早期 Zappos:店主到鞋店拍照 |
| **Concierge MVP** | 公开承认人工服务 | 早期 Airbnb:创始人亲自接待 |
| **单功能版** | 仅一个核心功能的产品 | 早期 Instagram 仅拍照分享 |
| **众筹** | 预购验证 | Pebble、Oculus |

### 经典案例

- **Dropbox**:用一个 3 分钟视频展示同步功能,等待列表从 5,000 涨到 75,000,验证需求
- **Zappos**:Nick Swinmurn 拍下当地鞋店照片放网上,有人买就去店里购买寄出
- **Airbnb**:三位创始人把自家充气床垫租给设计大会参会者,验证陌生人是否愿付费住别人家
- **Buffer**:两页着陆页(功能描述 + 价格)收集邮箱,验证付费意愿后再开发

### MVP 不是什么

| 误解 | 正解 |
|---|---|
| MVP = bug 多的产品 | MVP = 功能极简但体验完整 |
| MVP = 给产品经理看的原型 | MVP = 面向真实用户的可行产品 |
| MVP 上线就完成 | MVP 是循环的起点,需配套测量 |
| 越小越好 | 太小无法验证假设,要"刚好可学习" |
| MVP 适用一切 | 不适用医疗、航空、高合规等场景 |

### 与"构建-测量-学习"循环

```
构想 → 构建 MVP → 上线 → 测量数据 → 学习 → 转向 / 坚持
```

每个循环回答一个具体假设:用户是否存在、是否愿意为此付费、是否能持续使用。

### 创新会计与转向(Pivot)

- **创新会计**(Innovation Accounting):用核心比率衡量学习速度,而非营收
- **转向**(Pivot):基于 MVP 学习证据,系统性改变战略而非战术(目标客户、问题、平台、渠道)

## 应用场景

- 初创公司验证核心假设
- 大公司新产品 / 新业务线孵化
- 内部工具开发(先做最薄版本)
- 数字化转型(避免大爆炸式上线)
- 个人产品 / Indie hacker 验证

## 局限与陷阱

- **MVP 思维偏向 B2C / 软件**:不适用复杂硬件、医疗设备
- **品牌风险**:为大品牌发布"最小"产品可能损害品牌
- **质量陷阱**:把"低质量"当 MVP,失去用户信任
- **假学习**:数据没有覆盖真实假设,看似"学到了"实则误读
- **永远 MVP**:不愿迈入真正产品阶段,持续迭代假设
- **平台约束**:某些平台(企业 SaaS)对最小产品的容忍度低
- **网络效应需要规模**:平台型业务的 MVP 难以单边启动
