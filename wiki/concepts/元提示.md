# 元提示

## 定义

**元提示**(Meta-prompt / Meta-prompting)是一种"**提示用于生成提示**"的提示工程范式。它通过元层面的指令,让 LLM 自动设计、改写、优化针对具体任务的 prompt,而非直接执行任务。元提示的精神类似元编程(meta-programming):用代码生成代码。在 LLM 时代,它让"prompt 设计"从手工艺变成可工程化、可迭代、可自动化的工作。

## 核心要点

### 三种主要应用方向

#### 1. Prompt 生成(Prompt Generation)

给定任务描述,让 LLM 生成 prompt:

```
[Meta-prompt]
你是 prompt 工程专家。请为以下任务设计一个高质量的 prompt:
任务:把法律合同总结为 200 字,突出关键条款。

要求:
- 包含明确的角色定位
- 包含输出格式要求
- 包含 1-2 个示例
- 处理边界情况(如合同太长)

请输出 prompt:
```

#### 2. Prompt 优化(Prompt Optimization)

给定现有 prompt + 失败案例,让 LLM 改进:

```
[Meta-prompt]
以下 prompt 在 X 类输入上失败。请分析原因并改进:

原 prompt: ...
失败例: ...
预期: ...
实际: ...

请输出改进后的 prompt 与改进解释。
```

#### 3. Prompt 评估(Prompt Evaluation)

让 LLM 评判多个 prompt 的优劣:

```
[Meta-prompt]
比较以下 3 个 prompt 在任务 Y 上的优劣:
Prompt A: ...
Prompt B: ...
Prompt C: ...

按以下维度打分:
- 清晰度 / 完整性 / 鲁棒性 / 简洁度
- 综合排序与推荐
```

### 主要范式

#### APE(Automatic Prompt Engineer)

Zhou 等 2022 提出,核心步骤:
1. 给若干输入-输出例子
2. 让 LLM 生成 N 个候选 prompt
3. 在验证集上测试每个 prompt
4. 选最佳

发现:LLM 自己生成的 prompt 常超人类手工设计。

#### OPRO(Optimization by PROmpting)

Yang 等 2023 提出:
1. 维护 prompt 库与对应表现
2. 让 LLM 看到历史 prompt + 分数
3. 生成更好的新 prompt
4. 测试加入库
5. 迭代收敛

#### PromptBreeder(Fernando 2023)

进化算法 + LLM:
- 突变(由 LLM 生成变体)
- 交叉(融合两个 prompt)
- 选择(用任务表现做适应度)

#### Constitutional AI 的 self-critique

Anthropic 2022:让模型自我批判并修正,本质是元提示。

### 经典案例

**任务**:文本分类
- 人类 prompt(直觉):"请分类以下文本为 A/B/C..."
- APE 生成的 prompt:"请仔细阅读文本,识别其核心意图,然后从 A、B、C 中选择最贴切的类别。优先考虑..."
- 提升:准确率 + 5-15%

**任务**:数学推理 GSM8K
- 标准 CoT:"Let's think step by step"
- APE 优化后:"Let's work this out in a step by step way to be sure we have the right answer"
- 提升:准确率 + 几个百分点

### 主要应用

#### 自动化 prompt 设计

- 大企业 prompt 库管理
- 跨任务 prompt 模板生成
- 多语言 prompt 适配

#### Prompt 库版本管理

- 自动 A/B 生成 prompt 变体
- 持续优化生产 prompt
- 见 [[提示词版本管理]]

#### 多 agent 编排

- Manager-Worker 模式
- Manager 用元提示动态生成 worker 的 prompt

#### 学习率调整(LLM 训练)

- 用 meta-prompt 调控 fine-tuning 数据生成

### 设计原则

**给 meta-prompt 提供**:
1. **任务上下文**:具体场景、用户特征
2. **目标定义**:成功标准、KPI
3. **约束条件**:长度、风格、token 限制
4. **示例**:好 prompt 长什么样
5. **评估标准**:产出 prompt 如何被衡量

### 主要挑战

- **递归依赖**:meta-prompt 本身需要设计
- **评估循环**:谁评估元提示生成的 prompt 是否真的好
- **过度自动化**:可能丢失人工 prompt 工程师的领域直觉
- **token 成本**:多轮 prompt 生成 + 评估很贵
- **稳定性**:LLM 输出有随机性,自动 prompt 也波动

### 实战工具

- **DSPy(Stanford)**:声明式 prompt 编程,自动优化
- **PromptLayer / LangSmith**:prompt 实验与版本
- **Guidance / LMQL**:结构化 prompt 控制
- **Anthropic Prompt Generator**:自动从任务描述生成 prompt

### 与其他范式的关系

| 范式 | 焦点 | 与元提示关系 |
|---|---|---|
| Few-shot | 示例 | 元提示可生成 few-shot 的"示例选择" |
| CoT | 推理 | 元提示可生成 task-specific CoT 触发语 |
| ReAct | 工具 | 元提示可生成 ReAct 模板 |
| Self-Consistency | 投票 | 元提示可生成多样化 prompt 提供投票材料 |
| ToT | 树搜索 | 元提示可生成树节点的"思维生成"prompt |

### 主要趋势

- **LLM-as-Optimizer**:把 LLM 用于经典优化(超参、prompt、模型选择)
- **Self-Improving LLM**:模型自己生成训练数据 + 自我评估,渐近自我改进
- **Constitutional & Specification-driven**:让用户写规则,模型自动生成符合规则的 prompt
- **Personalized Prompting**:基于用户画像动态生成 prompt

## 和其他概念的关系

元提示是 [[提示词工程]] 的元层面方法,与 [[少样本提示]]、[[思维链]]、[[ReAct提示]]、[[思维树]] 等具体技术的关系是"用元提示自动生成或优化这些技术的具体 prompt"。它与 [[提示词版本管理]]、[[提示词工程方法论]] 直接关联。它与 [[Reflexion]] 在"自我改进"思路上相通,但元提示更侧重 prompt 本身的优化,Reflexion 更侧重任务执行的迭代。它在 [[大语言模型应用栈]] 中支撑 prompt 工程化层的自动化。
