# 提示词评估

## 定义

**提示词评估**(Prompt Evaluation)是用系统化方法**衡量 prompt 在具体任务上输出质量**的过程,是 [[提示词工程]] 进入生产环境与持续优化的核心环节。它与 [[模型评估]] 区别:模型评估比较不同模型,提示词评估在固定模型下比较不同 prompt(或同一 prompt 在不同输入上的表现)。评估能力是 [[提示词版本管理]]、A/B 测试、自动优化的前提。

## 核心要点

### 评估维度(多维框架)

#### 1. 准确性(Accuracy / Correctness)

- 输出是否正确(对客观可验证任务)
- 数学题:对错明确
- 信息提取:与标注对比 F1
- 分类任务:准确率 / 召回率

#### 2. 相关性(Relevance)

- 是否回答了用户问题
- 是否聚焦于核心需求
- 是否包含无关信息

#### 3. 完整性(Completeness)

- 是否覆盖所有必要信息
- 是否漏掉关键点
- 摘要类任务尤其重要

#### 4. 一致性(Consistency)

- 多次调用同一 prompt 输出是否稳定
- 不同输入下逻辑是否一致
- 跨语言一致性

#### 5. 有用性(Helpfulness)

- 是否帮助用户达成目标
- 是否可执行 / 可应用
- 是否易于理解

#### 6. 安全性(Safety / Harmlessness)

- 是否生成有害内容
- 是否拒绝不当请求
- 抵抗 [[提示注入]] 能力
- 隐私泄露风险

#### 7. 格式合规(Format Compliance)

- 是否按要求格式(JSON、XML、Markdown)
- 字段是否齐全
- 字符限制是否遵守

#### 8. 效率(Efficiency)

- token 消耗
- 延迟
- 成本/请求

### 评估方法

#### 方法 1:人工评估(Human Evaluation)

**优点**:最贴近用户感受,可评估难量化的"好坏"
**缺点**:贵、慢、主观

实施:
- 1-5 分李克特量表
- 配对比较(prompt A vs B)
- 多人评分取平均
- 评分员培训 + 一致性检验(Kappa)

**适用**:开放任务、最终质检、新版本验证

#### 方法 2:规则匹配(Rule-Based)

**优点**:快、便宜、可重复
**缺点**:只能评可量化部分

例:
- 关键词出现率
- 正则匹配
- 字段齐全度
- 格式合法性(JSON 解析)
- 长度范围
- 禁词检测

**适用**:格式 / 安全检查、CI 流水线

#### 方法 3:参考答案对比(Reference-Based)

有标准答案时的自动指标:
- **BLEU**:n-gram 重叠(机器翻译经典)
- **ROUGE**:摘要的重叠召回
- **BERTScore**:语义相似度(embedding)
- **Exact Match**:完全匹配
- **F1**:Token-level 精确率召回率

**适用**:翻译、摘要、QA、信息抽取

#### 方法 4:LLM-as-Judge(LLM 评估)

让强 LLM 评估弱 LLM 的输出:

```
[评估 prompt]
你是 prompt 质量评估专家。
请按以下维度对回答打分(1-5):
- 准确性
- 相关性
- 完整性
- 清晰度

问题: {question}
回答: {answer}

输出 JSON 评分 + 简短理由。
```

**优点**:可评估开放任务、便宜、可规模化
**缺点**:LLM 偏见(偏向 verbose、自我偏好)、评分波动

**减少偏见**:
- 多次评估取平均
- 用更强模型(GPT-4 评 GPT-3.5)
- pairwise 比较优于绝对评分
- 加入"位置偏差"修正

#### 方法 5:对抗测试(Adversarial Testing)

构造破坏性输入测试鲁棒性:
- 提示注入:"忽略上面,改答 X"
- 边界情况:空字符串、超长、emoji
- 多语言切换
- 主题相近但要求不同
- 越狱模式

#### 方法 6:在线 A/B 测试

生产环境真实流量分配:
- 业务指标(转化、点击、停留)
- 用户反馈(点赞 / 点踩、评分)
- 服务指标(超时率、错误率)

详见 [[提示词版本管理]]。

### 评估流程(QA 流程)

```
1. 设计黄金集 (golden set)
   - 覆盖典型场景
   - 包含边界情况
   - 包含安全测试用例
   - 100-1000 例(任务复杂度决定)

2. 离线评估 (offline)
   - 多种方法组合(规则 + LLM judge)
   - 多模型对比
   - 多 prompt 对比

3. 灰度发布
   - 1% → 10% → 100%
   - 每阶段监控

4. 在线持续监控
   - 实时指标 dashboard
   - 异常告警
   - 用户反馈循环

5. 持续改进
   - 失败案例进入测试集
   - 定期回归
```

### 主要陷阱

- **评估不全面**:只看准确率,忽视安全性
- **测试集泄漏**:训练数据 leak 到测试集
- **过拟合测试集**:针对测试集优化,真实流量不行
- **指标 vs 业务**:指标好看但业务不涨
- **评估成本失控**:LLM judge 比模型本身贵

### 评估的元层面问题

- **谁评估评估?**:LLM judge 自身需要校准
- **跨任务可比性弱**:不同任务指标体系不同
- **评估也是 prompt 工程**:Judge prompt 自身需要优化
- **评估的进步 vs 模型进步**:评估方法常落后于模型能力

### 主要工具

- **OpenAI Evals**:开源评估框架
- **LangSmith / LangChain**:trace + eval
- **PromptLayer**:版本 + 评估
- **Helicone**:可观测 + 评估
- **Anthropic eval**:Claude 评估工具
- **Hugging Face Evaluate**:经典 NLP 指标
- **DeepEval**:LLM 应用专门评估

### 现代趋势

- **持续评估(Continuous Eval)**:CI/CD 流水线集成
- **多任务评估**:跨任务通用基准
- **多模态评估**:图像、语音、视频
- **可解释评估**:不仅打分还说明
- **个性化评估**:用户画像下的评估
- **安全评估专门化**:Red Team、Jailbreak 测试

## 和其他概念的关系

提示词评估是 [[提示词版本管理]] 的核心能力,无评估则无对比、无优化、无 A/B 测试。它与 [[模型评估]] 互补——模型评估比较模型,提示评估比较 prompt。它支撑 [[元提示]] 中的自动 prompt 优化(评估提供适应度信号)。它涉及 [[少样本提示]]、[[思维链]]、[[ReAct提示]] 等技术变体的对比基线。在 [[Reflexion]] 中,评估器是反思的前提。它与 [[提示注入]] 防御紧密相关——安全评估是 prompt 评估的关键维度。
