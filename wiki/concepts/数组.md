# 数组 Array

## 定义

**数组**是把**相同类型**元素按下标(索引)线性排列的[[数据结构]],元素物理上**连续存储**于内存中。第 i 个元素地址 = 起始地址 + i × 元素大小,因此根据下标定位的代价是 **O(1)**(常数时间随机访问)。

数组分两类:
- **静态数组**:声明时确定容量,运行期不可改(如 C 的 `int a[100]`)
- **动态数组(Dynamic Array)**:支持自动扩容,如 C++ `vector`、Java `ArrayList`、Python `list`、Go `slice`

## 核心要点

### 操作复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 随机访问 a[i] | O(1) | 地址计算 |
| 末尾追加 push_back | 摊还 O(1) | 偶尔扩容 O(n) |
| 末尾删除 pop_back | O(1) | |
| 中间插入/删除 | O(n) | 需要搬移后续元素 |
| 按值搜索 | O(n) | 无序数组 |
| 二分搜索 | O(log n) | 有序数组,见[[二分查找]] |

### 动态数组扩容策略

容量满时按 2 倍(C++/Java)或 1.5 倍(Go slice)扩容:
- 申请新内存 → 拷贝旧元素 → 释放旧内存
- **摊还分析**:n 次 push_back 总代价 O(n),平均每次 O(1)
- 扩容因子取舍:2 倍空间利用率较低(平均 50%)但实现简单;1.5 倍空间利用率高且利于内存复用

### 多维数组的内存布局

二维数组在内存中按**行主序(C/C++/Python)**或**列主序(Fortran/MATLAB)**展平。访问模式应顺着主序方向以利用 CPU 缓存(参见[[缓存]])。

### 数组的优势与代价

**优势**:
- 缓存命中率高,实际运行远快于理论复杂度相同的链式结构
- 内存紧凑,无指针开销
- 易于并行/向量化(SIMD)

**代价**:
- 中间插入/删除昂贵(O(n))
- 容量固定或扩容代价
- 大数组分配可能触发系统调用、产生内存碎片

## 和其他概念的关系

数组是[[链表]]的"对照面",二者代表了内存布局的两种范式:连续 vs 分散。许多更高层的[[数据结构]]都基于数组实现:[[Hash表]]的桶数组、[[堆]]用数组隐式表示完全二叉树、动态数组栈实现、字符串(本质是 char 数组)。

[[排序算法]]中绝大多数针对数组设计(快排、堆排、归并)。[[二分查找]]要求数组有序。[[字符串匹配]]中的 KMP、Boyer-Moore 操作字符数组。

数据库底层的页(Page)、列存(Columnar Storage)本质都是数组,因为数组的顺序访问性能在大规模数据上具决定性优势。
