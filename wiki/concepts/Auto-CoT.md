# Auto-CoT

## 定义

**Auto-CoT**(Automatic Chain-of-Thought, Zhang 等 **2022** 论文《Automatic Chain of Thought Prompting in Large Language Models》)是一种**自动构建 [[思维链]] few-shot 示例**的提示工程技术,核心是**通过对问题集聚类、对每个簇用零样本 CoT 生成推理链,然后挑选作为 few-shot 示例**,从而免去人工编写示例的成本。它解决了"手写 CoT 示例费时费力 + 易选不当"的问题,是把 CoT 推向产品化的关键自动化技术。

## 核心要点

### 背景:Manual-CoT 的成本问题

经典 [[少样本提示]] CoT(Wei 等 2022):
- 在 prompt 中手工写若干"示例题 + 推理链 + 答案"
- 然后让模型对新问题模仿
- 8 个示例典型(GSM8K 标准设置)

**问题**:
- 需要专家手写示例(每个领域都要)
- 不同任务示例不同,工作量大
- 示例选择影响巨大,选不当效果反差
- 无法规模化

### Auto-CoT 流程

#### 步骤 1:问题聚类(Question Clustering)

从问题库中:
1. 用 Sentence-BERT 把每个问题编码为向量
2. K-means 聚成 K 个簇(K = 想要的示例数,通常 8)
3. 每个簇代表一类问题模式

#### 步骤 2:示例选择(Example Selection)

每个簇中:
- 选离簇心最近的问题
- 启发式过滤过长 / 异常问题
- 得到 K 个代表性问题

#### 步骤 3:零样本 CoT 生成推理链

对每个代表问题:
- 用零样本 CoT prompt:"Let's think step by step"
- 让模型生成完整推理链 + 答案
- 不验证答案对错(关键!)

#### 步骤 4:组合 few-shot prompt

把 K 对(问题, 推理链, 答案)组合为 few-shot:

```
Q: ... A: Let's think step by step. ... So the answer is ...
Q: ... A: Let's think step by step. ... So the answer is ...
[K 个示例]

Q: {新问题}
A: Let's think step by step.
```

### 为何不验证答案对错

直觉上应该筛掉错误推理。但 Zhang 等发现:
- **多样性 > 准确性**
- 即使示例答案错,只要推理过程展示"如何思考",就能引导新问题正确推理
- 强行筛对反而让示例风格趋同,限制模型推理多样性

这是反直觉但实证支持的发现。

### 实证表现

Zhang 等 2022 在 10 个推理基准上:

| 任务 | Zero-Shot | Manual-CoT | Auto-CoT |
|---|---|---|---|
| GSM8K | 40.7 | 46.9 | 47.9 |
| AQuA | 33.5 | 35.8 | 36.5 |
| StrategyQA | 53.8 | 65.4 | 65.4 |
| MultiArith | 78.7 | 91.7 | 92.0 |

Auto-CoT **匹敌或略超** 手工 Manual-CoT,但**完全自动化**——这是关键贡献。

### 与其他自动化方法对比

| 方法 | 自动化 | 多样性 | 成本 |
|---|---|---|---|
| Manual-CoT | 人工 | 中(取决于人) | 人工成本 |
| Random-CoT(随机选) | 是 | 高 | 低 |
| Retrieval-CoT(检索相似) | 是 | 低(同质) | 低 |
| **Auto-CoT** | 是 | 高(聚类保证) | 低 |
| Self-Generated CoT | 是 | 高 | 中(每问都生成) |

Auto-CoT 在多样性 vs 成本上平衡最佳。

### 关键技术细节

#### 聚类的重要性

简单随机选示例:多样性不足,可能选到几个相似题
聚类:保证示例覆盖问题类型空间,具有代表性

#### 启发式过滤

- 过滤异常长(token > 60)的问题
- 过滤过短的问题(< 5 tokens)
- 这是工程上的经验调整

#### 模型依赖

Auto-CoT 在 GPT-3 175B 上效果好。在小模型上(< 10B)效果有限——这是 CoT 整体的"涌现能力"特征。

### 主要应用

#### 任务自动化

不需要为每个新任务手写示例:
- 客服:从历史问答抽取
- 代码:从 GitHub issue 抽取
- 教育:从题库抽取
- 医疗:从病例抽取

#### 多领域 prompt 模板生成

公司有数百种使用场景,每种手写不现实,Auto-CoT 可大规模批量生成。

#### 与 RAG 结合

- 检索相关问题作为示例
- 用 Auto-CoT 自动生成推理链
- 比纯检索 + 答案更稳健

### 主要变体

#### LM-Generated Examples

不依赖现成问题库,直接让 LLM 生成"模拟问题":
- 给一个种子问题
- LLM 生成 K 个变体
- 每个变体生成 CoT 推理

#### Active Auto-CoT

迭代改进:
- 先用 Auto-CoT
- 找出失败案例
- 把失败案例加入示例池
- 重新聚类、选择

#### Self-Consistency + Auto-CoT

- Auto-CoT 生成 prompt
- 用 [[自一致性]] 多采样投票
- 双重提升

### 主要局限

- **依赖问题库**:没有问题集时无法用
- **聚类质量影响大**:K 选不当或聚类失误效果下降
- **零样本 CoT 错误"放大"**:示例错较多时仍可能误导
- **不能动态适应新问题类型**:静态生成,新型问题需重新聚类
- **跨语言效果不一**:在中文等小语种上需特别处理

### 现代发展

- **DSPy(Stanford)**:更系统的 prompt 优化框架,Auto-CoT 是其中一种策略
- **多模态 Auto-CoT**:图像 + 文字的自动 CoT 示例
- **领域适应 Auto-CoT**:针对特定领域微调
- **强化学习 + Auto-CoT**:用任务表现反馈选择更好的示例

### 实战工具

- **原作者 GitHub**:`amazon-science/auto-cot`
- **LangChain ExampleSelectors**:实现类似聚类选择
- **PromptBench**:评估 Auto-CoT 等方法

### 哲学思考

Auto-CoT 揭示了一个有趣事实:**LLM 自己生成的"教学示例"和人类专家写的几乎一样好**。这意味着:
- LLM 内部已经有"如何教"的隐性知识
- 人类的"prompt 工程师"角色可被部分自动化
- 但人类仍需在元层面设计与监督这一过程(选择哪些任务、聚类参数等)

## 和其他概念的关系

Auto-CoT 是 [[思维链]](CoT)+[[少样本提示]] 的自动化升级,免去人工示例编写。它与 [[元提示]] 在思想上相近——都是让 LLM 自动化 prompt 工程。它与 [[自一致性]] 在不同维度互补——SC 是多采样投票,Auto-CoT 是多样化示例选择。它与 [[Plan-and-Solve提示]] 都关注"如何让 CoT 更可靠"但路径不同。它在 [[提示词版本管理]] 中可作为"批量生成 prompt 模板"的工具。它属于 [[提示词工程方法论]] 中"工程化、自动化"原则的具体技术。
