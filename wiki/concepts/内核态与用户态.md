# 内核态与用户态

## 定义

**内核态(Kernel Mode / Ring 0)** 与 **用户态(User Mode / Ring 3)** 是 CPU 提供的特权级别。**内核态** 可执行所有指令、访问全部硬件;**用户态** 受限——不能直接 I/O、不能修改页表、不能改中断向量。应用必须通过**系统调用(System Call)** 陷入内核请求服务。这层硬件级隔离是 [[操作系统]] 安全与稳定的根本。

## 核心要点

- **特权级机制**
  - x86 提供 Ring 0-3,Linux/Windows 实际只用 0(内核)与 3(用户)。
  - ARM 用 EL0/EL1/EL2(Hypervisor)/EL3(Secure Monitor)。
  - CPU 在切换时检查段选择子或 CR0 等寄存器。
- **系统调用机制**
  - 用户态发起:`syscall` 指令(x86_64)、`svc`(ARM)、传统 `int 0x80`。
  - 内核态:校验参数 → 派发到对应实现 → 写返回值 → 恢复用户态。
  - 切换代价:寄存器保存/恢复、TLB 部分失效、缓存污染——几百纳秒。
- **常见系统调用**
  - 进程:fork、execve、wait、kill、clone(线程)。
  - 内存:brk、mmap、munmap、mprotect。
  - I/O:read、write、open、close、stat、lseek。
  - 同步:futex、semop、sigaction。
  - 网络:socket、bind、connect、listen、accept、send/recv。
- **优化技术**
  - **vDSO**:把高频只读系统调用(gettimeofday、time)映射进用户空间,避免陷入。
  - **io_uring**:批量系统调用 + 共享环形缓冲,减少陷入次数。
  - **eBPF**:用户态注入字节码到内核执行,跳过反复切换。
- **隔离的代价与突破**
  - DPDK / 内核旁路:为极致性能,把网卡操作放回用户态,牺牲安全换吞吐。
  - 容器与虚拟机:在内核态加更细粒度隔离。
- **典型攻击面**:Spectre/Meltdown 利用乱序执行 + 缓存侧信道泄露内核数据;系统调用成为安全审计核心点。

## 关系

- 是 [[操作系统]] 设计的核心抽象,影响一切应用层架构。
- [[I/O模型]]、[[零拷贝]]、[[Epoll与Kqueue]] 的性能差异多源自系统调用次数。
- [[Docker容器]] 共享宿主内核——容器进程仍走同一组系统调用,但被 namespace/cgroup 限制视图。
- [[DPDK与内核旁路]]、io_uring 是减少切换的两条路径。
- [[Web安全]]:内核漏洞影响所有进程,用户态隔离是最后一道防线。
