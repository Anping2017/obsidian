# 元编程 Metaprogramming

## 定义

元编程(Metaprogramming)是 **「程序作为数据被另一程序操纵」** 的技术。它包括:

- **代码生成**:在编译期或运行期生成代码
- **代码反射**:程序在运行期检查自身结构(类型、字段、方法)
- **代码改写**:在编译期或加载期修改代码
- **领域特定语言(DSL)**:用宿主语言构建小型专用语言

其本质是把代码从「执行的指令」提升为「可操作的数据」,使程序能够「编程编程本身」。

## 核心要点

### 不同语言的元编程风格

| 语言 | 主要机制 | 特点 |
|---|---|---|
| Lisp / Clojure | 宏(同象性) | 代码即数据,最纯粹元编程 |
| C++ | 模板元编程(TMP)、constexpr、宏 | 编译期复杂计算,但语法繁琐 |
| Rust | 宏(macro_rules!、procedural macros) | 强类型、安全的代码生成 |
| Python | 装饰器、metaclass、`__getattr__`、`exec`/`eval` | 灵活但易滥用 |
| Ruby | `method_missing`、open classes、Module#define_method | 极致动态,Rails 大量使用 |
| JavaScript | Proxy、Reflect、Decorators、AST 工具(Babel) | 运行期 + 构建期均可 |
| Java | 反射、注解处理器(APT)、字节码改写(ASM) | 运行期反射 + 编译期注解 |
| TypeScript | 条件类型、模板字面量类型、装饰器 | 类型层面的元编程 |
| Scala / Haskell | 隐式参数 / Template Haskell | 编译期生成 |

### 编译期 vs 运行期

| 维度 | 编译期 | 运行期 |
|---|---|---|
| 性能 | 零运行开销 | 反射通常较慢 |
| 类型安全 | 通常保留 | 常需运行时检查 |
| 灵活度 | 受限于编译信息 | 完整动态行为 |
| 调试难度 | 错误信息差,出错难定位 | 与一般代码相同 |
| 代表 | C++ TMP、Rust 宏、TS 类型 | Java 反射、Python 装饰器 |

### 典型应用场景

1. **ORM**:把类映射为数据库表(SQLAlchemy、Hibernate、TypeORM)
2. **依赖注入容器**:Spring、NestJS 通过装饰器/注解
3. **测试框架**:JUnit、pytest 通过反射发现测试
4. **序列化**:Jackson、Gson、Pydantic 反射读字段
5. **Web 框架路由**:`@app.get('/path')` 装饰器
6. **代码生成**:Protobuf、GraphQL Codegen
7. **AOP 切面编程**:日志、事务、权限拦截
8. **DSL**:RSpec、HTML/CSS 模板引擎

### Python 装饰器例

```python
def cached(func):
    cache = {}
    def wrapper(*args):
        if args in cache:
            return cache[args]
        result = func(*args)
        cache[args] = result
        return result
    return wrapper

@cached
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
```

`@cached` 是元编程——`cached` 把 `fib` 当数据接收并返回新函数。

### Lisp 宏(最纯粹元编程)

```lisp
(defmacro unless (test &body body)
  `(if (not ,test)
       (progn ,@body)))
```

宏在编译期把 `(unless x ...)` 改写为 `(if (not x) (progn ...))`,把语言扩展为新结构。Lisp 的同象性(代码 = 数据)使元编程极其优雅。

### TypeScript 类型层元编程

```typescript
type Capitalize<S extends string> =
  S extends `${infer F}${infer R}` ? `${Uppercase<F>}${R}` : S;

type Result = Capitalize<'hello'>;  // 'Hello'
```

TS 类型系统是图灵完备的小型语言,可在类型层级做模式匹配、递归。

### 风险与代价

- **可读性**:看似简洁实则复杂,新人难懂
- **调试难**:错误堆栈跨层级
- **性能**:运行期反射通常慢
- **维护性**:过度元编程让代码「魔法化」
- **工具**:IDE 静态分析常失效

业界共识:**先用普通代码,确实需要时才用元编程**。

## 和其他概念的关系

元编程的理论根基在 [[编译原理]] 与 [[函数式编程]] 中——AST、宏展开、类型系统都源于这些领域。Lisp 与 Haskell 是元编程哲学的源头。

[[泛型编程]] 与元编程紧密相关——C++ 模板、Rust 泛型本质是「类型层面的元编程」;TypeScript 把类型层元编程推向极致。

[[设计模式]] 中很多「模式」其实是缺乏元编程能力语言的补丁——如装饰器模式在 Python 中由原生 `@` 替代;策略模式在函数式语言中只是高阶函数。

[[依赖倒置]]、[[控制反转]] 在元编程支持下大幅简化——Spring/NestJS 框架的核心就是用注解 + 反射实现 IoC 容器。

[[逃逸分析]]、[[JIT编译]] 等运行时优化技术与元编程都涉及「程序对程序的操作」,共享理论基础。
