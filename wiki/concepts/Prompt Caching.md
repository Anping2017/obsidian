# Prompt Caching

## 定义

**Prompt Caching(提示词缓存)** 是 [[大语言模型]] 推理优化技术:把固定不变的 prompt 前缀的中间计算(主要是 KV Cache)缓存下来,在后续含相同前缀的调用中复用,从而大幅降低延迟与计费成本。Anthropic、OpenAI、Google 均已商业化支持。

## 核心要点

**适用场景**

- 长系统提示 + 频繁短查询(客服机器人、IDE 助手)
- 多轮对话中前几轮已稳定,只追加新轮
- [[RAG]] 中大段固定指南 + 检索片段变化
- [[少样本提示]] 中长固定示例 + 新问题
- [[AI Agent]] 中工具描述部分长且固定

**节省幅度**

- 通常缓存命中部分计费降至 1/10(具体厂商 0.05x-0.5x)
- 延迟降低,首 token 时间(TTFT)显著缩短
- 输入 [[Token]] 越多、调用越频繁,收益越大

**工作机制**

- LLM 推理时每个 token 在每层产生 KV(Key-Value)向量,存入 KV Cache 用于后续 token 计算
- 对相同前缀,KV Cache 计算结果完全确定
- 厂商在服务端识别 prompt 前缀重复并复用 KV Cache

**约束**

- 缓存有 TTL(常 5 分钟-1 小时),长期不用会失效
- 必须从 prompt 起点开始的连续前缀
- 对 prompt 中变量插入位置敏感:固定内容应放前段,变量放后段
- 模型版本切换会使缓存失效

**工程实践**

- 把"系统指令 + 工具列表 + 长文档"这类大块固定内容前置
- 用户输入、当前对话轮次后置
- 监控缓存命中率作为优化指标

## 和其他概念的关系

- 直接对象:[[大语言模型]] 推理的 KV Cache
- 主要受益:[[上下文窗口]] 大且 prompt 长的应用,如 [[RAG]]、[[AI Agent]]
- 计费维度:与 [[Token]] 经济模型紧密结合
- 与 [[少样本提示]]:大段固定示例最适合用 caching 摊薄成本
- 与 [[函数调用]] 协同:工具描述本身往往很长,缓存效果显著
