# 操作系统 Operating System

## 定义

**操作系统(Operating System, OS)**是介于硬件与应用之间的**系统软件**,职责是:
- 抽象硬件,提供统一接口(API、系统调用)
- 管理 CPU 时间(调度)、内存(分配/虚拟化)、IO 设备、文件系统、网络
- 提供安全隔离与资源公平共享
- 支持多任务、多用户

代表家族:**Unix → Linux、BSD、macOS;Windows NT 系列;移动端 iOS、Android**(基于 Unix/Linux 内核)。

## 核心要点

### 内核态与用户态

CPU 提供两种特权级:**内核态(Ring 0)** 可执行特权指令,访问全部硬件;**用户态(Ring 3)** 只能调用受限 API。
应用通过**系统调用(syscall)**进入内核,陷入(trap)切换特权。每次 syscall 有开销(寄存器保存、切换上下文)。

### 五大子系统

| 子系统 | 职责 |
|---|---|
| 进程管理 | 创建/调度/销毁[[进程与线程]] |
| 内存管理 | 虚拟内存、页表、分配、回收 |
| 文件系统 | 文件、目录、权限、Block 分配 |
| IO / 设备驱动 | 抽象硬件设备 |
| 网络 | 协议栈(TCP/IP) |

### 进程调度

CPU 是有限资源,调度器决定下一刻哪个进程/线程运行。常见算法:
- **FIFO / FCFS**:先来先服务
- **SJF**:短作业优先,理论最优但需预知运行时间
- **优先级调度**:实时系统
- **时间片轮转(Round Robin)**:公平交替
- **多级反馈队列**:Linux O(1) 调度器
- **CFS(Completely Fair Scheduler)**:Linux 当前默认,基于红黑树按虚拟运行时间排序

### 内存管理

**虚拟内存**:每进程看到独立的连续地址空间,实际由 MMU(内存管理单元)通过**页表**映射到物理页帧。
- **分页**:把内存切成 4 KB 页,按需加载
- **TLB(Translation Lookaside Buffer)**:页表的 [[缓存]],加速地址转换
- **写时复制(Copy-on-Write)**:fork() 时父子共享页,写时才真复制
- **swap**:不常用页换出磁盘
- **OOM Killer**:内存极度紧张时挑进程杀

### 文件系统

抽象磁盘为目录 + 文件树。关键概念:
- **inode**:文件元数据(权限、大小、数据块指针),文件名只是目录项指向 inode
- **块(Block)**:磁盘最小分配单位(通常 4 KB)
- **日志(Journal)**:崩溃一致性,如 ext4、NTFS
- **快照与 COW 文件系统**:ZFS、Btrfs
- **VFS**:Linux 抽象层,支持插入多种文件系统

### IO 模型

- **阻塞 IO(BIO)**:read 等到数据返回。简单但浪费线程
- **非阻塞 IO**:read 立即返回错误或数据,需轮询
- **IO 多路复用**:select/poll/epoll(Linux)、kqueue(BSD)、IOCP(Windows)。一个线程监听大量 fd
- **信号驱动**:数据就绪时内核发信号
- **异步 IO**:Linux io_uring 是新一代,真正的异步

[[事件循环]]、Nginx、Node.js 大量依赖 epoll/kqueue。

### 同步原语

内核与用户态都需要并发原语:互斥锁、信号量、自旋锁(spinlock)、读写锁、RCU(Read-Copy Update)。
Linux 内核中数千个 spinlock 保护各种数据结构。

### Linux 哲学

- "一切皆文件"(Everything is a file):socket、设备、管道都通过文件描述符操作
- 小工具组合:`ls | grep | wc` 通过管道
- 单内核架构(monolithic),但模块化(LKM)
- 开源开放,Linus 主导决策

### 微内核 vs 宏内核

- **宏内核(Linux、Windows NT)**:内核态包含调度、内存、文件、驱动、网络。性能好,但内核复杂、bug 影响大
- **微内核(QNX、L4、minix)**:内核只保留 IPC、调度,其他放用户态服务。隔离好,理论安全,但性能损失
- **混合**:macOS 的 XNU 基于 Mach + BSD,介于两者

### 容器与虚拟化

- **VM**:Hypervisor(KVM、Xen、VMware)虚拟整套硬件,跑独立 OS
- **容器**([[Docker容器]]):Linux Namespace + cgroups,共享内核
- **WSL2**:Windows 跑真 Linux 内核
- **Unikernel**:OS 与应用编译为单进程,极致精简

## 和其他概念的关系

操作系统是几乎所有[[算法]]、[[数据结构]]在工程中实际运行的舞台。[[进程与线程]]、文件系统(基于 inode + B+ 树或类似)、虚拟内存(多级页表 = [[树]])、调度器(Linux CFS 用红黑树 = 平衡 [[树]])都是数据结构的精彩实例。

[[Docker容器]]、[[Kubernetes]]、[[微服务]]建立在 OS 提供的基础抽象之上。[[事件循环]]模型依赖 OS 的 epoll/kqueue。[[数据库]]性能与 OS 的 IO 调度、页缓存深度耦合。

理解 OS 是从"会用框架"到"理解性能"的分水岭。所有看似神奇的延迟优化、并发突破,最终都回归到 syscall、上下文切换、页错误、缓存命中这些 OS 概念。
