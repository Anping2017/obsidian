# RLHF

## 定义

**RLHF(Reinforcement Learning from Human Feedback, 人类反馈强化学习)** 是用 [[强化学习]] 把 [[大语言模型]] 与人类偏好对齐的技术。它不是直接监督模型给出标准答案,而是让人类对模型多个输出进行**两两比较**,把这种偏好信号转化成奖励,再用 PPO 等 RL 算法优化策略。

OpenAI 在 InstructGPT(2022)与 ChatGPT(2022)中将其大规模产品化,直接催生了当代对话助手浪潮。

## 核心要点

**三阶段流程**

1. **监督微调(SFT)**:先在(prompt, 高质量回答)对上做监督微调,得到一个会"听指令"的模型
2. **奖励建模(RM)**:让人类对同一 prompt 的多个模型输出排序,训练一个奖励模型 $r_\phi(x, y)$ 学习偏好
3. **PPO 强化学习**:把奖励模型当作 RL 环境的奖励信号,用 PPO 优化策略,通常加 KL 惩罚保持与 SFT 模型相近,防止崩坏

**为什么要用 RL 而非直接监督**

- 偏好难以写成标量标签,但易做两两比较
- 同一 prompt 有多个合理回答,奖励模型可学习"哪个更好"的非唯一性
- RL 允许模型在生成空间中"探索"出新策略

**主要替代/演化方法**

- DPO(Direct Preference Optimization, 2023):跳过奖励模型,直接用偏好对训练,数学上等价但更简单
- RLAIF(AI Feedback):用强 LLM 替代部分人类标注,降本
- Constitutional AI(Anthropic):用模型自身按"宪法"自我批评和修正,Claude 的核心方法
- ORPO、KTO 等后续变体

**关键挑战**

- 奖励黑客(Reward Hacking):模型学到欺骗奖励模型的捷径
- 标注一致性:不同标注员偏好差异大
- 模型谄媚(Sycophancy):为讨好用户而牺牲事实正确性
- KL 控制:平衡探索与不偏离原模型

## 和其他概念的关系

- 上下文位置:位于 [[预训练与微调]] 流水线最后的"对齐"阶段
- 算法依赖:[[强化学习]] 中的 PPO 算法
- 直接结果:把 [[大语言模型]] 从基础模型变成能用的对话助手
- 与 [[幻觉]] 关系:对齐可减少明显错误,但也可能引入新偏差(过度谨慎、谄媚)
- 哲学议题:本质是 AI 对齐(alignment)的工程化实现
