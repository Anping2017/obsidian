# 数据仓库

## 定义

**数据仓库(Data Warehouse)** 是 Bill Inmon 1991 年定义的"面向主题的(Subject-Oriented)、集成的(Integrated)、相对稳定的(Non-Volatile)、反映历史变化的(Time-Variant)数据集合,用于支持管理决策"。是 [[OLAP vs OLTP]] 中 OLAP 的核心载体,与业务系统(OLTP)分离、专为分析查询优化。

## 核心要点

- **四特性(Inmon 经典定义)**
  - **面向主题**:按"客户、产品、销售"等业务主题组织,而非业务流程
  - **集成**:整合多个异构源(各业务库 / 外部数据)统一编码与口径
  - **非易失**:仓库数据加载后不再修改,只追加新数据,可追溯
  - **时变**:保留历史快照,支持时间维度分析
- **数据仓库 vs 数据库 vs 数据湖**
  - **业务库(OLTP)**:支撑业务,行存、强一致
  - **数据仓库(DW)**:结构化数据,列存,Schema-on-write
  - **数据湖(Data Lake)**:原始数据、半 / 非结构化,Schema-on-read
  - **数据湖仓(Lakehouse)**:Delta/Iceberg/Hudi,数据湖上加事务和 ACID
- **建模流派**
  - **Inmon 范式建模**:3NF,数仓内部规范化,然后到数据集市
  - **Kimball 维度建模**:Star Schema,反范式,直接面向分析
    - 事实表(Fact):度量(销售额、点击数)
    - 维度表(Dimension):描述属性(时间、产品、客户)
    - **Star Schema**:事实表中心 + 维度直接关联
    - **Snowflake Schema**:维度进一步规范化(产品 → 类别 → 类目)
- **分层架构(常见 DW 分层)**
  - **ODS(Operational Data Store)**:贴源层,业务库原样镜像
  - **DWD(Data Warehouse Detail)**:明细层,清洗后的事实数据
  - **DWS(Data Warehouse Summary)**:汇总层,按主题聚合
  - **ADS(Application Data Store)**:应用层,面向具体报表
  - **DIM**:维表层
- **慢变维度(SCD)**
  - **Type 1**:直接覆盖,不保留历史
  - **Type 2**:新增一行 + 起止时间,完整保留历史(主流)
  - **Type 3**:加列保留前一值
- **典型技术栈**
  - **传统**:Teradata、Oracle Exadata、Greenplum
  - **云原生**:Snowflake、Google BigQuery、AWS Redshift、Azure Synapse
  - **开源**:Apache Hive(早期)、Presto/Trino、ClickHouse、StarRocks、Doris
  - **数据湖仓**:Databricks Delta Lake、Apache Iceberg、Apache Hudi
- **ETL/ELT 流水线**
  - 数据源 → 抽取 → 转换 → 加载到 DW
  - 见 [[ETL与ELT]]
  - 现代 ELT:先入仓 + dbt 内做转换,SQL 即代码
- **存储与查询特点**
  - [[列式存储]] 主导,压缩比高
  - 大表 JOIN、聚合、窗口函数
  - 物化视图、Cube 预计算加速
  - MPP(大规模并行处理)架构,见 [[批处理]]
- **现代趋势**
  - **实时数仓**:Flink + Kafka + ClickHouse / StarRocks,延迟从 T+1 → 秒级
  - **湖仓一体**:Databricks Lakehouse、Iceberg + Trino
  - **指标平台**:统一定义业务指标(LookML、Cube、dbt Metrics)
  - **AI / ML 集成**:Snowflake Cortex、BigQuery ML 把 ML 推到仓内

## 和其他概念的关系

数据仓库是 [[OLAP vs OLTP]] 中 OLAP 的核心载体,与业务的 [[关系型数据库]] OLTP 分离。数据通过 [[ETL与ELT]] 流入仓库。

底层多用 [[列式存储]] + MPP 架构。其建模反 [[数据库范式]],Star/Snowflake schema 大量冗余以加速查询。

[[流处理]](Flink/Kafka Streams)与 [[批处理]](Spark)是 DW 上 / 入仓的两种模式,催生 [[Lambda架构]] / Kappa 架构。

[[查询优化器]] 在 DW 中需要识别 Star Schema 模式,做 Star Join 优化。

在 [[微服务]] 架构下,业务系统多库分散,中央数仓是跨域分析的唯一抓手。
