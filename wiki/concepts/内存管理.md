# 内存管理

## 定义

**内存管理** 是程序运行过程中分配、跟踪、释放堆内存的机制。栈内存由编译器按作用域自动管理,关键挑战在堆——长生命周期、共享、易泄漏。语言对内存管理的选择是塑造其性能与安全姿态的根本。

## 核心要点

- **手动管理(C/C++)**
  - `malloc/free`、`new/delete`,完全控制分配点。
  - 极致性能,适合实时系统。
  - 易错:内存泄漏、悬垂指针、双重释放、缓冲区溢出 —— CVE 漏洞主要来源之一。
  - C++ RAII + 智能指针(`unique_ptr`/`shared_ptr`)缓解。
- **垃圾回收(Java/C#/Python/Go/JS)**
  - 自动识别不再可达对象并回收。
  - 算法:引用计数、标记清除、复制、标记整理、分代、并发并行。
  - 优点:开发心智负担低,消除一类内存安全 bug。
  - 缺点:运行时开销、GC 暂停(STW)、不适合硬实时;参考 [[Java垃圾回收]]。
- **所有权(Rust)**
  - 编译期借用检查 + 移动语义,无 GC、无运行时开销。
  - 学习曲线陡,但内存与并发安全编译期保证;参考 [[Rust所有权]]。
- **混合方案**
  - 引用计数 + 循环检测(CPython、Swift)。
  - 区域内存(Arena):按生命周期批量释放,游戏引擎、编译器常用。
  - 池化分配:固定大小对象复用,减少碎片。
- **关键概念**
  - **碎片化**:外碎片(空闲不连续)、内碎片(分配大于实际)。
  - **分代假设**:大多数对象朝生夕死。
  - **逃逸分析**:编译期判断对象是否逃出函数,可栈分配或标量替换。
  - **NUMA**:多 CPU 节点内存访问代价不同,大规模 JVM 需 NUMA 感知。

## 关系

- 与 [[操作系统]] 的虚拟内存协作——malloc 底层用 brk/mmap 系统调用。
- 与 [[Python GIL]] 联动——CPython 的引用计数依赖 GIL 保护。
- [[Rust所有权]]、[[Java垃圾回收]] 是不同极端的代表方案。
- 影响 [[并发与并行]]——GC 通常需要 STW 屏障,所有权天然防数据竞争。
- 是 [[操作系统进程内存]] 的应用层视角,共同构成完整内存图景。
