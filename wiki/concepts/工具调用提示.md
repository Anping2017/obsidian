# 工具调用提示

## 定义

**工具调用提示**(Tool-Use Prompting / Function Calling Prompting)是 [[提示词工程]] 中**引导 [[大语言模型]] 在合适时机调用外部工具**(API、计算器、数据库、网页搜索、代码执行环境等)的技术。

它把 LLM 从"纯文本生成器"扩展为"能与世界交互的代理",是 [[AI Agent]] 与 [[AI Agent框架]] 的核心使能技术。

## 核心要点

### 三种主流形态

#### 1. Function Calling(OpenAI 2023.6 起)

模型原生支持的结构化工具调用:

```python
tools = [
    {
        "name": "get_weather",
        "description": "获取天气信息",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string"}
            }
        }
    }
]

response = openai.chat.completions.create(
    messages=[{"role": "user", "content": "上海今天天气?"}],
    tools=tools
)
# 模型返回工具调用指令(JSON),开发者执行后回传
```

模型经过专门训练,能稳定输出工具调用 JSON。

#### 2. Tool Use(Anthropic Claude)

类似 OpenAI 但更结构化的 API 设计,2024 起支持。

#### 3. ReAct 模式(2022 论文)

通过 prompt 引导,无需原生支持:

```
Question: 上海今天天气如何?

Thought: 我需要查询当前天气,使用 weather_api 工具
Action: weather_api[上海]
Observation: 25°C, 多云
Thought: 我已经获得了天气信息
Final Answer: 上海今天 25°C,多云。
```

经典论文 *ReAct: Synergizing Reasoning and Acting in Language Models* 使其成为 Agent 框架基础范式。

### 工具描述设计

工具描述质量决定调用准确性:

#### 好的工具描述

```json
{
  "name": "search_emails",
  "description": "在用户邮箱中搜索符合条件的邮件。仅返回最近 100 封,按时间倒序。无法访问已删除邮件。",
  "parameters": {
    "query": {
      "type": "string",
      "description": "搜索关键词,支持发件人、主题、内容"
    },
    "after": {
      "type": "string",
      "format": "date",
      "description": "起始日期 YYYY-MM-DD"
    }
  }
}
```

#### 坏的工具描述

```json
{
  "name": "search",
  "description": "搜索",
  "parameters": {"q": {"type": "string"}}
}
```

### 关键设计原则

#### 1. 工具数量

- 简单任务 < 10 个工具
- 复杂 Agent 可达 30+,但需分组检索
- 过多工具 → 模型选错或不知如何选

#### 2. 描述清晰度

- 工具能做什么、不能做什么
- 何时使用、何时不使用
- 参数含义、格式、限制
- 错误情况

#### 3. 命名约定

- 动词 + 名词:`get_weather`、`search_emails`、`create_invoice`
- 一致风格(全用 snake_case)
- 不要太相似名字(`search` vs `find`)

#### 4. 错误处理

```
Tool: search_emails(query="发票")
Error: User has not authorized email access.

Thought: 用户未授权,我应该告知用户并请求授权。
Final Answer: 我需要您授权我访问邮件后才能搜索。
```

模型需学会处理工具失败、参数错误、超时等。

### 多工具协调

#### 顺序调用

```
Tool: search_orders(date="today")
→ [order_id_1, order_id_2]
Tool: get_order_details(order_id="order_id_1")
→ {...}
Tool: send_message(to="customer1", text="...")
```

#### 并行调用

OpenAI/Claude 支持单次响应中并行调用多个工具:
```
Tool: get_weather(city="上海") | get_traffic(city="上海") | get_news(city="上海")
```

减少延迟,适合独立子任务。

### 主要应用模式

#### 1. RAG 增强

```
Query → search_knowledge_base → 文档 → 综合回答
```

#### 2. 计算器/代码执行

```
"计算 35234 × 78912" → execute_code("...") → 结果
```

避免 LLM 算术错误。

#### 3. 实时信息

```
"今天美元汇率?" → get_exchange_rate → 数据
```

突破训练数据时效。

#### 4. 数据库查询

```
"上月销售前 5 客户?" → execute_sql(...) → 表
```

#### 5. 文件操作

```
"找出项目中所有 TODO 注释" → grep("TODO") → 列表
```

#### 6. 多模态

```
"分析这个图片" → vision_analyze(image) → 描述
"生成一张猫的图" → text_to_image(...) → URL
```

### MCP 协议(Anthropic 2024)

[[MCP协议]](Model Context Protocol)统一工具接口:
- 工具开发者:实现一次,所有 MCP 客户端可用
- 应用开发者:使用任何 MCP server
- 类似 USB-C 之于 AI 工具生态

### 评估方法

#### Berkeley Function Calling Leaderboard(BFCL)

业界主要评估各模型工具调用能力:
- 简单调用准确率
- 多工具组合
- 并行调用
- 错误处理

#### TAU-Bench

模拟真实业务流程的多工具任务。

#### 经验数据

GPT-4o、Claude 3.5 Sonnet 等顶级模型工具调用准确率 90%+;弱模型 60-80%。

### 局限与挑战

#### 1. 选择错误

模型选错工具或不调用工具直接编造答案。

#### 2. 参数错误

填错参数、漏字段、格式错误。

#### 3. 错误链放大

一步出错 → 后续基于错误结果继续 → 雪崩。

#### 4. 安全隐患

工具调用真实系统 → 误删、未授权访问、注入攻击。

#### 5. 调试困难

中间步骤多 → 难复现、难追溯。

### 实务最佳实践

1. **工具描述详细且测试过**:写完后用各类边界 case 测试
2. **结构化输出 + 校验**:用 JSON Schema 验证参数
3. **沙盒执行**:危险工具(rm、push)隔离运行
4. **人在回路**:关键操作需用户确认
5. **超时与重试**:防止死锁
6. **可观测性**:每次调用日志、监控
7. **逐步推广**:先在低风险场景试用

### 主要 SDK 与工具

- OpenAI Python/Node SDK:functions、tools 参数
- Anthropic SDK:tools、tool_use messages
- LangChain:Tool、StructuredTool
- LlamaIndex:Tool 抽象
- AutoGen:tool registration
- MCP SDK:跨厂商标准
