# 向量召回

## 定义

**向量召回**(Vector Retrieval / Dense Retrieval)是把查询(query)和被检索内容(documents / items)都编码为高维稠密向量(embedding),然后通过 **向量相似度**(余弦相似度、内积、欧氏距离)做近邻搜索,从大候选集中取回最相关的 Top-K 候选。它取代或补充了传统倒排索引的关键词匹配(BM25/TF-IDF),是 **语义搜索**、[[RAG]]、推荐系统的基础技术之一。

## 核心要点

### 向量召回 vs 关键词召回

| 维度 | 关键词召回(BM25) | 向量召回(Dense) |
|---|---|---|
| 原理 | 词项匹配 + IDF 加权 | 向量空间相似度 |
| 同义/近义 | ✗(需扩展词表) | ✓(语义天然) |
| 长尾长查询 | 一般 | 强 |
| 精确匹配(品牌/型号) | 强 | 弱 |
| 解释性 | 高(能指出命中词) | 低 |
| 计算成本 | 倒排表,毫秒级 | 需向量库 + ANN,毫秒到几十毫秒 |
| 冷启动 | 即用 | 需训练或预训练模型 |

实践中常做 **混合召回(Hybrid)**——关键词 + 向量分数加权融合,兼得两者优势。

### 关键技术栈

1. **Embedding 模型**
   - 通用:OpenAI `text-embedding-3`、Cohere、bge、e5
   - 中文:BGE、M3E、智源 BGE-M3
   - 多模态:CLIP(图文)、BLIP(图文)
2. **向量数据库 / ANN 索引**
   - 专用:Pinecone、Milvus、Weaviate、Qdrant
   - 通用 + 扩展:Postgres+pgvector、Elasticsearch+kNN、Redis Vector
   - 库:Faiss(Facebook)、HNSW、Annoy、ScaNN(Google)
3. **检索增强**:与排序模型(reranker)组合,常用 cross-encoder 做精排
4. **过滤**(filter):元数据过滤(时间、分类、用户权限)

### 经典 ANN 算法

| 算法 | 思想 | 性能 |
|---|---|---|
| **HNSW** | 多层图导航 | 主流,高召回 + 低延迟 |
| **IVF** | 倒排 + 聚类 | 内存友好,可扩展 |
| **PQ**(Product Quantization) | 子空间量化压缩 | 大规模存储 |
| **ScaNN** | 各向异性量化 + 重排 | Google 经典 |

### 混合检索的标准范式

```
Query
 ├─→ BM25 检索 → 倒排索引 → Top-N1
 └─→ Embedding 编码 → 向量库 → Top-N2
       ↓
   Score Fusion(RRF / 加权)
       ↓
   Cross-Encoder Rerank(可选)
       ↓
   Final Top-K
```

### 重要工程问题

- **chunk 切分策略**:文档切片大小、重叠、按语义/段落/字符分,直接影响召回质量
- **元数据**:embedding 不带过滤条件,需另存元数据做 pre/post-filter
- **更新与删除**:全量重建 vs 增量更新,各向量库差异大
- **质量评测**:常用 Recall@K、MRR、NDCG,需准备标注数据

## 典型应用

- **企业知识库 / RAG**:配合 LLM 做内部问答(参见 [[RAG|检索增强生成]])
- **电商搜索**:商品语义搜索,"轻便的男士外套" 匹配 "薄款防风夹克"
- **推荐系统**:用户向量 ↔ 物品向量近邻召回,典型见 YouTube 双塔模型
- **图像搜索**:CLIP 把图和文映射到同一空间,文搜图、图搜图
- **代码搜索**:GitHub Copilot/Sourcegraph 都用 embedding 检索代码
- **去重 / 聚类**:重复内容检测、客户画像聚类

## 局限与陷阱

- **embedding 模型偏见**:训练数据偏向英文 / 通用域,垂直领域(医学、法律)需要领域微调
- **精确查询效果差**:SKU 编号、人名等需关键词召回兜底
- **长尾问题**:稀有概念在 embedding 空间分散,召回不稳定
- **维护成本**:模型升级需要全量重新 embedding
- **召回 ≠ 排序**:向量相似度高的不一定是最相关的,需 reranker 精排
- **过度信任**:embedding "万能感"导致工程师跳过传统检索优化
