# 回溯算法 Backtracking

## 定义

**回溯算法(Backtracking)**是一种基于[[DFS深度优先搜索]]的搜索算法,通过在解空间树上**尝试 → 验证 → 失败则撤销(回溯)**的方式枚举所有可能解。它适用于**组合、排列、子集、子集和、N 皇后、数独**等问题。

回溯的核心是"试错":在每一步选择一个候选,若导致不可行,撤销当前选择继续尝试其他候选。它本质上是受控的暴力搜索,通过**剪枝**显著降低实际复杂度。

## 核心要点

### 标准模板

```
def backtrack(path, choices):
    if 满足终止条件:
        result.add(path 的拷贝)
        return
    for 候选 in choices:
        if 不满足约束: continue   # 剪枝
        path.add(候选)            # 选择
        backtrack(path, 新选择)
        path.remove(候选)         # 撤销选择
```

### 关键要素

1. **解空间(Solution Space)**:可能解的全集,通常是树形或图形结构
2. **状态表示(Path)**:当前已做选择的累积
3. **约束条件**:不满足则剪枝,跳过整个子树
4. **目标条件**:满足则记录解

### 经典问题

| 问题 | 状态 | 剪枝 |
|---|---|---|
| 全排列 | 已选元素 | 不重复使用 |
| 子集 | 当前下标 | 选/不选 |
| 组合 | 当前下标 + 已选数 | 提前退出 |
| N 皇后 | 行 → 列、对角线占用 | 攻击检查 |
| 数独 | 行/列/宫的占用 | 候选数检查 |
| 单词搜索 | 网格位置 + 已访问 | 边界、字母不匹配 |
| 24 点 | 当前数字 + 运算符 | 整除/范围 |

### 剪枝技术

剪枝是回溯效率的关键,有三大类:
- **可行性剪枝**:当前路径已不可能成解(数独某格无候选)
- **最优性剪枝**:当前路径不可能优于已知最优解(分支定界)
- **对称性/等价剪枝**:多个分支等价,只搜一个(N 皇后第一行只搜前一半)

未剪枝时回溯可能 O(2ⁿ) 或 O(n!),工程不可用;剪枝得当可降到几乎线性。

### 回溯 vs 普通 DFS

回溯特别强调"撤销选择"以让状态在不同分支共享,相当于在 DFS 上做"现场恢复"。普通 DFS 可能不需要撤销(每个节点独立访问)。

### 回溯 vs DP

| 维度 | 回溯 | [[动态规划]] |
|---|---|---|
| 目的 | 枚举所有解 / 任一可行 | 计数 / 最优值 |
| 子问题 | 通常无重叠 | 重叠 |
| 复杂度 | 指数级(剪枝降低) | 多项式 |

但有些问题既能 DP 也能回溯(如背包),区别在于"是否需要列出所有方案"。

### 状态压缩与位运算

N 皇后中,用三个整数(列、左对角、右对角)表示已被攻击,O(1) 检查。常 Web 后端枚举权限组合也用位掩码加速。

## 和其他概念的关系

回溯是[[递归]]的一种使用模式,实现上依赖[[DFS深度优先搜索]]。它与[[分治算法]]都用递归,但分治是"分→治→合",子问题独立;回溯是"试→错→改",路径上的状态相互依赖。

[[动态规划]]是"自底向上"的反向回溯。如果问题既要枚举又要剪枝,常配合 memoization,回溯 + 记忆化几乎等价于 DP。

工程中的应用:
- **[[正则表达式]]引擎**(Backtracking Regex):大多数语言的正则用回溯,某些恶意输入可触发指数爆炸(ReDoS)
- **AI 求解**:旧 AI(SAT 求解、约束满足、CSP)的核心
- **测试用例生成**:自动机器人测试时枚举操作序列
- **路径规划**:迷宫、棋类博弈树
