# 客户开发

## 定义

**客户开发(Customer Development, CustDev)** 由硅谷连续创业者 **Steve Blank** 在 2005 年的《**The Four Steps to the Epiphany**》中系统提出,核心命题:

> 创业不只是产品开发,更是客户开发——**初创企业是临时组织,目的是寻找可重复、可扩展、可盈利的商业模式**。在找到之前,所有计划都是假设。

Blank 强调一句口号:**"Get out of the building!"(走出办公室!)** —— 创业者必须直接接触真实客户,而非闭门写商业计划书。

## 核心要点

### 客户开发四步法

| 阶段 | 任务 | 关键问题 |
|---|---|---|
| **1. 客户发现(Customer Discovery)** | 验证假设是否成立 | 客户真有这个问题吗? |
| **2. 客户验证(Customer Validation)** | 找到可重复销售模式 | 我们的解决方案被买单吗? |
| **3. 客户创造(Customer Creation)** | 把销售扩大到主流 | 怎么获取大量客户? |
| **4. 公司建设(Company Building)** | 建立运营组织 | 怎么从初创变成公司? |

前两步是寻找 PMF([[产品市场契合度]]),后两步是规模化。

### 客户开发 vs 产品开发

传统产品开发流程(线性):

```
概念 → 设计 → 开发 → Alpha/Beta → 发布
```

Blank 指出:**这个流程在初创公司用是灾难** —— 因为它假设客户、需求、解决方案都已知。

客户开发并行流程:

```
[产品开发线]:概念 ─ 开发 ─ MVP ─ 发布 ─ 迭代
[客户开发线]:发现 ─ 验证 ─ 创造 ─ 建设
```

两条线不断交互,**学习驱动产品调整**。

### 客户访谈的核心方法

不是"卖产品",而是"听问题":

| 阶段 | 重点 |
|---|---|
| **问题验证** | 客户有这个痛点吗?多痛?现在怎么解决? |
| **方案验证** | 我们的方案是否解决?客户愿意付吗? |
| **付费验证** | 客户真的掏钱吗?多少? |

### 客户访谈的"妈妈测试"

Rob Fitzpatrick 在《**The Mom Test**》中给出实用法则:

> "妈妈测试":即使问妈妈,也能得到客观回答的问题方式。

不要问:
- "你会用我们这个产品吗?"(妈妈会说会的)
- "你觉得这个想法怎么样?"(全是表扬)
- "我们要做 X,你愿付 100 块吗?"(套话)

要问:
- "你最近一次遇到 X 问题是什么时候?"
- "你那次是怎么解决的?"
- "你为此付出了什么代价?"
- "你现在用什么工具/方式?"

聚焦**过去行为**,不是未来意图——人对未来的预测极不可靠。

### 早期采用者画像(Early Adopter)

CustDev 的关键是找到**真正痛苦、愿意尝试新方案的早期采用者**:

| 特征 | 描述 |
|---|---|
| **意识到问题** | 已经知道自己有这个问题 |
| **痛苦深** | 痛到愿意花钱解决 |
| **已尝试解决** | 有用过(差的)替代方案 |
| **愿意忍受 MVP** | 不需要完美,要快 |
| **愿意反馈** | 主动给意见 |
| **自带传播** | 解决问题后会推荐 |

Blank 称这类客户为"**有头发着火的人**" —— 痛得不忍。

### Customer Development Manifesto

Blank 提炼的客户开发宣言(摘要):

1. 没有什么事实可以在你的办公室里证实
2. 把客户开发与产品开发并行
3. 失败是寻找的固有部分
4. 不断迭代和转向(Pivot)
5. 没有商业计划书能在第一次客户接触后存活
6. 不同初创公司类型需不同方法
7. 初创公司的指标与成熟公司不同
8. 决策快、周期短、迭代快

### 与精益创业的关系

[[精益创业]](Eric Ries,2011)继承并扩展 CustDev:

- Ries 是 Blank 的学生
- CustDev 提供**方法论**(怎么发现需求)
- Lean Startup 加上**工具**(MVP、Build-Measure-Learn、创新会计)
- 商业模式画布(Osterwalder)是表达假设的画板

三者构成现代创业方法论铁三角:**画布表达假设、CustDev 验证客户、精益创业循环改进**。

### CustDev 的常见错误

- **找朋友访谈**:友情让反馈失真
- **问引导性问题**:得到想听的答案
- **听承诺不看行为**:"我会用"≠真用
- **过早卖**:第一次访谈就推销
- **样本偏差**:只访某类客户
- **不记录**:依赖记忆而非事实
- **不分享发现**:整个团队应同步学习

### 适用边界

CustDev 最适合**明确客户的 B2B/B2C** 创业;在以下领域需调整:

- **超前科技**:客户都没意识到需求(Henry Ford "如果问客户,他们想要更快的马")
- **平台型**:双边市场,需同时验证两边
- **政府/医疗**:决策周期长、监管复杂
- **极小众**:候选客户太少做不了大量访谈

## 和其他概念的关系

- 是 [[精益创业]] 的方法论基础(Eric Ries 师从 Blank)
- 与 [[商业模式画布]] 互补:画布表达假设,CustDev 验证假设
- 是寻找 [[产品市场契合度]] 的核心方法
- 与传统 [[市场分析]](调研报告)对比,强调一手访谈
- 涉及 [[创业机会识别]] 的验证阶段
- 在大公司内部演化为"用户研究"(User Research)、设计思维(Design Thinking)
- 影响产品管理(PM)与用户体验(UX)的方法论
- 与 [[管理决策]] 中"假设-验证"的科学方法论一致
- 心理学层面:对抗访谈的多种偏差(社会期望、自利偏差)
- 在 B2B SaaS 中演化为"客户成功"(Customer Success) 体系
