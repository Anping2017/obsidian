# 二叉搜索树 Binary Search Tree

## 定义

二叉搜索树(Binary Search Tree, BST),又名二叉查找树或二叉排序树,是满足以下性质的[[二叉树]]:

- 若左子树非空,左子树所有节点的键值 **小于** 根节点
- 若右子树非空,右子树所有节点的键值 **大于** 根节点
- 左右子树本身也是 BST

这种有序结构使得查找、插入、删除可以**沿一条路径**完成,平均时间复杂度 O(log n)。

## 核心要点

### 三大基础操作

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = self.right = None

def search(root, key):
    if not root or root.key == key: return root
    return search(root.left, key) if key < root.key else search(root.right, key)

def insert(root, key):
    if not root: return Node(key)
    if key < root.key: root.left = insert(root.left, key)
    elif key > root.key: root.right = insert(root.right, key)
    return root
```

删除最复杂,分三种情况:

1. **叶子节点**:直接删
2. **只有一个子节点**:用子节点替换
3. **有两个子节点**:用中序后继(右子树最左节点)替换,再删后继

### 时间复杂度

| 操作 | 平均 | 最坏(退化为链) |
|---|---|---|
| 查找 | O(log n) | O(n) |
| 插入 | O(log n) | O(n) |
| 删除 | O(log n) | O(n) |

最坏情况发生在按升序/降序插入时,树退化为链表。

### 中序遍历的奇妙性质

BST 的中序遍历(左→根→右)产出**升序序列**。这意味着 BST 不仅是搜索结构,也是**排序结构**——插入完毕后的中序遍历相当于一次排序。

### 平衡的必要性

为避免最坏情况,衍生出**自平衡 BST**:

| 类型 | 平衡策略 | 应用场景 |
|---|---|---|
| AVL 树 | 严格平衡(高度差 ≤ 1) | 查询多于修改 |
| [[红黑树]] | 弱平衡(黑高度相同) | 通用,Linux 调度、C++ map |
| Treap | 随机化平衡 | 简单实现 |
| Splay 树 | 访问局部性 | 缓存场景 |

[[B+树]] 是多路平衡查找树,适合磁盘([[数据库]]索引)。

## 和其他概念的关系

BST 是 [[数据结构]] 课程的基石之一,承上启下:从 [[二叉树]] 引入有序性,向上发展为 [[红黑树]]、AVL、B/B+ 树等平衡变体。

[[算法]] 视角下,BST 是**分治**思想的具象——每次操作把搜索空间减半。这与 [[二分查找]]、[[归并排序]] 同源。

实际应用中,BST 平衡变体广泛存在:[[操作系统]] 的进程优先级管理(Linux CFS 用红黑树)、[[数据库]] 索引(B+ 树)、[[Hash表]] 在 Java HashMap 中桶溢出转红黑树、[[字典树]] 与 BST 互补处理字符串与有序数值。

[[复杂度分析]] 在 BST 学习中尤为关键——理解为什么平均 O(log n) 而最坏 O(n),是建立"渐近 vs 实际"思维的最佳样例。
