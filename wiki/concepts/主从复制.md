# 主从复制

## 定义

**主从复制(Master-Slave Replication / Primary-Replica)** 是把一台数据库(主库)的数据变更同步到一台或多台数据库(从库)的技术。目的是数据冗余(灾备)、读扩展(配合 [[读写分离]])、地理就近访问、备份不影响主库。是分布式数据库高可用的基石。

## 核心要点

- **复制粒度**
  - **基于 SQL 语句(Statement-based)**:从库重放 SQL,体积小但非确定性函数(NOW()、UUID())可能导致主从不一致
  - **基于行(Row-based)**:从库重放变更行,确定但日志大;MySQL 5.7+ 默认
  - **混合(Mixed)**:大多用 SQL,不安全场景切到 Row
  - **WAL 流(Logical/Physical)**:PostgreSQL 用 WAL streaming(物理)和逻辑解码(逻辑)
- **同步模式**
  - **异步(Async)**:主写完日志即返回,从在后台拉取重放
    - 性能最好,但主挂了未同步的日志会丢失
  - **半同步(Semi-sync)**:主等至少一个从 ACK 收到日志才返回
    - 折中:大幅减小数据丢失窗口,延迟可控
  - **同步(Sync)**:主等所有(或法定多数)从确认才返回
    - 最安全但延迟随网络放大
- **MySQL 复制**
  - **binlog**:主库的二进制变更日志
  - **IO 线程**:从库连主拉 binlog,写入 relay log
  - **SQL 线程**:从 relay log 重放
  - **GTID(Global Transaction ID)**:全局事务 ID,简化故障切换
  - **多线程复制**:从库并发应用 relay log,缓解延迟
- **PostgreSQL 复制**
  - **流复制(Streaming Replication)**:物理 WAL 日志流式同步
  - **同步 / 异步可配**:application_name + synchronous_standby_names
  - **逻辑复制(Logical Replication)**:发布订阅模式,可跨大版本、跨表选择
- **MongoDB 复制集(Replica Set)**
  - 1 主 N 从 + 1 仲裁(Arbiter)
  - 主挂自动选举(类 Raft)
  - 从可读(配置 readPreference)
- **Redis 主从**
  - 主全量 RDB + 增量 buffer 同步给从
  - 哨兵(Sentinel)做监控与故障转移
  - 集群模式分片 + 每片主从
- **多主复制(Multi-Master)**
  - 多个节点都接受写,互相同步
  - 优点:任意节点写、地理分布友好
  - 难点:写冲突解决(LWW、CRDT、版本向量)
  - 实现:Galera Cluster、MySQL MGR、Cassandra(无主)、CouchDB
- **复制延迟问题**
  - 大事务、大查询、慢盘 IO、网络抖动都会拉大延迟
  - 业务影响:写后读不到、报表数据错乱
  - 监控:Seconds_Behind_Master(MySQL)、pg_stat_replication(PG)
- **故障转移(Failover)**
  - 自动:工具(Orchestrator、Patroni、Sentinel)检测主挂、选新主、切流量
  - 难点:脑裂(主从都自认为是主)、数据丢失、应用感知
  - **预防脑裂**:Quorum / Lease / 第三方裁判

## 和其他概念的关系

主从复制是 [[读写分离]]、灾备、扩展的基础设施。其本质是把主库的状态(操作日志)广播到从库,与 [[消息队列]] 的发布订阅有本质相似性。

异步复制存在数据丢失风险,触及 [[CAP定理]] 中 C(强一致)与 A(高可用)的权衡。半同步是工程上的折中。

[[Raft共识算法]] / [[Paxos]] 是更严格的复制协议,在 etcd、Consul、TiKV 等现代分布式系统中替代传统主从。

[[NoSQL数据库]] 中,Cassandra 是无主多副本(每节点都能写,后台 Anti-entropy 修复)、MongoDB 是单主复制集、Redis Cluster 是分片主从。

[[分布式锁]]、分布式服务发现都依赖底层的复制机制保证元数据一致。
