# 零信任架构 Zero Trust Architecture

## 定义

**零信任架构(Zero Trust Architecture,ZTA)** 是 Forrester 分析师 John Kindervag 在 2010 年提出的安全模型,核心主张:**"永不信任、始终验证(Never Trust, Always Verify)"**——抛弃"内网可信、外网不可信"的边界思维,假设网络已被攻破,每次访问都需基于身份、设备状态、行为上下文动态决策。

NIST 在 2020 年发布 SP 800-207 标准化,将 ZTA 上升为美国联邦政府强制方向。云原生、远程办公、SaaS、零工经济让传统边界消失,零信任成为现代企业安全主流框架。

## 传统 vs 零信任

**传统"城堡-护城河"模型**

- VPN 进内网即"可信"
- 内部服务间相互信任
- 网络位置 = 权限
- 一台机器被攻破横向扩散容易

**零信任**

- 没有"内网"概念
- 每次请求重新认证
- 默认拒绝,显式授权
- 持续监控、动态调整
- 访问决策基于多维信号

## 核心原则

**1. 显式验证**

每次访问都基于:
- 身份(Identity:Who are you?)
- 设备状态(Device:Is the device healthy?)
- 位置(Location:Where from?)
- 行为(Behavior:Is this normal?)
- 时间(Time:Within work hours?)
- 资源敏感度(Resource:How sensitive?)

**2. 最小权限**

- Just-In-Time Access:临时授权,自动到期
- Just-Enough-Access:只给当前任务所需
- 不预授大权限"以备不时之需"

**3. 假设已被攻破**

- 默认环境敌对
- Defense in Depth(纵深防御)
- 限制爆炸半径(微分段)
- 加密一切(网内也加密)
- 持续日志审计

## NIST ZTA 架构组件

```
用户/设备 → 政策执行点(PEP)→ 资源
                  ↓
              政策决策点(PDP)
              ├── 政策引擎(PE)
              ├── 政策管理员(PA)
              └── 信任引擎
              ↑
   信号源:身份(IdP)、设备(MDM)、威胁(SIEM)、风险(UEBA)
```

每次请求经过 PEP 拦截,PDP 综合多源信号决定是否放行。

## 关键技术

**1. 身份与访问管理(IAM)**

- 强身份(MFA、生物识别、硬件 Token)
- SSO(Single Sign-On)统一入口
- 联合身份(SAML、OIDC、[[OAuth 2.0]])
- 动态权限(基于属性,不只角色)

**2. 设备信任**

- MDM(Mobile Device Management):iPhone / Android 集中管理
- EDR(Endpoint Detection):终端检测响应
- Device Health:补丁、加密、防病毒状态
- Conditional Access:不达标设备拒绝高敏资源

**3. 微分段(Micro-segmentation)**

- 内部服务间默认不通,显式开放
- [[服务网格]](Istio)+ NetworkPolicy
- 软件定义边界(SDP / ZTNA)
- 替代 VPN 的 ZTNA(Zscaler、Cloudflare Access)

**4. 持续监控**

- UEBA(User Entity Behavior Analytics)异常行为
- 实时风险评分
- 异常即重认证
- SIEM([[ELK Stack]] / Splunk)汇总

**5. 加密**

- 全程 [[TLS]](服务间 mTLS)
- 静态数据加密(KMS)
- 端到端加密(信令)

## BeyondCorp(Google 实践)

Google 2009 年起推行的零信任实施(后开源思想),关键思路:

- 任何员工设备从任何网络访问内部应用,经过统一访问代理
- 员工设备需注册并健康
- 应用基于 OAuth 2.0 / OIDC 鉴权
- 完全消灭内部 VPN

这是企业零信任落地的标杆案例,2014 年起多篇论文公开,影响整个行业。

## ZTNA(零信任网络访问)

替代 VPN 的解决方案:
- 用户连接代理(如 Cloudflare Access)
- 代理验证身份、设备、上下文
- 验证通过后连接到具体应用(不是整个网络)
- 一次访问一应用,而非一次连入整个内网

主流 ZTNA 厂商:
- Zscaler ZPA
- Cloudflare Access
- Cisco Duo
- Tailscale(开源 + 商业)
- Okta Advanced Server Access
- Citrix Secure Private Access

## SASE(Secure Access Service Edge)

Gartner 2019 年提出,把网络(SD-WAN)与安全(ZTNA、SWG、CASB、FWaaS)融合到云端:
- 云原生的全局边缘网络
- 用户从任何位置经过最近 PoP 接入
- 一站式策略管理

SASE 是零信任在网络层的产品化,Cloudflare、Zscaler、Cato Networks、Palo Alto Prisma 是主要玩家。

## 部署成熟度模型(CISA ZTMM)

美国 CISA 五大支柱:
1. **Identity**:身份
2. **Devices**:设备
3. **Networks**:网络
4. **Applications & Workloads**:应用
5. **Data**:数据

每个支柱四级(Traditional / Initial / Advanced / Optimal),组织可分阶段提升。

## 实施挑战

**1. 历史包袱**

- 老应用没法接入 SSO
- 不支持 OIDC 的内部系统
- 物理边界(IDC 内服务器)迁移难

**2. 用户体验**

- 严格 ZT 让登录变复杂
- 平衡安全 vs 摩擦
- MFA 疲劳

**3. 文化阻力**

- "我们一直这么做"
- 内部信任假设根深蒂固
- 需要 CISO 自上而下推动

**4. 工具碎片化**

- IdP / MDM / EDR / ZTNA 多厂商
- 集成复杂
- 管理成本

**5. 性能**

- 每次请求多次验证 → 延迟
- 加密开销
- 缓存策略

## 零信任在云原生

**[[Kubernetes]] 集群**

- ServiceAccount + RBAC
- NetworkPolicy 微分段
- mTLS 服务间认证(Istio / Linkerd 自动化)
- Pod Security Admission
- Image Signing(Cosign)

**API**

- 每次请求 [[JWT]] / [[OAuth 2.0]] 验证
- 短效 Token + 刷新
- Scope 细化(最小权限)

**数据库**

- IAM 数据库认证(AWS RDS IAM、GCP Cloud SQL IAM)
- 短期凭据(HashiCorp Vault 动态密钥)

## 与传统安全模型的过渡

**第 1 步**:MFA 全员推行
**第 2 步**:SSO 统一身份
**第 3 步**:Conditional Access 政策
**第 4 步**:消除 VPN,迁移 ZTNA
**第 5 步**:微分段网络
**第 6 步**:持续监控与自动响应

通常 2-5 年规划。

## 与 GDPR / SOC2 等合规

零信任天然提升合规水平:
- GDPR:最小化数据访问、审计日志、加密
- SOC2:访问控制、监控、变更管理
- ISO 27001:风险管理、连续改进

## 局限

- "零信任"是营销术语,容易过度承诺
- 不是单一产品,是架构与文化
- 完全实施需多年
- 中小企业成本高
- 用户摩擦显著
- 误判导致正常业务受阻

## 和其他概念的关系

零信任与 [[OAuth 2.0]]、[[OIDC]]、[[JWT]]、[[Cookie与Session]]、[[TLS]] 等具体技术构成完整身份与访问栈。它的"加密一切"主张推动了 [[服务网格]] mTLS 自动化的兴起。

它与 [[微服务]] / [[Kubernetes]] 云原生架构互为支撑——容器化让"每个工作负载有自己身份"成为可能。它的"持续验证"思想与 [[OWASP Top 10]] A01 破损访问控制防御一脉相承。

零信任 vs 传统边界的转变,与 [[微服务]] vs 单体、[[GitFlow与TrunkBased]] 中 Trunk-Based vs GitFlow 等架构演进同源——都是规模、复杂度、协作方式变化倒逼的范式转移。
