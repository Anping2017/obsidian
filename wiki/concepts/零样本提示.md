# 零样本提示

## 定义

**零样本提示(Zero-shot Prompting)** 是最简单的 [[提示词工程]] 形态:不提供任何示例,仅通过清晰的自然语言指令让 [[大语言模型]] 直接完成任务。它依赖模型在预训练阶段已掌握的通识与指令理解能力,无须 [[预训练与微调]] 或 [[少样本提示]] 中的示例。

## 核心要点

**典型格式**

```
[角色]你是一位资深翻译。
[任务]请把以下中文翻译为英文。
[输入]今天天气真好。
[输出要求]只输出译文,不要解释。
```

**适用场景**

- 模型常见能力范围内的任务(翻译、总结、改写、提取)
- 任务边界清晰、输出形式简单
- 对成本敏感,希望尽量短的 prompt
- 快速原型验证

**何时不够用**

- 任务输出格式特殊、模型未必能猜对(此时改用 [[少样本提示]])
- 复杂多步推理(此时用 [[思维链]])
- 输出必须严格符合 schema(此时用 [[结构化输出]] 或 [[函数调用]])
- 极小模型上零样本几乎不可用(参见 [[涌现能力]])

**写好零样本提示的五条经验**

1. **指令开头说清楚**:角色、任务、目标各占一行,胜过塞在一段话里
2. **明确输出格式**:不写"答得清晰一点",而是"用 3 条要点回答"
3. **加约束而非否定**:正面说"中文回答",而非"不要用英文"
4. **关键约束放结尾**:模型对 prompt 末尾内容更敏感
5. **避免歧义**:把"分析"改成"列出 3 个原因并各给一句证据"

**常见反模式**

- 指令过于笼统("帮我看看这个数据")
- 多个任务塞在一个 prompt(模型可能只做最后一个)
- 用否定指令("不要…")模型容易反向理解
- 假设模型有它没有的上下文(如某公司内部术语)

## 和其他概念的关系

- 同级范式:[[少样本提示]](加示例)、[[思维链]](加推理步骤)
- 整体方法论:属于 [[提示词工程]] 最基础形态
- 能力前提:依赖 [[大语言模型]] 的指令遵循能力,小模型上效果差
- 经济性:[[Token]] 开销最低,[[Prompt Caching]] 收益相对小
- 可与 [[结构化输出]]、[[角色提示]] 组合使用
