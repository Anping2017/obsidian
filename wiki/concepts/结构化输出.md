# 结构化输出

## 定义

**结构化输出(Structured Output)** 让 [[大语言模型]] 严格按照预定义格式(JSON、YAML、XML、Markdown 表格、特定 schema)生成,从而使输出能被下游程序可靠地解析与处理。这是把 LLM 嵌入传统软件流水线的桥梁。

主流厂商均已提供原生支持:OpenAI 的 JSON mode 与 Structured Outputs、Anthropic 的 tool use schema、Google 的 controlled generation 等。

## 核心要点

**实现方式光谱**

| 方式 | 强度 | 代表 |
|---|---|---|
| Prompt 约束 | 弱(模型自觉) | "请输出 JSON" |
| Few-shot 示例 | 中 | 给几个 JSON 示例 |
| API JSON 模式 | 中-强 | OpenAI `response_format: json_object` |
| Schema 强制 | 强 | OpenAI Structured Outputs、Pydantic + Instructor、Anthropic Tools |
| 解码端约束 | 极强 | guidance、outlines、llama.cpp grammar,生成时屏蔽不合法 token |

**强 schema 是怎么做到的**

- 在解码每一步,根据当前已生成内容计算下一 token 必须满足的合法集合(如 JSON 解析器允许的)
- 把不合法 token 的概率置零,只在合法 token 中采样
- 结果:输出 100% 符合 schema,无须后处理

**典型场景**

- 信息提取:从合同/邮件抽出字段
- 多字段分类:同时输出标签 + 置信度 + 理由
- 表单填写:把自然语言转结构记录
- [[函数调用]]:本质就是结构化输出的特例
- 数据管道:LLM 作为流水线中的一环,下游工具消费 JSON

**最佳实践**

- 用 JSON 而非自由文本格式,后者容易出错
- 字段命名清晰、用枚举限制可选值
- 给出一个 minimal example 比堆叠形容词有效
- 字段顺序按"先确定后推断"组织,便于模型从已知推未知
- 监控 schema 失败率,作为 prompt 退化预警

**和 Markdown 的关系**

- Markdown 是给人看的"轻结构",并不强制
- 真正要给程序消费应当用 JSON / Schema
- 给人 + 程序双消费可考虑 JSON 嵌在 Markdown 代码块

## 和其他概念的关系

- 整体方法论:属于 [[提示词工程]] 输出控制部分(F in RTCF)
- 直接特例:[[函数调用]] 在协议层面强制结构化
- 协议化:[[MCP协议]] 中工具入参定义本质是 JSON Schema
- 工程价值:让 LLM 输出在自动化流水线中可靠消费
- 与 [[幻觉]] 关系:schema 约束减少格式幻觉但不解决事实幻觉
