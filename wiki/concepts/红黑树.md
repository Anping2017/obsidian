# 红黑树 Red-Black Tree

## 定义

红黑树(Red-Black Tree)是一种**自平衡的[[二叉搜索树]]**。每个节点带有一个颜色属性(红或黑),通过若干性质约束 + 旋转操作,使任意路径长度差不超过 2 倍,从而保证查找、插入、删除都在 O(log n) 时间内完成。

它由 Rudolf Bayer 1972 年提出(称「对称二叉 B 树」),Leonidas Guibas 与 Robert Sedgewick 1978 年正式命名为红黑树。

## 核心要点

### 五大性质

1. 每个节点要么红、要么黑
2. **根节点是黑**
3. 每个 NIL(空叶子)节点是黑
4. **红节点的两个子节点必须都是黑**(不可有连续两红)
5. **从任一节点到其后代任一 NIL 节点,经过的黑节点数相同**(黑高度,Black Height)

这些性质共同保证:从根到任一叶子的最长路径不超过最短路径的 2 倍。

### 维持平衡的操作

插入 / 删除可能违反性质,需要通过两种操作恢复:

1. **变色**(Recoloring):改变节点颜色
2. **旋转**(Rotation):左旋、右旋

```
左旋(以 X 为支点):
       X                 Y
      / \               / \
     a   Y      →      X   c
        / \           / \
       b   c         a   b
```

旋转操作 O(1) 完成,保持 BST 性质,改变高度分布。

### 插入流程概要

1. 像普通 BST 插入,新节点染红
2. 若父节点也是红(违反性质 4),进入修复:
   - 叔叔红:把父和叔变黑,祖父变红,递归向上
   - 叔叔黑且当前节点是「LR / RL」:先旋转父
   - 叔叔黑且「LL / RR」:旋转祖父 + 变色

最多 2 次旋转 + O(log n) 变色完成插入。

### 与 AVL 树对比

| 维度 | AVL | 红黑树 |
|---|---|---|
| 平衡严格度 | 严格(高度差 ≤ 1) | 较松(2:1) |
| 查找速度 | 略快(高度更小) | 略慢 |
| 插入/删除旋转次数 | 较多 | 较少 |
| 适用场景 | 查询多于修改 | 通用平衡 |

工业实现选红黑树的多,因修改性能更稳定。

### 实际应用

| 系统 | 用法 |
|---|---|
| Java TreeMap / TreeSet | 红黑树实现有序映射 |
| C++ std::map / std::set | GCC 实现是红黑树 |
| Linux 内核 CFS 调度 | 用红黑树按虚拟运行时间排序进程 |
| Linux 内核 epoll、定时器 | 红黑树管理事件 |
| Java HashMap 桶 | 链表过长时(默认 8)转红黑树降低退化风险 |
| Nginx 定时器、内存池 | 红黑树管理 |

## 和其他概念的关系

红黑树是 [[二叉搜索树]] 的自平衡变体,与 AVL、Treap、Splay 同属一族,共同回答「如何保证 BST 不退化」的问题。

它与 [[B+树]] 都属于「平衡多路/二路查找树」,但 B+ 树面向磁盘,红黑树面向内存。两者构成 [[数据库]] 索引、[[操作系统]] 数据结构的两大基石。

[[Hash表]] 与红黑树常组合使用:Java HashMap 用拉链法解决冲突,链长超阈值转红黑树以防 hash 攻击退化为 O(n)。这种「混合数据结构」是工业实践的智慧。

理解红黑树是深入 [[Linux内核]]、[[JDK 集合框架]]、[[C++ STL]] 实现的钥匙。许多看似神奇的 O(log n) 性能,底层都是红黑树。

[[算法]] 学习中,红黑树是对 [[二叉搜索树]] 与 [[复杂度分析]] 理解的综合考验,代码量相对大但思路清晰。
