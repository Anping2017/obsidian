# Odoo 多公司架构

## 定义

Odoo **多公司架构(Multi-Company)** 让一个 Odoo 实例的同一数据库内**同时承载多个法人公司**(集团子公司、连锁门店、跨国分支),数据按公司隔离,但用户可在被授权的公司间切换,跨公司交易(子公司间销售 / 内部调拨)由专门规则处理。是 Odoo 在 ERP 市场区别于单公司方案的关键能力。

## 核心要点

**数据隔离机制**

- 几乎所有业务模型都有 `company_id` 字段:产品、客户、订单、发票、库存、会计科目
- 系统通过 **ir.rule(记录规则)** 强制只显示用户当前所在公司的数据
- 用户在右上角公司切换器中选择"激活公司"决定看到的数据范围
- 多公司用户可同时勾选多个公司同时看(联合视图)

**核心模型的多公司行为**

| 模型 | 是否多公司 | 备注 |
|---|---|---|
| 产品 (product.product) | 可共享或专属 | 不设 company_id 即全局共享 |
| 联系人 (res.partner) | 默认共享 | 跨公司可见,但订单仍按公司隔离 |
| 销售订单 / 发票 | 按公司隔离 | 必有 company_id |
| 会计科目表 | 按公司 | 每公司独立 chart of accounts |
| 银行账户 | 按公司 | 不可跨公司 |
| 用户 | 跨公司 | 通过 company_ids 字段授权多公司 |

**跨公司交易(Inter-Company)**

通过 *inter_company_rules* 模块:
1. 公司 A 创建销售订单卖给公司 B(B 是 partner)
2. 系统自动在公司 B 创建对应**采购订单**
3. 发货 / 收货 / 发票各方独立记账,但单据互相关联
4. 集团合并报表汇总各公司

**会计层面的多公司**

- 每公司**独立 chart of accounts**(法人独立法定账)
- 每公司独立税务规则(不同国家不同税率)
- 货币:公司基础货币不同(美元 / 人民币 / 欧元),系统按汇率折算
- **集团合并报表**:通过 *consolidation* 应用按所有权比例合并

**用户与公司的多对多**

- 每用户有 `company_ids`(可访问的多公司)和 `company_id`(默认公司)
- 切换公司不需重新登录,但部分缓存会刷新
- 权限体系叠加:用户在 A 公司是销售员,在 B 公司是经理,可同时

**典型应用场景**

1. **连锁企业**:每家门店一个公司(独立税号),共享产品和员工
2. **跨国集团**:每国一个公司(本地币种、本地税率),共享客户库
3. **多品牌运营**:同一团队运营多个品牌主体
4. **企业内部分包**:研发公司-销售公司-生产公司分离

## 与其他概念的关系

多公司架构基于 [[Odoo安全模型]] 中的记录规则,与 [[Odoo部署架构]] 中的多租户(multi-tenant,数据库级隔离)是两种不同方案。多公司是同库,多租户是异库。在 [[Odoo电商模块]]、[[Odoo PoS销售点]] 中,门店常对应公司。

## 高频陷阱

- 用户切换公司后部分对话窗 / 草稿可能丢失,需保存
- 跨公司交易必须双向都启用 inter-company 规则,否则只单边自动化
- 产品 company_id 留空 = 全局共享,但价目表可能仍按公司
- 合并报表需各公司用相同 fiscal year,否则需用对账工具
- 第三方模块未必兼容多公司,自定义开发需考虑 company_id 过滤
