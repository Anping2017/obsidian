# 提示词工程五要素

## 定义

提示词工程(Prompt Engineering)是设计 LLM 输入以稳定获得高质量输出的实践。它不是"魔咒",而是 **把模糊意图转化为结构化指令** 的工程方法。LLM 越强大,这种转化的效率收益越高——同样的 GPT-4,差 prompt 输出鸡肋,好 prompt 输出近乎专家。

## 核心要点

### 五要素框架

任何 prompt 都可拆为五个组成部分:

1. **角色(Role)**:你是 X 领域 Y 年经验的 Z
2. **上下文(Context)**:背景信息,用户是谁,场景是什么
3. **任务(Task)**:具体要做什么,以动词开头
4. **约束(Constraints)**:不要做什么,字数/语气/格式限制
5. **输出格式(Format)**:Markdown / JSON / 表格 / 列表

缺其一就可能产出偏离预期。

### Lyra 的 4D 优化方法论

由 prompt 优化器 Lyra 提出的元方法,把"如何写 prompt"工程化:

- **Deconstruct(拆解)**:提取意图、实体、上下文,识别已给与未给
- **Diagnose(诊断)**:审计模糊点、缺失点、结构需求
- **Develop(开发)**:按任务类型选技术(创意 → 多角度,技术 → 约束,教学 → few-shot,复杂 → CoT)
- **Deliver(交付)**:写出最终 prompt 并附使用指南

### 进阶技术

- **Chain-of-Thought (CoT)**:让模型"逐步思考",在最终答案前展示推理过程,显著提升复杂推理任务准确率
- **Few-shot Learning**:在 prompt 中给 2-5 个示例,模型按示例风格输出
- **Multi-perspective**:让模型从多个角色/视角分析同一问题
- **Self-Critique**:先生成,再批评自己,再修订
- **Structured Output**:用 JSON Schema 限定输出格式,适合 API 集成

### JSON Prompt 模式

把视频脚本、图像描述、产品文案等转为 JSON 结构:

```json
{
  "scene": "湖边日落",
  "mood": ["宁静", "治愈"],
  "characters": [{"role": "妻子", "action": "煮咖啡"}],
  "camera": "wide shot, slow pan",
  "duration_seconds": 8
}
```

优点:可复用、可版本化、可批量生成、便于团队协作。

### 学习类 prompt 设计

教育/学习场景的 prompt 模式("学习大纲整理专家"、"深度学习教练"):

1. 角色定位为某学科教师/教练
2. 输出严格按"鸟瞰 → 拆解 → 重建 → 应用 → 反思"五段
3. 每段强制使用清晰的 markdown 标题与表格
4. 加入费曼技巧、间隔重复、刻意练习等 [[PKM方法论]] 元素

这种"结构化 + 教学法 + 自动化"的组合,可生成可执行的学习路径,而非泛泛的建议。

### 平台差异

- **ChatGPT/GPT-5**:擅长结构化分节,Custom Instructions 长期生效
- **Claude**:长上下文(1M token)和长输出友好,推理任务可用 thinking mode
- **Gemini**:多模态强,可处理长视频/PDF
- **国产**:DeepSeek 推理强、Kimi 长文档强、通义千问中文好

针对模型微调 prompt 比"通用最佳"更有效。

### 反模式

- **过度修饰**:加无意义形容词("世界顶级"、"绝对完美")
- **角色冲突**:既要"严谨学者"又要"幽默风趣"
- **指令矛盾**:"详细但简短"、"专业但通俗"
- **缺少示例**:复杂格式只描述不给样
- **一次问太多**:任务越多答案越平庸,拆解再问

### 迭代心态

最佳 prompt 不是一次写出的,是 **生成 → 评估输出 → 调整 prompt → 再生成** 的循环结果。把 prompt 视为可版本化的资产,Templater + Obsidian 可以保存好用的 prompt 库,这与 [[Obsidian插件生态]] 联动起来构建个人 AI 工作流。
