# 闭包 Closure

## 定义

**闭包(Closure)**是函数与其**定义时的词法环境(lexical environment)** 的绑定。即使外层函数已经返回,闭包仍能访问并修改其捕获的外部变量。

更形式化的定义:闭包是"自由变量(free variables)被绑定后的函数"。函数中引用的不是其参数也不是局部变量的标识符就是自由变量;闭包把自由变量"关闭(close over)"到当前作用域中。

## 核心要点

### 工作原理

每次函数调用产生一个执行上下文(activation record),包含其局部变量。普通语言的执行上下文在函数返回时销毁;但若内部函数被外部"持有",那么外层执行上下文必须保留 —— 因为内部函数还可能访问它的变量。

底层实现:外层执行上下文不是分配在调用栈,而在堆;内部函数对象隐含一个指针指向这个上下文(scope chain / environment record)。

### 经典例子

```js
function counter() {
    let n = 0;
    return function() {
        return ++n;
    };
}
const inc = counter();
inc(); // 1
inc(); // 2
```
`inc` 是闭包,持有外层 `counter` 中的 `n`。即使 `counter()` 调用已结束,`n` 仍存活。

### 闭包的用途

1. **数据封装/私有状态**:模拟"私有变量"(JavaScript 早期没有 class 私有字段)
2. **回调与异步**:`setTimeout(() => console.log(name), 1000)`,name 通过闭包捕获
3. **柯里化与部分应用**:`add(1)(2)` 第一次调用返回的函数闭包了 `1`
4. **模块模式**:IIFE(立即执行函数表达式)+ 闭包,曾是 JS 模块化的基础
5. **装饰器实现**:Python `@decorator`、JS 函数装饰器
6. **事件处理器**:DOM 事件绑定时常用闭包持有上下文

### 闭包陷阱:循环 + 异步

经典 JS 题:
```js
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 输出 3, 3, 3
}
```
原因:`var` 是函数作用域,所有闭包共享同一 `i`。修复:用 `let`(块作用域,每次迭代新绑定)或显式 IIFE 捕获。

### 内存泄漏

闭包持有外部变量 → 外部变量不被 GC 回收。常见泄漏:
- DOM 元素被闭包持有,即使从 DOM 树移除也不释放
- 长生命周期对象(全局)持有短生命周期闭包
- 解决:及时置 null、避免不必要的捕获

### 不同语言的闭包

| 语言 | 是否有闭包 | 备注 |
|---|---|---|
| JavaScript | ✓ | 由 var/let 作用域决定捕获方式 |
| Python | ✓ | 默认只读;`nonlocal` 关键字才能写 |
| Java | 部分 | Lambda 只能捕获 effectively final 变量 |
| C# | ✓ | Lambda、匿名函数 |
| Go | ✓ | 共享变量,goroutine 中需注意 |
| Rust | ✓ | 三种 Fn/FnMut/FnOnce 区分捕获方式 |
| C++ | ✓(C++11+) | Lambda 显式声明捕获:[=]、[&]、[x] |
| Lisp/Scheme | ✓ | 闭包概念的发源地 |

### [[函数式编程]]的视角

闭包是函数式编程实现"状态"的方式 —— 表面上"无变量",其实通过函数嵌套与捕获保持状态。Lisp、Scheme、Haskell 把闭包视为基本工具,Y 组合子、Monad 都依赖闭包。

## 和其他概念的关系

闭包与作用域、提升(hoisting)、变量生命周期紧密相连。它是[[函数式编程]]的核心机制:柯里化、记忆化、装饰器都依赖闭包。

[[设计模式]]中"命令模式"、"策略模式"、"观察者模式"在 FP 视角下退化为简单的闭包传递。Linus 反对 OOP 的"过度封装",但闭包的"轻封装"在 Linux 内核也大量使用(回调函数 + 上下文指针,本质是 C 风格闭包)。

[[操作系统]]的延续(continuation)、协程(coroutine)与闭包都涉及"保存执行上下文"的概念,异曲同工。
