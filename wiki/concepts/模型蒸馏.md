# 模型蒸馏

## 定义

**模型蒸馏**(Knowledge Distillation, KD)是 Geoffrey [[Hinton]] 等人在 2015 年论文 *Distilling the Knowledge in a Neural Network* 中提出的训练技术:让一个**小模型(学生 Student)**学习**大模型(教师 Teacher)**的行为,以达成"小型化但保留主要能力"的目标。

它是模型压缩的三大方法之一(另两个是 [[模型量化]] 与剪枝),被 BERT-Distilled、DistilBERT、TinyLlama 等广泛采用,也是 OpenAI、Anthropic、DeepSeek 内部模型蒸馏的核心方法。

## 核心要点

### 核心思想:软标签胜过硬标签

传统监督学习用**硬标签**(one-hot,如 [0,0,1,0]):
- 损失函数仅惩罚错误类
- 只学到"对/错"

蒸馏用**软标签**(教师输出的概率分布,如 [0.05, 0.10, 0.80, 0.05]):
- 包含教师对类间相似性的隐性知识
- 学到"为什么对、为什么不那么错"

### 损失函数

```
L_distill = α × L_CE(student, hard_label) 
          + (1-α) × T² × KL(p_T_student || p_T_teacher)

其中 T 是温度(Temperature),软化概率分布:
p_T(x_i) = exp(z_i/T) / Σ exp(z_j/T)
```

- T = 1:标准 softmax
- T 较大(2-10):分布更软,展现"次优答案"的关系
- α 平衡硬标签监督与软标签蒸馏

### 主要类型

#### 1. 响应蒸馏(Response-Based / Output Distillation)

学生模仿教师的最终输出概率分布。最简单经典方式。

#### 2. 特征蒸馏(Feature-Based)

学生模仿教师的中间层特征表示。
- FitNets:对齐隐层激活
- Hint Layer:在指定层加蒸馏损失

#### 3. 关系蒸馏(Relation-Based)

学生模仿教师**样本间的关系**(如样本相似性矩阵),而非单个输出。

#### 4. 自蒸馏(Self-Distillation)

教师与学生为同一架构的不同检查点,把后期版本知识传给早期版本,提升训练效率。

### LLM 蒸馏的特殊形态

#### Sequence-Level 蒸馏

针对生成式模型,让学生生成的整个序列模仿教师生成的序列。
- DeepSeek-V3 的 R1 推理能力被蒸馏到 V3 系列
- LLaMA 7B 蒸馏自更大模型获得更强能力

#### Reasoning Distillation

让学生学习教师生成的[[思维链]]:
- 教师生成 CoT 答案
- 学生在监督学习中模仿包含推理步骤的回答
- 显著提升小模型推理能力

DeepSeek R1 把推理能力蒸馏到 7B/14B 小模型,让消费级硬件也能运行强推理模型。

#### 黑盒蒸馏(Black-Box Distillation)

教师只提供输出(没有 logits),如通过 API 访问 GPT-4。
- 训练数据 = 教师生成的(输入, 输出)对
- 仅响应蒸馏的形式
- 法律风险:教师方 ToS 通常禁止用其输出训练竞品

OpenAI 与 ByteDance 关于"是否使用 GPT 训练豆包"的争论是典型案例。

### 经典工程案例

| 模型 | 教师 | 压缩 |
|---|---|---|
| DistilBERT | BERT-base | 40% 减小,97% 性能保留 |
| TinyBERT | BERT-base | 7.5× 压缩 |
| DistilGPT-2 | GPT-2 | 50% 减小 |
| MobileBERT | BERT-large | 4.3× 压缩,移动端可用 |
| TinyLlama | LLaMA-2 7B | 1.1B 参数 |
| Phi-2 / Phi-3 | 合成数据 + 蒸馏 | 微软 SLM 系列 |

### 优势

- 小模型推理快、内存少、部署便宜
- 在监督数据有限时,教师作为"丰富监督源"
- 学生通常优于直接训练同尺寸的模型
- 与 [[模型量化]] 联合使用效果倍增

### 局限

- 学生不会"超越"教师
- 教师必须先训练好,成本传导
- 黑盒蒸馏存在法律与商业风险
- 复杂推理任务上小模型仍有上限

### 蒸馏 vs 微调

| 维度 | 蒸馏 | 微调 |
|---|---|---|
| 出发点 | 学生模型从零或预训练开始 | 已有模型适应新任务 |
| 监督源 | 教师模型 | 标注数据 |
| 目标 | 复制能力 | 增加新能力 |

许多框架混合两者:用教师生成蒸馏数据,再用其微调学生。

### 与其他技术的协同

```
压缩流水线:
1. 蒸馏(模型变小) → 2. 量化(精度变低) → 3. 剪枝(稀疏化)
              ↓
         多技术协同 = 极致部署效率
```

### 道德与商业争议

- 通过 API 蒸馏闭源模型可能违反 ToS
- "数据洗白":用未授权模型生成数据训练模型
- 知识产权边界:模型权重 vs 模型行为
- DeepSeek R1 是否蒸馏自 OpenAI o1 的争论

## 和其他概念的关系

- 与 [[模型量化]]、剪枝构成模型压缩三大方法
- 应用于 [[大语言模型]]、[[Transformer架构|Transformer]]、CNN 各类模型
- 与 [[预训练与微调]] 形成不同的小模型策略
- [[Hinton]] 等深度学习先驱的代表性贡献
- 在 [[思维链]]、推理能力传递上有专门发展
- 与 [[蒸馏式自监督]]、[[强化学习]] 中的奖励建模可类比
- 边缘部署场景下与 [[模型量化]] 联用
