# 面向对象编程 OOP

## 定义

**面向对象编程(Object-Oriented Programming, OOP)**是一种以**对象**(数据 + 行为的封装单元)为中心的程序设计[[编程范式]]。它把程序看作"对象间消息传递"的过程,与面向过程(以函数为中心)、[[函数式编程]](以纯函数和不可变数据为中心)对立。

OOP 由 Alan Kay 在 Smalltalk 中提出 ——"消息传递"才是核心,但流行语言(Java、C++、C#、Python、Ruby)以"类与继承"为外在形式。

## 核心要点

### 四大特性

1. **封装(Encapsulation)**:把数据和操作捆绑,通过访问修饰符(public/private/protected)隐藏内部细节。优势:隔离变化、保证不变式。
2. **继承(Inheritance)**:子类复用父类属性和方法,建立"is-a"层次。
3. **多态(Polymorphism)**:同一接口不同行为。子类型多态(继承+方法重写)和参数多态(泛型)。
4. **抽象(Abstraction)**:用抽象类/接口定义"做什么"而不规定"怎么做"。

### 类、对象、实例

- **类(Class)**:类型,模板,蓝图
- **对象 / 实例(Object/Instance)**:类的具体化,占用内存
- **构造函数(Constructor)**:创建实例时调用
- **析构函数(Destructor)**:销毁时调用,常用于释放资源(C++ RAII)

### 继承的几种形式

- **单继承**(Java、C#):每个类一个父类
- **多重继承**(C++、Python):多个父类,可能引发"菱形继承"二义性
- **接口/Trait/Mixin**:解决多继承痛点

Java 用接口 + 默认方法、Python 用 MRO(C3 算法)、Scala/Ruby 用 Mixin/Trait。

### 静态分发 vs 动态分发

- **静态(Static)**:编译期决定调用,如 C++ 普通成员函数、Java static 方法
- **动态(Dynamic)**:运行期根据对象实际类型调用,如 Java/C# 实例方法、C++ virtual 函数 — 这是**多态**的实现机制
- 通过虚函数表(vtable)实现:对象头部隐含指针指向类的方法表

### OOP 的批评

- **继承层次过深** → 牵一发动全身,Joshua Bloch 主张"组合优于继承"
- **共享可变状态** 在并发下棘手,需要锁
- **Banana-Monkey-Jungle 问题**:想要香蕉,却要捎上猴子和丛林
- **过度抽象** 让简单问题变复杂,Linus 著名的"Don't tell me about your damn Object Mafia"

近年趋势:Go、Rust 不强调继承(只保留组合 + 接口);Kotlin、Swift 鼓励 data class + sealed class;函数式范式回潮。

### 与其他范式融合

现代主流语言基本都是**多范式**:
- Java/C# 加入 lambda、stream、record
- Python 兼具 OOP 和函数式
- Scala、Kotlin 显式融合 OOP + FP
- C++ 同样支持泛型编程、模板元编程

OOP 不是"对错"问题,是"工具适配"问题。

## 和其他概念的关系

OOP 是[[设计模式]]的语言载体 —— 大多数 GoF 模式以类与对象的关系表达。[[设计原则SOLID]]是 OOP 设计的伦理。[[设计模式]]是 OOP 的常用解法集合。

[[函数式编程]]从不同角度组织程序:数据不可变、函数无副作用、用组合代替继承。[[微服务]]架构在系统层面体现 OOP 思想:每个服务"封装"自己的数据和行为,通过 API 通信。

[[数据库]]中的关系模型(表/行/列)与对象模型存在"阻抗失配"(Object-Relational Impedance Mismatch),催生 ORM 框架(Hibernate、SQLAlchemy、Active Record)。
