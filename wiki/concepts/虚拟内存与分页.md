# 虚拟内存与分页

## 定义

**虚拟内存(Virtual Memory)** 是 [[操作系统]] 提供给每个进程的独立地址空间抽象——进程看到 0 到 2^48(典型 64 位)的连续地址,实际物理内存由 OS 透明管理。**分页(Paging)** 是把虚拟与物理地址空间切成固定大小(典型 4KB)页面、用页表记录映射关系的方法。

## 核心要点

- **核心收益**
  - **进程隔离**:进程间地址不重叠,A 写不到 B 的内存。
  - **按需调页(Demand Paging)**:页面首次访问时才从磁盘加载,启动快、内存利用率高。
  - **超额分配**:虚拟空间总和可远超物理,通过 swap 缓冲。
  - **共享内存**:不同进程虚拟页映射同一物理页,实现快速 IPC。
  - **内存映射 I/O**:`mmap` 把文件映射为内存,简化文件 I/O。
- **页表结构**
  - 多级页表(x86_64 四级:PML4 → PDPT → PDT → PT)节省空间。
  - **TLB(Translation Lookaside Buffer)**:CPU 内置快表缓存近期翻译,命中率影响性能极大。
  - **Huge Page**:2MB/1GB 大页,减少 TLB miss,适合大堆服务。
- **缺页异常(Page Fault)**
  - **次缺页(Minor)**:页面在内存但映射未建立 —— 快。
  - **主缺页(Major)**:需从磁盘 swap 或文件读入 —— 慢,可见 IO 等待。
- **替换算法**:LRU 近似(Linux 用双链表 + active/inactive 列表)、Clock、Working Set。
- **写时复制(COW)**:fork() 后父子进程共享物理页,任一方写入才复制——大幅加速进程创建。
- **NUMA 与内存绑定**:多 CPU 架构下不同节点访问代价不同,需 `numactl` 等工具调优。

## 关系

- 是 [[操作系统]] 内存管理的核心机制,所有现代 OS(Linux/Windows/macOS)都基于此。
- 与 [[内存管理]] 在用户态的 GC/手动管理是上下游关系——malloc 底层向内核请求虚拟页。
- [[Docker容器]] 不虚拟化内存,与宿主共享内核;但 cgroup 限制内存用量。
- 数据库引擎(PostgreSQL、MySQL)用 mmap 或自管 buffer pool 与虚拟内存交互。
- 与 [[I/O模型]]:零拷贝技术(sendfile、splice)绕过用户态拷贝,基础是页映射。
- 与 [[Web安全]]:ASLR 利用虚拟内存随机化抵御内存攻击。
