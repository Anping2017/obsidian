# 思维树

## 定义

**思维树**(Tree of Thoughts, ToT)是 **Shunyu Yao** 等人在 **2023 年** 论文《Tree of Thoughts: Deliberate Problem Solving with Large Language Models》中提出的提示工程范式,核心是**把推理过程组织为树结构,在每一步生成多个候选"思维(thought)"分支,通过搜索算法(BFS、DFS、剪枝)与价值评估选择最优路径**。它扩展了线性的 [[思维链]](CoT),把 LLM 推理升级为类似人脑的"深思熟虑"(System 2)模式。

## 核心要点

### 与 CoT 的对比

| 维度 | CoT | ToT |
|---|---|---|
| 结构 | 线性链 | 树状 |
| 生成 | 一条思路一条路 | 每步多分支 |
| 搜索 | 无 | BFS / DFS / 剪枝 |
| 自评 | 无 | 中间状态评价 |
| 回溯 | 不可 | 可放弃错误路径 |
| 适合 | 直觉式、明确 | 探索式、需规划 |
| 计算 | 1×LLM 调用 | n×m×LLM 调用 |

### 四个核心组件

#### 1. 思维分解(Thought Decomposition)

把任务分解为若干"思维步",每步是有意义的中间状态:
- 数学题:每个推理步骤
- 创意写作:段落或情节
- 24 点游戏:每次合并两数
- 填字游戏:每个单词
- 编程:每个函数 / 模块

#### 2. 思维生成(Thought Generation)

每步从当前状态生成 k 个候选:
- **采样(Sample)**:同一 prompt 多次采样,温度 > 0
- **建议(Propose)**:让模型显式列出 k 个不同方案

#### 3. 思维评估(State Evaluation)

判断每个候选好坏:
- **价值打分**:让 LLM 给当前状态打分(0-10)
- **投票**:对所有候选投票选最佳
- **可行性预测**:预测能否最终达到目标

#### 4. 搜索算法(Search Algorithm)

- **广度优先(BFS)**:每层保留前 b 个状态,继续扩展
- **深度优先(DFS)**:沿一条路深入,失败回溯
- **A***:启发式搜索,价值高优先
- **MCTS**:蒙特卡洛树搜索,适合大空间

### 经典案例:24 点游戏

给 4 个数字,通过四则运算得 24:

**CoT 失败模式**:
- 先选哪两个数没有"远见"
- 错了无法回头

**ToT 解法**:
1. 第一层:列出所有"两数操作"(可能 24 个组合)
2. 给每个候选打分:能否达到 24
3. 保留前 5 个,扩展第二层
4. 重复直至剩 1 数 = 24

**结果**:GPT-4 用 CoT 成功率 4%,用 ToT 提升至 74%。

### Prompt 模板

ToT 不是单一 prompt,而是一组 prompt + 搜索控制:

```
[Generation Prompt]
当前状态: {state}
请提出接下来 5 个可行的思路,每个一行。

[Evaluation Prompt]
当前状态: {state}
判断这个状态有多大可能达到目标 {goal}?
打分 1-10。

[Search Loop in Code]
while not is_goal(state):
  candidates = generate(state, k=5)
  scores = [evaluate(c, goal) for c in candidates]
  state = top_b_by_score(candidates, scores)
```

### 与其他范式的关系

- **CoT**:ToT 的"链"是 ToT 的特例(b=1, 深度为目标)
- **Self-Consistency**:多采样取众数,但不构建树
- **Plan-and-Solve**:先规划再执行,不显式搜索
- **MCTS**:更系统的搜索算法,DeepMind AlphaZero 风格
- **ReAct**:加入工具调用,可与 ToT 结合

### 思维图(Graph of Thoughts, GoT)

Besta 等 2023 进一步推广:
- 不仅树(每节点一父),允许图(每节点多父)
- 可合并不同分支思路
- 更灵活但更复杂

### 实战权衡

**优势**:
- 复杂任务大幅提升成功率
- 显式探索 + 回溯
- 中间状态可解释、可审查

**劣势**:
- LLM 调用次数 b × m × LLM(指数)
- 成本高,延迟长
- 价值函数难定义(评估器本身可能错)
- 工程复杂

**适用场景**:
- 数学竞赛题、谜题
- 复杂规划(项目计划、策略游戏)
- 创意写作的多分支探索
- 需要"反悔"的搜索式任务

**不适用**:
- 简单查询、对话
- 快速响应需求
- 评估器难以构建的开放任务

### 与其他改进的对比

| 方法 | 核心 | 提升 | 成本 |
|---|---|---|---|
| CoT | 线性推理 | +20% | 1× |
| Self-Consistency | 多采样投票 | +5-10% | n× |
| ToT | 树搜索 + 评估 | +50%+(难题) | n×m× |
| ReAct | 加工具 | 视任务 | n× + 工具 |
| Reflexion | 失败反思 | 视任务 | 多轮 |

### 实现框架

- **TreeOfThought 库**:Princeton-NLP 官方实现
- **LangChain ToT**:封装好的 chain
- **LMQL**:声明式语言,支持搜索控制

## 和其他概念的关系

思维树是 [[思维链]] 的进化形式,在结构上从线性变为树状。它与 [[ReAct提示]] 在处理复杂任务上互补——ToT 重内部推理,ReAct 重外部交互。它与 [[Reflexion]] 在"自我改进"思想上相通,但 Reflexion 是事后反思,ToT 是过程中探索。它扩展了 [[少样本提示]] 与 [[零样本提示]] 的应用边界。在 [[大语言模型应用栈]] 中,ToT 是 "高级推理" 模块的代表性技术。它与认知心理学中"系统 1 vs 系统 2"思维的对比直接呼应。
