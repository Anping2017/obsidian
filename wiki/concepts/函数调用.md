# 函数调用

## 定义

**函数调用(Function Calling / Tool Use)** 是让 [[大语言模型]] 按预定义 JSON Schema 输出结构化工具调用请求,从而调用外部 API、数据库、代码执行器等的能力。它把 LLM 从"只会聊天"升级为"能行动"。

OpenAI 在 2023 年 6 月发布 Function Calling,Anthropic、Google、开源模型相继跟进,如今是 LLM 应用工程的事实标准。

## 核心要点

**调用流程**

1. 开发者定义工具集(name + 描述 + 参数 schema)随 prompt 一并提供
2. 用户提问 → 模型判断是否需要工具
3. 需要时输出特殊格式:`{tool: "search_web", arguments: {q: "..."}}`
4. 应用执行实际调用,把结果再喂回模型
5. 模型基于结果生成最终回答(可多轮)

**典型工具类别**

- 信息检索:网页搜索、向量库([[RAG]])、知识库
- 计算:代码执行(Python sandbox)、计算器
- 数据查询:数据库 SQL、内部 API
- 行为类:发邮件、创建工单、控制设备
- 元能力:调用其他 LLM、子 Agent

**为什么有效**

- 解决 [[幻觉]]:让模型把"算"和"查"外包给确定性工具
- 解决知识过时:实时数据每次现取
- 解决精确执行:代码 / SQL 由专用引擎执行,不靠模型自我推演
- 解决多步任务:一连串工具调用串成 [[AI Agent]] 工作流

**工程注意点**

- 工具描述质量决定调用准确度
- 模型可能"幻觉"参数(传入不存在字段),需校验
- 错误恢复:工具失败时模型应能解读错误并调整
- 安全:工具能力越强越要权限隔离、审批门禁
- 标准化:[[MCP协议]] 把工具发现与调用从厂商锁定解放

## 和其他概念的关系

- 直接服务对象:[[AI Agent]] 的能力底座
- 协议化标准:[[MCP协议]] 把工具暴露与发现协议化
- 与 [[RAG]] 互补:RAG 是"查文档",函数调用是"调 API",合称外部知识/能力注入
- 主要益处:大幅缓解 [[幻觉]],提供事实性回答
- 与 [[结构化输出]]:函数调用本质上是结构化输出的特例
