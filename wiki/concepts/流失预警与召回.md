# 流失预警与召回

## 定义

流失预警与召回(Churn Prediction & Win-back)是用机器学习模型基于用户行为衰减信号预测每个用户的"流失概率",并在他们真正流失前触发个性化召回动作的客户运营战术。它源自一个朴素事实:挽回流失客户的成本是新增客户的 1/5,挽回流失高价值客户的 LTV 影响是新增普通客户的 5-10 倍——所以"防止流失"比"拉新"更值得投资。SaaS、订阅服务、电商、银行业都依赖此战术。

## 核心要点

**流失定义(Churn Definition)**:

不同业务模型有不同流失定义:

- **订阅业务**:用户主动取消订阅 / 不续费。
- **App / 工具**:N 天未启动(常 30 / 60 / 90 天)。
- **电商**:N 天未购买(取决品类:快销品 30 天,3C 180 天)。
- **B2B SaaS**:看 NRR(Net Revenue Retention),负流失或缩减。
- **银行 / 金融**:账户余额 < 阈值或 N 天无交易。

**流失预测模型**:

### 输入特征(Behavioral Signals)

- **使用频次衰减**:最近 7 天 vs 上 7 天的活跃比。
- **关键功能使用降低**:核心动作不再做。
- **Session 时长缩短**。
- **打开 Push / 邮件比例下降**。
- **客服投诉次数增加**。
- **支付失败 / 拒付**(订阅业务)。
- **降级套餐**。
- **询问取消政策 / 退款流程**。
- **NPS 低分 + 文字情绪负面**。

### 模型选择

- **逻辑回归**:解释性强,适合早期。
- **决策树 / 随机森林**:能处理非线性,出特征重要性。
- **XGBoost / LightGBM**:工业级标配,准确率高。
- **深度学习**:用 LSTM / Transformer 处理用户行为序列,大企业用。
- **生存分析(Cox Regression)**:不仅预测会不会流失,还预测什么时候。

### 输出

- 每个用户一个流失概率分数(0-1)。
- 阈值划分:0-0.3(健康)、0.3-0.6(预警)、0.6-1.0(高危)。
- 模型按月 / 周重训练,新行为信号纳入。

**召回策略 — 分层应对**:

### 1. 早期预警(概率 0.3-0.5)

- **触发器**:活跃下降但未真正流失。
- **动作**:
  - 个性化内容推荐(他喜欢的内容触达)。
  - 价值提醒("您还没用过 X 功能")。
  - 邀请评分 / NPS 调研(主动了解原因)。
- **目标**:让他重新活跃,不必降价。

### 2. 高危(概率 0.5-0.8)

- **触发器**:多个负面信号叠加。
- **动作**:
  - 优惠券 / 折扣("您的专属 20% 折扣")。
  - 客服主动外呼 / 一对一咨询。
  - 个性化案例研究(其他用户的成功故事)。
- **目标**:重新建立连接 + 给小利益。

### 3. 极高危(概率 > 0.8)

- **触发器**:几乎确定要流失。
- **动作**:
  - 大力度挽留(免费月 / 一对一服务 / 专属客户经理)。
  - 高管层介入(B2B 大客户)。
  - 调研:"我们如何能改进?"
- **目标**:不只挽留,更要了解为什么流失,改进产品。

### 4. 已流失(N 天未活跃)

- **Win-back 邮件序列**:见 [[邮件序列设计]]。
- **专属优惠**:仅给已流失用户的特殊价格。
- **告别邮件**:即使要走,留好印象,未来还会回来。

**关键 KPI**:

- **流失率(Churn Rate)**:本期流失数 / 期初用户数。
- **保留率(Retention Rate)** = 1 - 流失率。
- **CLV / LTV 影响**:流失对 [[客户终身价值]] 的破坏量化。
- **召回率(Win-back Rate)**:被召回成功比例(目标 5-15%,行业基准 5%)。
- **预警准确率**:模型预测高危中真正流失的比例。
- **每召回 1 个客户的成本 vs 重新拉新 1 个客户的成本对比**(目标:召回 < 拉新 1/3)。

**B2B vs B2C 流失差异**:

| 维度 | B2C | B2B |
|---|---|---|
| **流失信号** | 行为衰减为主 | 决策方变更 / 财年变化 / 竞品介入 |
| **召回成本** | 中(优惠券) | 高(销售投入) |
| **召回 ROI** | 5-15% | 30-50% |
| **响应方** | 客服 / 营销 | CSM / 客户经理 / 高管 |

**实施挑战**:

- **数据基础**:需要 [[CDP客户数据平台]] 完整行为数据。
- **跨部门协同**:营销 / 客服 / 销售 / 产品都要参与。
- **隐私合规**:监控行为不能侵犯隐私。
- **召回动作设计**:不只是发优惠券,需要个性化方案库。
- **避免"召回焦虑"**:对刚进入预警的用户过度强势挽留 → 反感离开。

**反模式**:

- **流失定义模糊**:每个部门定义不同,数据无法对齐。
- **预测模型不更新**:用户行为模式变化,模型很快失准。
- **召回动作单一**(只用优惠券)→ 价格敏感用户被惯坏,不敏感用户被忽视。
- **不区分原因**:产品问题 / 服务问题 / 价格问题 / 竞品挖角不同应对。
- **召回成本算不过来**:每个高危用户给 50% 折扣,总成本 > 挽回 LTV。
- **不做失败复盘**:即使召回失败也不分析为什么,下次仍犯同样错误。

## 和其他概念的关系

流失预警与召回是 [[CRM]]、[[CDP客户数据平台]]、[[营销自动化]] 的高阶应用,也是 [[客户终身价值]](LTV)与 [[客户复购]] 提升的核心战术。它依赖 [[同期群分析]] 度量真实流失曲线、[[客户细分]] 识别高风险群、[[机器学习]] 模型做预测。

它与 [[激活率]] 是因果链的两端——激活率决定漏斗顶部留住率,流失预警决定漏斗底部继续保有率。在 [[AARRR模型]] 中,Retention 环节的核心战术正是流失预警与召回。

[[B2B营销]] 中流失预警与 NRR(Net Revenue Retention)、Customer Health Score 紧密绑定,CSM(Customer Success Manager)的核心 KPI 之一就是低流失。在 [[订阅经济]] 时代,流失预警是公司估值的核心驱动——SaaS 公司估值与 NRR 强相关,NRR > 120% 享显著估值溢价。
