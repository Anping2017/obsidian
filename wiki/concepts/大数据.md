# 大数据 Big Data

## 定义

大数据(Big Data)指**单机或传统数据库难以在可接受时间内捕获、存储、管理、分析的数据集合**,以及**为应对这类数据所发展的技术、方法与文化**。它不仅是「数据多」,更是「需要新范式」。

经典 Doug Laney 三 V 定义后扩展到 5V:

- **Volume 体量**:从 TB 到 PB 到 ZB
- **Velocity 速度**:实时流式产生与处理
- **Variety 多样**:结构化、半结构化、非结构化
- **Veracity 真实性**:质量、噪声、可信度
- **Value 价值**:从海量低密度信息提炼商业价值

## 核心要点

### 技术栈演进

| 阶段 | 代表 | 特征 |
|---|---|---|
| 数据仓库时代 | Teradata、Oracle DW | 集中式 MPP,价格昂贵 |
| Hadoop 时代(2006-2015) | HDFS + MapReduce + Hive | 通用硬件 + 开源,但写代码繁琐 |
| Spark/流处理 | Spark、Flink、Kafka | 内存计算 + 低延迟 + SQL 友好 |
| 云原生数仓 | Snowflake、BigQuery、Redshift | 计算存储分离、按需付费 |
| 数据湖屋(Lakehouse) | Iceberg、Delta、Hudi | 兼具数据湖灵活与数仓 ACID |
| 流批一体 | Flink、Materialize、Pinot | 实时分析与离线统一 |

### 核心组件

- **存储**:HDFS、对象存储(S3、GCS)、列式格式(Parquet、ORC)
- **计算引擎**:Spark、Flink、Presto/Trino、Druid
- **消息流**:[[Kafka]]、Pulsar、Kinesis
- **资源调度**:YARN、Kubernetes、Mesos
- **数据格式**:Parquet、Avro、ORC、Iceberg
- **查询接口**:Hive SQL、Spark SQL、Presto SQL
- **机器学习**:Spark MLlib、TensorFlow on K8s、Ray

### Lambda 架构 vs Kappa 架构

[[Lambda架构]] 双管齐下:批处理保正确,流处理保低延迟,代价是双份代码。
[[Kappa架构]] 用流处理一统,通过重放历史数据做离线计算。

现代数据栈(Modern Data Stack)推动统一存储格式 + Lakehouse,使两套架构走向融合。

### 应用场景

- 用户画像与推荐(YouTube、Netflix、抖音)
- 实时风控(支付、广告反作弊)
- 商业智能与决策支持
- IoT 与时序监控
- 自然科学(基因组、天文、气象)
- 大模型训练数据准备

### 挑战

- 数据治理:权限、血缘、质量
- 成本控制:存算资源监控,避免账单失控
- 隐私合规:GDPR、CCPA、个保法
- 团队协同:数据工程师、分析师、科学家、工程师协同复杂

## 和其他概念的关系

大数据与 [[数据库]]、[[数据仓库]] 的边界日益模糊——OLAP 数据库(ClickHouse、Doris)与大数据引擎(Spark)在很多场景互相替代。[[OLAP与OLTP]] 的差异决定了选型。

[[ETL与ELT]] 是把业务数据导入大数据平台的工具链;[[列式存储]] 是大数据查询性能的关键。

[[人工智能]] 与大数据深度耦合:深度学习的崛起依赖海量数据;反过来,大数据平台越来越内置 ML 能力(如 Snowflake Snowpark ML、Databricks)。

[[云计算]] 让大数据从专属基础设施转向「按需付费」,大幅降低了门槛;[[边缘计算]] 与大数据组合形成「云边端」数据流转架构。

[[分布式系统]] 的众多理论(MapReduce 编程模型、Quorum 复制、容错)都源于或服务于大数据系统。
