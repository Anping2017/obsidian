# 操作系统进程内存 OS Process Memory

## 定义

进程内存(Process Memory)是 [[操作系统]] 为每个进程分配的**独立虚拟地址空间**,典型 64 位系统每个进程拥有理论 256TB 的虚拟地址。该空间被划分为多个段(segment),每个段有不同用途、不同权限,共同支撑程序执行。

## 核心要点

### 虚拟地址空间布局(Linux 进程)

```
┌────────────────────────────┐ 高地址
│   内核空间 (高 1/4 或 1/2)  │  用户态不可访问
├────────────────────────────┤
│       栈 (Stack)           │  自高向低增长,函数调用、局部变量
│            ↓               │
│                            │
│    内存映射区 (mmap)        │  共享库、文件映射、匿名映射
│                            │
│            ↑               │
│       堆 (Heap)            │  自低向高增长,动态分配
├────────────────────────────┤
│  BSS 段(未初始化全局变量)  │  零填充
├────────────────────────────┤
│  数据段(已初始化全局变量)  │  从可执行文件读入
├────────────────────────────┤
│  代码段 (Text)              │  只读 + 可执行,机器指令
└────────────────────────────┘ 低地址(通常 0x400000)
```

### 各段特征

| 段 | 权限 | 来源 | 增长方向 |
|---|---|---|---|
| 代码段(.text) | r-x | 可执行文件 | 静态 |
| 数据段(.data) | rw- | 可执行文件 | 静态 |
| BSS 段(.bss) | rw- | 零初始化 | 静态 |
| 堆 | rw- | brk/sbrk/mmap 申请 | 向高增长 |
| 内存映射 | 可变 | mmap 系统调用 | 双向 |
| 栈 | rw- | 进程创建时分配 | 向低增长 |
| 内核空间 | -- | OS 私有 | 共享 |

### 关键机制

- **虚拟地址 → 物理地址**:由 MMU + 页表完成,详见 [[虚拟内存与分页]]
- **写时复制(COW)**:fork 时父子共享物理页,写入时才复制
- **内存映射(mmap)**:文件直接映射进虚拟地址,避免 read/write 系统调用开销
- **共享内存**:多进程映射同一物理页实现进程间通信
- **守卫页(Guard Page)**:栈底无访问权限,栈溢出触发段错误

### 常见问题

- **段错误(Segmentation Fault)**:访问无权限地址(如解引用空指针、越界写)
- **栈溢出**:递归过深、巨大局部数组
- **堆碎片**:频繁 malloc/free 不同大小,glibc malloc 用 bins 缓解
- **内存泄漏**:malloc 后忘记 free,常见于无 GC 语言

## 和其他概念的关系

进程内存是 [[操作系统]] 与 [[编程语言比较|编程语言]] 的桥梁——每种语言的内存模型最终落到这个布局上。[[C语言]] 暴露指针让程序员直接管理;[[内存管理|Python内存管理]]、[[Java垃圾回收]]、[[Go]] 在堆上自动管理但栈仍由编译器决定。

[[虚拟内存与分页]] 让进程觉得拥有独立大空间,实际由 OS 调度物理内存与磁盘交换。[[Page Cache]]、[[内存映射 mmap]] 是 [[文件系统]] 性能的关键。

[[缓冲区溢出]]、[[Use-After-Free]]、ROP 攻击都源于进程内存模型的细节;[[内存安全]] 语言(Rust)从语言层面消除这类问题。

[[进程与线程]] 共享同一进程的代码段和堆,但栈独立;[[fork]] 与 [[exec]] 系统调用决定了 Unix 进程模型。
