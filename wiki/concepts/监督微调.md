# 监督微调

## 定义

监督微调(Supervised Fine-Tuning, SFT)是在[[预训练与微调]]范式下的"微调"阶段:用高质量的指令-响应对作为训练数据,通过标准的语言建模损失继续训练[[大语言模型]],使其学会遵循指令、给出格式化回答。

## 与预训练的区别

| 维度 | 预训练 | SFT |
|---|---|---|
| 数据 | 海量无标签文本 | 人工标注指令-响应对 |
| 规模 | 万亿 token | 万-百万样本 |
| 损失 | 自回归语言建模 | 仅在响应部分计算损失 |
| 目标 | 学会"语言" | 学会"听话" |

## 数据来源

- 人工编写(Anthropic 早期、Vicuna)
- LLM 自动生成(Self-Instruct、Alpaca)
- 公开开放数据集(OpenOrca、SlimOrca)
- 角色扮演 / 多轮对话(Wizard、UltraChat)

## 关键技术

- **Loss Masking**:仅对 assistant 段计算损失,不让模型学用户指令的复述
- **Packing**:多个样本拼接成一条训练序列以提高 GPU 利用率
- **LoRA / QLoRA**:参数高效微调,降低显存需求
- **多轮 SFT**:让模型学会维持对话上下文

## 后续阶段

SFT 输出的模型称为 SFT 模型,但仍有局限:
- 不知如何处理冲突指令
- 倾向给"看起来好"的答案
- 缺乏拒绝有害请求的训练

因此一般还要走:
- [[RLHF]] / [[DPO直接偏好优化]] / [[Constitutional AI]] 进行偏好对齐

## 与其他概念的关系

- 是[[指令微调]]的实现方式之一
- 是 [[RLHF]] 与 [[DPO直接偏好优化]] 的前置步骤
- 与 [[预训练与微调]] 共同构成现代 LLM 训练范式
- 在 [[GPT系列模型]] InstructGPT 论文中首次系统化
- 与 [[Constitutional AI]] 形成对比(后者用 AI 反馈替代部分人工)

## 实践工具

- HuggingFace TRL 库
- Axolotl、LLaMA-Factory(中文社区主流)
- Unsloth(QLoRA 加速)
- DeepSpeed / FSDP 分布式
