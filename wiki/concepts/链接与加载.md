# 链接与加载

## 定义

**链接(Linking)** 是把编译产生的多个目标文件(`.o`/`.obj`)及库文件合并,并解析跨模块符号引用,最终生成可执行文件或共享库的过程。**加载(Loading)** 是 [[操作系统]] 把可执行文件读入内存、设置内存映像、跳转到程序入口的过程。两者衔接编译与运行。

## 核心要点

- **静态链接(Static Linking)**
  - 编译期把库代码完整复制进可执行文件;产物自包含、无依赖。
  - 优点:部署简单,启动快;缺点:体积大,库升级需重新链接。
  - 典型:Go、Rust 默认输出。
- **动态链接(Dynamic Linking)**
  - 库以共享对象形式存在(`.so`/`.dll`/`.dylib`),运行时由动态链接器解析。
  - 优点:多进程共享同一物理副本,节省内存;库可独立升级。
  - 缺点:启动稍慢、版本兼容问题(Linux 的 SOVERSION、Windows DLL hell);典型工具 `ld.so` / `ldd`。
- **符号解析**
  - 强符号(已定义函数/变量)与弱符号(extern 声明)按 ELF/PE 规则匹配。
  - 重定位表记录哪些地址需要在链接或加载时填充。
- **可执行文件格式**
  - **ELF**(Linux):.text/.data/.bss/.rodata 段,节头表 + 程序头表。
  - **PE**(Windows):IMAGE_NT_HEADERS,导入/导出表。
  - **Mach-O**(macOS):多架构 fat binary。
- **加载步骤**(Linux 简化)
  1. `execve` 系统调用读取 ELF 头。
  2. 解析程序头表,`mmap` 映射代码、数据段。
  3. 若动态链接,加载 `ld.so` 解析依赖。
  4. 调用 `__libc_start_main` → `main`。
- **位置无关代码(PIC)** 与 **ASLR**:共享库与可执行文件用 PIC 实现地址空间随机化,提升安全。
- **延迟绑定(Lazy Binding)**:首次调用时才解析 PLT/GOT 表项,加速启动。

## 关系

- 是 [[编译vs解释]] 流水线的"运行前"两环——编译输出 → 链接 → 加载 → 执行。
- [[操作系统]] 进程创建依赖加载器和 [[操作系统进程内存]] 布局。
- [[AOT编译]] 产物常静态链接,简化分发。
- 与 [[Docker容器]]:容器镜像是加载视角的"打包",镜像层包含可执行文件 + 共享库,绕开宿主依赖管理。
- 与 [[Web安全]]:GOT/PLT 劫持、ROP gadget 是常见的内存安全漏洞利用面。
