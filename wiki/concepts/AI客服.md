# AI客服

## 定义

AI 客服(AI Customer Service / Conversational AI)指使用大语言模型(LLM)+ 检索增强(RAG)+ 业务系统集成构建的自动化对话客服系统。它能 7×24 小时响应用户咨询,处理 70-90% 的标准化问题(产品咨询、订单查询、退换货、常见故障、政策解读),只把复杂 / 情绪 / 高价值案例转人工。它是 2023 后 [[CRM客户关系管理|CRM]] 与 [[营销自动化]] 演进的核心方向,也是 [[AI×营销]] 落地最快、ROI 最直接的领域之一。

## 核心要点

**技术架构 — 现代 AI 客服三层**:

### 第 1 层 — LLM(大语言模型)基础

- **国际**:OpenAI GPT-4o、Claude Sonnet 4、Gemini 2.5。
- **国产**:通义千问、文心一言、智谱 GLM、DeepSeek、Kimi、豆包。
- **专用**:阿里通义千问 客服版、智谱 GLM 客服版。
- **本地化部署**:LLaMA、Qwen 开源模型 + 私有微调。

### 第 2 层 — 知识库 + RAG(检索增强)

- 把企业的产品手册、FAQ、客服历史对话、政策文档、订单系统接入。
- 用户提问 → 向量检索 → 找到相关知识片段 → LLM 基于检索内容生成答复。
- 关键技术:[[Embedding]] + [[向量数据库]] + [[RAG]]。

### 第 3 层 — 业务系统集成

- 订单系统:查订单、改地址、申请退款。
- 物流系统:查物流状态。
- 用户中心:查会员等级、积分余额、订阅状态。
- CRM:看用户画像与历史。
- 通过 Function Calling / Tool Use 调用各系统 API。

**核心场景**:

### 1. 售前咨询

- 产品参数对比、适用人群、使用建议。
- 库存查询 / 配送时效。
- 优惠政策解读。
- **AI 客服优势**:即时响应、不下班、处理万人并发。

### 2. 订单服务

- 订单查询、修改地址、催发货、申请退款、申请换货。
- **关键**:必须接系统 API,不仅生成文字答复。
- 用户体验上,从"打电话等 5 分钟"变"对话框秒级回复"。

### 3. 售后服务

- 故障诊断:用户描述故障 → AI 引导排查 → 给出解决方案 → 必要时转维修。
- 退换货流程:AI 引导填表、告知周期、跟踪进度。
- 常见 FAQ:政策解读、使用方法。

### 4. 主动外呼 / 主动关怀(Outbound)

- 物流到达通知、签收提醒。
- 满意度调研。
- 续费 / 复购提醒。
- 流失预警的挽回触达。

**关键能力**:

- **多轮对话上下文**:记住对话历史,理解指代。
- **意图识别**:用户说"我要退货" → 进入退货流程,不要继续推荐商品。
- **情绪识别**:愤怒 / 失望 / 满意 → 对应不同应对策略。
- **多语言**:海外品牌客服支持英 / 西 / 法 / 阿 / 中等。
- **多模态**:图片 / 视频上传(用户传产品故障图,AI 识别)。
- **转人工无缝**:AI 处理不了立刻转人工 + 把对话上下文同步给人工。

**部署形态**:

- **网站 Web Chat**:右下角对话窗口。
- **App 内嵌客服**:用户中心入口。
- **微信公众号 / 客服**:中国主流。
- **企业微信 / 小红书客服**:私域阵地。
- **电话呼叫中心 IVR + 语音 AI**:自动语音应答。
- **WhatsApp / Telegram / FB Messenger**:海外主流通道。

**主流厂商 / 工具**:

- **国际**:Intercom、Zendesk、Freshworks、Drift、Ada、Dialogflow CX、Microsoft Copilot Studio。
- **国产**:阿里小蜜、小冰、讯飞客服、网易七鱼、容联七陌、智齿科技、Udesk。
- **新一代**:基于 LLM 的 AI 客服(2024+)崛起,如 Sierra、Decagon。

**关键 KPI**:

- **首次响应时间**:< 1 秒(AI 客服优势)。
- **解决率(Resolution Rate)**:AI 直接解决 / 总咨询。健康线:简单问题 80%+。
- **转人工率**:AI → 人工的转接率,反映 AI 能力天花板。
- **用户满意度(CSAT)**:对 AI 客服会话的评分。
- **NPS / CES(客户费力度)**:综合体验度量。
- **每次会话成本**:AI 客服 0.1-0.5 元 vs 人工 5-20 元 vs 电话 10-50 元。
- **AI 替代率**:AI 处理量 / 总咨询量,健康线 70%+。

**实施关键点**:

1. **知识库梳理**:把企业知识结构化,这是 70% 的工作。"垃圾进垃圾出"。
2. **意图分类清晰**:常见 20-30 个意图覆盖 80% 流量。
3. **回退策略**:AI 不确定时不要瞎答,转人工。
4. **持续学习**:每周复盘 bad case,加入训练 / Prompt 调整。
5. **人工兜底**:AI 客服 ≠ 全自动,复杂 / 情绪场景必须人工。
6. **合规审查**:涉及金融 / 医疗 / 法律的回答需合规过滤。

**反模式**:

- **盲目 100% 替代人工**:复杂案例机械应付,客户愤怒升级。
- **不接业务系统**:AI 只能聊,不能解决问题,沦为"礼貌答辩"。
- **不持续优化**:上线就不管,效果衰减。
- **不告知用户是 AI**:违反一些地区的法规(欧盟 / 加州);失去信任。
- **答复"我无法帮你处理"过多**:用户感到被拒。

## 和其他概念的关系

AI 客服是 [[CRM客户关系管理|CRM]] / [[客户关系管理]] 与 [[营销自动化]] 在 [[AI×营销]] 时代的革命性升级,也是 [[私域流量运营]] 的智能化触手。它在 [[转化漏斗]] 的售前 / 售后两端都直接影响转化率与复购率。

它的技术栈与 [[RAG]]、[[Embedding]]、[[向量数据库]]、[[大语言模型]]、[[AI Agent]] 同源,可视为 LLM 落地最成熟的 ToB 应用之一。在 [[CDP客户数据平台]] 中,AI 客服的对话日志是新型用户画像数据来源——文字描述比行为数据更直接表达需求。

[[销售KPI体系]] 中,AI 客服分担了人工销售 / 客服的工作,让人专注高价值案例。在 [[B2B营销]] 中,AI 客服 + 销售 RoBot(SDR Bot)正在自动化线索资格审核(MQL → SQL)。
