# 提示词反模式

## 定义

**提示词反模式**(Prompt Anti-Patterns)指 [[提示词工程]] 中**常见但有害的 prompt 写法**——它们看似合理但实际上降低 [[大语言模型]] 输出质量、增加 token 浪费、引入意外行为。

学习反模式与学习正确模式同等重要——大多数失败的 prompt 不是创新不够,而是踩了已知陷阱。

## 核心要点

### 反模式 1:过度限制(Over-constraining)

#### 表现

```
请写一篇文章,要求:
- 严格 1000 字,误差不超过 ±5 字
- 必须包含 7 个段落
- 第 3 段必须以"然而"开头
- 包含 3 个引用,每个 25-35 字
- 不能用任何表语
- ...(20 条规则)
```

#### 问题

- 模型无法严格满足字数等量化要求
- 多重约束相互冲突
- 模型注意力分散于规则,损失内容质量
- 可能直接违背某些规则

#### 改进

```
请写一篇约 1000 字的文章,
结构包含引言、3 个核心论点、结论,
适当引用专家观点。
```

只保留**重要的、可验证的**约束。

---

### 反模式 2:模糊指令(Vague Instructions)

#### 表现

```
帮我看看这段代码。
```

#### 问题

模型不知道用户想要:
- 解释代码做什么?
- 找 bug?
- 评审代码风格?
- 优化性能?
- 添加注释?
- 重构?

#### 改进

```
请审查这段 Python 代码,关注:
1. 是否有内存泄漏风险
2. 算法时间复杂度是否最优
3. 错误处理是否完善

如发现问题,给出修改建议代码。
```

具体到**做什么、关注什么、输出什么**。

---

### 反模式 3:信息冲突(Conflicting Instructions)

#### 表现

```
请用专业的学术语气,但不要太正式。
答案要全面,但保持简洁。
要详细解释,但不要超过 50 字。
```

#### 问题

互斥要求让模型在两端权衡,结果两边不讨好。

#### 改进

明确**单一目标**或**优先级**:
```
请用专业但易懂的语气解释,
长度控制在 100 字以内,
若必须更长,优先简洁性。
```

---

### 反模式 4:负面指令(Negative-only)

#### 表现

```
不要冗长。不要使用复杂词汇。不要包含个人意见。
不要 ... 不要 ... 不要 ...
```

#### 问题

- LLM 对正面指令更敏感
- 大量"不要"占用注意力
- "不要想象一只粉色大象" 反而强调那只象

#### 改进

转为正面表述:
```
保持简洁(每段 < 3 句)。
使用日常词汇。
仅陈述客观事实。
```

如必须用否定,放在正面之后:
```
请按客观事实回答,不要加入主观判断。
```

---

### 反模式 5:角色破坏(Role Breaking)

#### 表现

```
你是一位资深医生,为我提供诊断建议。
顺便,你也是一位律师,告诉我法律问题。
还有,你是一位程序员,写一段 Python 代码。
```

#### 问题

- 角色冲突,模型不知用哪个视角
- "都精通"暗示削弱专业性
- 输出质量降低

#### 改进

每个角色单独 prompt 或分子任务:
```
你是医生,请诊断 ...
[新对话]
你是律师,请评估 ...
[新对话]
你是程序员,请实现 ...
```

---

### 反模式 6:示例污染(Bad Few-Shot)

#### 表现

提供质量低或风格不一致的示例:
```
任务:翻译以下英文为简洁中文

示例 1:
EN: Hello
ZH: 你好啊朋友!希望今天过得愉快...

示例 2:
EN: Goodbye  
ZH: bye

请翻译:Welcome
```

#### 问题

- 示例风格不一致 → 模型不知道目标
- 低质量示例直接降低输出质量
- 少数示例的偏差被放大

#### 改进

示例应:
- 风格一致
- 质量高
- 覆盖主要变体
- 数量适当(2-5 个常足够)

---

### 反模式 7:幻觉诱导(Hallucination Inducing)

#### 表现

```
请告诉我这本不存在的书《量子社会主义》的主要观点。
```

或

```
请引用 5 篇 2025 年关于 X 的论文,给出准确标题、作者、期刊、页码。
```

#### 问题

- 直接要求 LLM 编造它不知道的信息
- 模型为满足要求会生成虚假内容
- 用户难以察觉

#### 改进

```
请告诉我关于 X 的核心观点,如果你不确定,说不知道而不要猜测。
如有引用,请只用你确定真实存在的来源。
```

或用 [[RAG]] 给模型真实文献。

---

### 反模式 8:过度礼貌(Over-politeness)

#### 表现

```
你好!希望你今天过得开心!不知道是否方便,如果不打扰的话,
能不能请你考虑帮我做一个小小的尝试,可能的话,
看看能不能写一段代码呢?当然如果不方便也完全没关系...
```

#### 问题

- 浪费 token
- 真正指令隐藏在客套话中
- 模型可能误把客套当指令

#### 改进

```
请用 Python 写一个排序函数,要求 ...
```

直接,清晰。礼貌没有错,但不需冗长。

---

### 反模式 9:超长上下文塞满

#### 表现

把完整 1MB 文档塞进 prompt 让模型回答简单问题。

#### 问题

- 注意力分散("中间迷失"现象)
- 关键信息可能被忽略
- 成本高
- 延迟大

#### 改进

- 用 [[RAG]] 只检索相关片段
- 摘要后再 prompt
- 拆分多次小 prompt

---

### 反模式 10:逐字格式控制

#### 表现

```
输出必须严格如下:
"答案是:[X]"
其中 [X] 为数字,前后加双引号,无任何其他字符。
```

#### 问题

模型偶尔会:
- 加句号
- 加换行
- 用单引号
- 加解释

#### 改进

- 用结构化输出(JSON Schema、Pydantic)
- 用 function calling
- 后处理清洗

---

### 反模式 11:从零教导(Reinventing the Wheel)

#### 表现

把通用任务的所有步骤都列在 prompt 中:
```
要分析数据,请:
1. 先看数据类型
2. 再看分布
3. 检查缺失值
... (20 步)
```

#### 问题

- 模型已经有这些常识
- 占 token、限制创造性
- 维护成本高

#### 改进

```
请分析这份数据,关注 ... (你想强调的特殊点)
```

只指定**领域特有**或**与默认不同**的部分。

---

### 反模式 12:不一致的角色和任务

#### 表现

```
你是一位友善的客服。请用严厉的语气拒绝用户退款请求。
```

#### 问题

人格设定与任务指令冲突,模型在两端摇摆。

#### 改进

让人格与任务一致:
```
你是一位专业的客服。请按照公司退款政策处理用户请求,
即使需要拒绝,也要保持理解与共情。
```

---

### 反模式 13:技术术语堆砌

#### 表现

```
请用 SOLID 原则、DDD、CQRS、Hexagonal Architecture、
Event Sourcing、Saga Pattern、CRDT、Bulkhead 模式...
```

#### 问题

- 模型无法精确理解所有术语在你具体上下文中的含义
- 可能生成"看起来对"的代码,实际不符合你需求
- 导致华而不实

#### 改进

具体说明:
```
我有一个微服务架构,需要在订单服务和库存服务间保持最终一致性。
请实现一个 ... 解决方案。
```

---

### 反模式 14:过度依赖单一 prompt

#### 表现

试图用一个 mega-prompt 完成复杂多步任务。

#### 问题

- prompt 难维护
- 中间错误难调试
- token 成本高

#### 改进

拆分为多个步骤,每步独立 prompt(prompt chaining):
```
Step 1 prompt:抽取关键信息
Step 2 prompt:基于信息分析
Step 3 prompt:生成最终输出
```

或用 [[AI Agent框架]] 的 chain / graph 结构。

---

### 识别反模式的检查清单

```
□ 我的指令是否单一明确?
□ 是否存在冲突要求?
□ 限制是否真的必要?
□ 角色和任务是否一致?
□ 示例(若有)质量是否高?
□ 我是否在让模型编造?
□ 上下文是否过长?
□ 我是否过度规定细节?
```
