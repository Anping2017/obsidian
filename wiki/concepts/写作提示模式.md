# 写作提示模式

## 定义

写作提示模式是面向[[大语言模型]]执行各类文本创作任务的提示工程方法集合。其核心理论是:写作 = 角色 × 结构 × 风格 × 迭代。

## 四要素框架(RSSI)

### R - Role(角色)

```
你是《纽约客》风格的特稿作者,擅长用细节叙事承载洞察。
```

具体角色比抽象"作家"更有效。可参考:行业(科技博主)、刊物(《经济学人》)、个人(海明威)。

### S - Structure(结构)

不同文体有不同结构,先指定:
- 议论文:论点-论据-反驳-结论
- 故事:情境-冲突-高潮-解决
- 营销文:AIDA(Attention-Interest-Desire-Action)
- 教程:背景-步骤-验证-延伸
- 邮件:开门见山-理由-请求-感谢

### S - Style(风格)

- 长度(短/中/长,具体字数)
- 节奏(短句多 vs 长句多)
- 语调(正式/口语/讽刺/温暖)
- 修辞偏好(类比、反问、列举)
- 第几人称

### I - Iteration(迭代)

```
先生成大纲 → 我反馈 → 写第一段 → 我反馈 → 完整稿 → 修订
```

不要一次到位,分阶段优化。

## 经典模板

### 长文章模板

```
角色:[资深科技作家]
受众:[CTO 与 VP 工程]
目标:[让他们理解 X 的战略价值]
结构:故事开头 → 数据支撑 → 反例 → 行动建议
风格:正式但不学究,1500-2000 字
迭代:先给我大纲与三种开头,我选一个再写完。
```

### 邮件模板

```
为我起草一封 [recipient] 邮件,目的 [goal]。
长度 < 150 字。语气 [polite/firm]。结构 [opening - context - ask - close]。
请提供 3 个备选开头。
```

## 关键技巧

- **避免 AI 标志词**:在 System Prompt 中禁用 "delve, navigate, leverage, in conclusion"
- **风格示例**:贴一两段你想要的风格样本作为 in-context
- **修订指令**:不只说"改",而说"砍掉前两段、把第三段改成第一段、降低形容词密度"

## 反模式

- 提示太短("写一篇文章")
- 一次性出整稿,不允许迭代
- 不指定受众
- 表面要"创意"但实际想要规范
- 让 AI 出标题但不规定数量与风格
