# 大语言模型应用栈

## 概述

[[大语言模型]] 本身只是个文本输入输出的概率模型,要把它变成可靠的产品,需要在其之上构建完整的工程栈。这一栈层既不写在论文里,也未必出现在模型权重中,而是工程师每天打交道的实际系统:[[提示词工程]] 控制输入,[[RAG]] 注入外部知识,[[函数调用]] 与 [[MCP协议]] 接入工具,[[AI Agent]] 编排多步任务,[[Prompt Caching]] 优化成本,[[模型评估]] 持续监控质量。

## 多角度分析

### 分层视图

```
┌──────────────────────────────────────────┐
│  产品层(对话、IDE 助手、客服、自动化等)│
├──────────────────────────────────────────┤
│  Agent 编排(规划、记忆、反思、多 Agent)│
├──────────────────────────────────────────┤
│  能力扩展层                               │
│   - RAG(检索 + 向量数据库)              │
│   - 函数调用 / MCP(工具与外部系统)      │
│   - 结构化输出(JSON Schema)             │
├──────────────────────────────────────────┤
│  提示词工程层                             │
│   - System Prompt、零样本 / 少样本 / CoT │
│   - 角色提示、提示词链                    │
├──────────────────────────────────────────┤
│  推理优化层(KV Cache、Prompt Caching、量化)│
├──────────────────────────────────────────┤
│  基础模型层(LLM:GPT/Claude/Gemini/Llama)│
└──────────────────────────────────────────┘
```

### 输入侧:[[提示词工程]]

- [[System Prompt]] 定义产品身份与边界
- [[零样本提示]] / [[少样本提示]] 引导任务
- [[思维链]] 释放复杂推理
- [[结构化输出]] 让程序消费可靠

### 知识层:[[RAG]]

- [[Embedding]] + [[向量数据库]] 完成检索
- 切块、重排、混合检索是工程关键
- 解决 [[幻觉]]、私有知识、知识更新三大痛点

### 能力层:[[函数调用]] 与 [[MCP协议]]

- 让 LLM 能查实时数据、调代码、操作系统
- [[MCP协议]] 把工具生态从厂商锁定中解放
- 是 [[AI Agent]] 的能力底座

### 编排层:[[AI Agent]]

- ReAct、Plan-Execute、Tree of Thoughts 等推理模式
- 短期记忆(上下文)+ 长期记忆(向量库 / 数据库)
- 多 Agent 协作(角色分工)

### 经济与性能层

- [[Prompt Caching]] 大幅降本提速
- 模型路由:简单请求走小模型,复杂走大模型
- 量化、推理加速
- 监控 [[Token]] 消耗、首 token 延迟、错误率

### 评估与安全层

- 持续 [[模型评估]]:任务能力、回归测试、用户满意度
- 防御 [[提示注入]]:多层纵深、最小权限、人在回路
- [[幻觉]] 监控与降低
- 红队测试与渗透演练

### 与传统软件栈的关系

- LLM 应用是新型 Stack,但仍离不开 DB、缓存、消息队列、可观测性
- 产品仍要做用户体验、错误处理、灰度发布
- 工程师的能力分布是"传统后端 + LLM 工程"的杂交

## 结论

大语言模型应用栈是**当下软件工程最快变化的领域**,堆栈中每一层每年都在重大演进:模型能力扩展使部分中间层变薄(超长上下文降低 RAG 必要性),协议标准化让能力层趋同([[MCP协议]]),Agent 编排框架激烈竞争。**对工程团队的实际启示**:基础模型选型不是终点,真正的护城河在数据(私有语料)、流程(评估与迭代)和工具集成深度;在快速变化中保持架构松耦合、可观测、可替换比押注某一层"最优解"更重要。
