# 编程语言比较

## 概述

编程语言不是"哪门最好",而是"哪门最适合当前问题与团队"。每种主流语言都是设计者在多个维度上的权衡结果:**类型系统**、**内存管理**、**抽象代价**、**并发模型**、**生态**、**可读性**等。

本主题对照 wiki 已涉及的语言(JavaScript / TypeScript、Python、Node.js、PHP、HTML/CSS),拓展到 Java、Go、Rust、C++ 等,从工程视角横向比较。

## 多角度分析

### 按类型系统

| 类型 | 静态/动态 | 强/弱 | 代表 |
|---|---|---|---|
| 静态强 | 编译期检查类型 | 不允许隐式转换 | Java、C#、Go、Rust、Haskell、Swift、Kotlin |
| 静态弱 | 编译期 | 大量隐式转换 | C/C++ |
| 动态强 | 运行期 | 严格 | Python、Ruby、Erlang |
| 动态弱 | 运行期 | 宽松 | JavaScript(早期)、PHP |
| 渐进式 | 可加可不加 | 取决于注解 | TypeScript(JS+静态)、Python type hints |

**渐进式类型**(TypeScript、Python type hints、PHP 7+ 类型声明)是当代主流——大型项目几乎不可能没有静态类型的辅助。

### 按内存管理

- **手动**:C、C++(智能指针缓解)。极致性能,但内存泄漏/野指针风险
- **垃圾回收(GC)**:Java、C#、Go、Python、JS、Ruby。开发友好,但 GC 暂停
- **引用计数**:Python、Swift。简单确定,需破环
- **所有权 + 借用**:Rust。编译期检查,无 GC 也无段错误,但学习陡峭

### 按运行时

| 类型 | 启动 | 性能 | 代表 |
|---|---|---|---|
| 编译为机器码 | 即开即用 | 极高 | C/C++/Rust/Go |
| JVM/CLR | 较慢(预热) | 高(JIT) | Java/Kotlin/Scala/C# |
| 解释执行 | 快 | 中 | Python/Ruby/PHP |
| JIT | 快 | 高 | JavaScript(V8) |
| AOT | 启动极快,体积小 | 高 | GraalVM 编译 Java |

### 按[[编程范式]]倾向

- **OO 主导**:Java、C#、C++(部分)
- **OO + FP 融合**:Kotlin、Scala、Swift、TypeScript、Python
- **FP 优先**:Haskell、OCaml、F#、Erlang、Clojure
- **过程式**:C
- **多范式统一**:Rust(系统级 + ADT + Trait)

### 并发模型

| 语言 | 模型 |
|---|---|
| Java/C# | OS 线程 + 锁、Future |
| Go | goroutine + channel(CSP) |
| Erlang | Actor 模型 + 不可变 |
| Kotlin | Coroutine |
| Python | asyncio(协程) + GIL 限制多线程 |
| JS/Node | [[事件循环]] 单线程 + Worker |
| Rust | OS 线程 + ownership 安全 + tokio |

### 主流语言速览

#### Java

- 1995 Sun Microsystems
- "Write once, run anywhere"(JVM)
- 面向企业,强类型、OO、生态庞大
- 框架:Spring、Spring Boot、Hibernate
- 适合:大型企业应用、Android、安卓 / 后端、Hadoop / Spark

#### Python

- 1991 Guido van Rossum,可读性至上
- 动态强类型,GIL 限制 CPU 多线程
- 巨大数据科学/AI 生态(NumPy、pandas、PyTorch、TensorFlow)
- 慢但开发快
- 适合:数据分析、机器学习、脚本、Web 后端(Django/Flask/FastAPI)

#### JavaScript / TypeScript

- 1995 Brendan Eich 浏览器脚本,后扩展到全栈([[Node.js|Node]])
- 单线程[[事件循环]]、动态类型
- TypeScript 加静态类型,大型前端必备
- 适合:浏览器、Node 后端、跨平台(React Native、Electron)

#### Go

- 2009 Google,简化系统编程
- 静态类型、GC、内置 [[并发与并行|并发]](goroutine + channel)
- 编译快、二进制单文件、部署简单
- 适合:云原生(Docker、Kubernetes、etcd 都是 Go 写的)、网络服务、CLI

#### Rust

- 2010 Mozilla,内存安全 + 零成本抽象
- 所有权 + 生命周期,编译期 catch 大多数内存 bug
- 学习曲线陡,但社区年度评比"最受爱戴"长青
- 适合:系统编程、性能敏感后端、WASM、嵌入式、新兴区块链

#### C++

- 1979 Bjarne Stroustrup,C 加 OO 加泛型
- 极致性能、零成本抽象,但复杂度爆表
- 现代 C++(11/14/17/20/23)显著进化
- 适合:游戏引擎(Unreal)、浏览器(Chromium)、数据库(MySQL、ClickHouse)、HFT

#### PHP

- 1995 Rasmus Lerdorf,动态弱类型(早期)→ 渐进式强化
- WordPress、Laravel、Symfony 主导 Web 后端
- 性能不高但社区庞大,小公司部署快
- 8.x 性能/类型系统大跃进

#### Kotlin / Swift

- Kotlin:JVM 上的现代化 Java 替代,Android 官方语言
- Swift:Apple 主推,iOS/macOS

#### Erlang / Elixir

- Erlang:1986 Ericsson,Actor + 不可变 + 软实时,运行 WhatsApp/Discord
- Elixir:Erlang VM 上,语法更现代

### 选型决策矩阵

| 场景 | 推荐 |
|---|---|
| 大型企业应用 | Java、C# |
| 高并发后端 API | Go、Rust、Java |
| 数据分析、AI | Python、R |
| 系统编程、嵌入式 | C、Rust、C++ |
| Web 前端 | TypeScript |
| 跨平台 App | Flutter(Dart)、React Native(JS/TS) |
| iOS 原生 | Swift |
| Android 原生 | Kotlin |
| 高性能游戏 | C++ |
| 脚本、原型 | Python、JS |
| 区块链 | Rust、Solidity、Go |

## 结论

### 多语言能力的价值

- 不同问题适合不同工具(避免金锤子)
- 学新语言提升对编程范式、系统的理解
- 工程实践:核心服务用 Java/Go,数据/AI 用 Python,前端用 TS,边缘脚本用 shell

### 语言之间的迁移

- 静态 ↔ 动态:难度中等
- OO ↔ FP:思维切换最难
- GC ↔ 手动/所有权:认知重构
- 学第二门语言加深第一门理解

### 趋势观察

- 静态类型 / 渐进式类型回潮
- 内存安全语言(Rust)在系统编程领域取代 C/C++ 部分场景
- WASM 让多语言编译到统一目标
- 协程 / 异步成主流并发抽象
- 单语言生态 → 多语言混合架构常态
