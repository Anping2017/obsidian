# 现代云原生架构

## 概述

**云原生(Cloud Native)** 是 CNCF 定义的"在动态、分布式、云环境中构建和运行可扩展应用"的方法论。其核心是把分布式系统的复杂性(部署、伸缩、容错、监控、安全、配置)下沉到统一的基础设施,让业务代码专注价值创造。现代云原生架构由**容器编排、服务网格、Serverless、可观测性、CI/CD、基础设施即代码** 六大支柱构成,共同支撑"高可用、弹性、自愈、声明式"的分布式应用。

## 多角度分析

### 1. 部署与运行层:从 VM 到 Serverless 的演进

云计算十年演进可概括为:**VM → 容器 → Kubernetes → Serverless → AI 原生云**。

- **VM 时代(IaaS,2010s)**:AWS EC2 把物理机虚拟化,弹性按需付费替代自建机房。但每 VM 仍要 OS、配置、运维。
- **容器时代([[Docker容器]])**:OS 级别隔离,启动秒级,镜像可移植,见 raw"容器化+微服务"。
- **K8s 时代([[Kubernetes]])**:自动调度、扩缩、自愈,事实上的容器编排标准。控制面 + 工作节点 + Pod / Service / Deployment 抽象。
- **Serverless 时代**:AWS Lambda / Vercel / Cloudflare Workers,开发者不再关心服务器,事件触发按调用计费。
- **边缘计算 + 云融合**:见 raw"边缘计算 + 云融合",把算力推到 CDN 节点,毫秒级响应。

### 2. 服务通信:从直连到服务网格

[[微服务]] 间通信经历从硬编码 IP → 服务发现 → 服务网格的演进:

- **早期**:配置文件 / DNS,扩缩容必重启
- **[[服务发现]]**:Eureka / Consul / etcd,服务注册查询动态化
- **[[API网关]]**:统一入口,处理认证 / 限流 / 路由
- **[[服务网格]]**:sidecar 代理透明拦截,把通信治理(LB / 熔断 / mTLS / 追踪)下沉到基础设施
- 现代架构中,**网关管南北流量,网格管东西流量**,组合使用

异步通信靠 [[消息队列]](Kafka / RabbitMQ / NATS / SQS)实现服务解耦、流量削峰、最终一致性,见 [[BASE理论]]。

### 3. 数据层:多模态共存

云原生数据层通常**多种数据库共存(Polyglot Persistence)**:

- **[[关系型数据库]]**:核心交易,MySQL / PostgreSQL / Aurora / PolarDB
- **[[NoSQL数据库]]**:不同模型适配不同场景
  - KV:[[缓存]] Redis / DynamoDB
  - 文档:MongoDB
  - 列族:Cassandra / HBase / ScyllaDB
  - 图:Neo4j / JanusGraph
- **[[数据仓库]]**:Snowflake / BigQuery / Redshift,做 [[OLAP vs OLTP]] 中的 OLAP
- **数据湖 / 湖仓**:S3 + Delta / Iceberg
- **时序**:InfluxDB / TimescaleDB
- **搜索**:Elasticsearch + [[倒排索引]]
- **向量**:Pinecone / Milvus + [[向量数据库]]

[[分库分表]]、[[读写分离]]、[[缓存]] 是单库优化的常用手段。NewSQL(TiDB / CockroachDB / Spanner)用 [[Raft共识算法]] 把分布式事务下沉到数据库层。

### 4. 可观测性:从监控到三支柱融合

云原生应用的复杂性使"监控"演进为"[[可观测性三支柱]]":

- **指标(Metrics)**:[[Prometheus]] + Grafana,RED/USE 黄金信号
- **日志(Logs)**:Fluentd / Loki / ELK,结构化 + trace_id 关联
- **追踪(Traces)**:Jaeger / Tempo,跨服务调用链
- **统一标准**:[[OpenTelemetry]] 合并三支柱采集

KPI 指标驱动 [[熔断与降级]]、[[限流]] 阈值,以及 [[灰度发布与蓝绿部署]] 决策。

### 5. 安全:零信任 + 全程加密

云原生安全采用**零信任(Zero Trust)** 模型:

- **身份认证**:OAuth 2.0、JWT、Passkeys / FIDO2
- **传输加密**:[[TLS]] / mTLS,服务网格内自动加密
- **密钥管理**:HashiCorp Vault / AWS KMS
- **WAF / 反爬**:CDN 边缘部署
- **机密计算**:加密状态下运算,SGX / Confidential VM
- **策略即代码**:OPA / Kyverno 在 K8s 内实施
- 见 [[Web安全]]

### 6. CI/CD 与 IaC:声明式即一切

- **CI/CD**:GitHub Actions / GitLab CI / Jenkins / ArgoCD
- **GitOps**:Git 是真理之源,Argo CD / Flux 自动同步集群状态
- **IaC**:Terraform / Pulumi / CloudFormation,基础设施版本化
- **配置管理**:Helm / Kustomize 管理 K8s 部署
- **特性开关**:LaunchDarkly / Apollo,业务开关与发布解耦

部署策略全面演进到 [[灰度发布与蓝绿部署]],配合 [[幂等性]] 设计降低风险。

## 结论

现代云原生架构的本质是**把分布式系统的复杂性下沉到基础设施层**,让业务代码专注业务。其核心理论(CAP / BASE / 一致性模型)、核心算法(Paxos / Raft / Quorum / 向量时钟)、核心工程实践(限流 / 熔断 / 降级 / 幂等 / 灰度)共同构成了一张完整的能力图谱。

掌握云原生不是学若干工具,而是建立**分层抽象**的思维:把通信治理交给服务网格、把扩缩容交给 K8s、把持久化交给托管数据库、把安全交给零信任 + mTLS、把可观测性交给 OpenTelemetry。剩下的精力才能投入业务建模与差异化创新。

未来五年的趋势已清晰:**Sidecarless / eBPF 替代传统 sidecar**、**AI 原生云做智能调度**、**Lakehouse 统一批流**、**WASM + 边缘计算重塑分发模型**。基础设施会越来越"看不见但永远在",这正是云原生的终极形态。
